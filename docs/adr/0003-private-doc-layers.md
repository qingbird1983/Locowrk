# ADR-0003：文档分「契约层」与「本机层」，本机层永不推送

- 状态：已接受
- 日期：2026-10-17
- 决策人：青鸟（定形状与排除范围）/ Qoder（执行与订正口径）
- 出处：用户 2026-10-17 两条指令——① `docs/design/` 根只放"接下来要开发或需要重构的设计方案稿"，
  做完或被重新设计就搬进 `archive/`；② `design`、`history`、`issue`、`references` 从远端排除。
  本轮两次追问的回答：`authority/` 留在仓库、已提交的历史**不重写**（"只管以后"）
- 取代：无
- 被取代：无

## 背景

仓库里的文档有两种用途混在一层里：一种是**别人接手必须读的契约**（施工规则、架构正身、进度、决策记录），
一种是**作者自己的过程与史料**（未落地的方案稿、旧批次流水、问题清单、外部参考笔记）。
治理前它们全部入库，于是"私人工作史"变成了公开仓库的主体内容——实测 `docs/` 里过半字节是历史流水。

三条约束决定了不能简单地"整个 design 排除"：

- `AGENTS.md` 与代码注释天天指向 `docs/design/authority/` 里那几份唯一说法，排除它们等于让下一个
  clone 的人（或他的 agent）读不到需求来源，只能猜。
- `.gitignore` 对**已跟踪**的文件无效。实测证据：`docs/issue/` 早在忽略名单里，仓库却仍跟踪着三份文件。
- 排除只对"以后的改动"生效；已经提交过的内容仍留在 git 历史里，任何"翻 log"的人都看得到。

## 决策

把文档层按"会不会让下一个人做错事"切成两类，并把切法变成机器可判的：

1. 入库（契约层）：`AGENTS.md` `STRUCTURE.md` `README.md` `CONTRIBUTING.md` `docs/roadmap/`
   `docs/adr/` `docs/design/authority/` `specs/` `docs/prototype/` `scripts/`。
2. 不入库（本机层）：`docs/design/` 根上的方案稿、`docs/design/archive/`、`docs/history/`（含 `audit/`）、
   `docs/issue/`、`docs/references/`——写进 `.gitignore`，并对已跟踪的文件执行 `git rm -r --cached`（本地文件保留）。
3. `docs/design/` 根的定位钉死为"还没落地的那件事"：稿上的设计**全部做完**或**换了做法重开**，就把整份稿子
   搬进 `archive/`，新方向另起一稿；搬时同步在 `docs/design/archive/README.md` 点名它，并在稿末补一行
   "何时、为什么搬进来"——这一层不再有 git 改名记录可追。
4. 在役文档里指向本机层的链接，同行必须写明「不入库」；这条判据（`check-docs.mjs` 的 R10）**不在脚本里写第二份名单**，
   运行时直接问 `git check-ignore`，`.gitignore` 是唯一出处。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 整个 `docs/design/` 都不推送（用户最初的表述） | `authority/` 是施工指南与代码注释的引用落点；排除后入口文档里每一处"去看规范"都变死路径，别人接手只能猜。用户后来明确"authority 留在仓库里" |
| 连带把这四层从 git 历史里抹掉 | 需要重写全部提交（哈希全变、不可逆）。用户裁定"只管以后，不动历史"；且本仓至今零远端、从未 push，没有对外泄漏面要止损 |
| 只加 `.gitignore` 规则，不做 `git rm -r --cached` | 已跟踪文件不受忽略规则影响，规则等于没生效。`docs/issue/` 就是现成反例：忽略名单里有它，仓库仍跟踪三份文件 |
| 把本机层的正文搬进 `docs/` 之外（例如用户目录） | 这些稿子要与代码同仓对照才有用；搬出仓库后 `STRUCTURE.md` 这张地图就覆盖不到，反而更容易漂 |
| 在 `check-docs.mjs` 里手写一份"不入库目录名单" | 两处名单必然漂移（本仓反复出事的就是这个）。改成运行时问 `git check-ignore`，名单唯一出处仍是 `.gitignore` |
| 让 `docs/design/` 根的稿子留在原地只加个"已完成"标记 | 那等于回到"用目录名/标记表示状态"的旧形状——治理 G6 刚因为这个问题废掉过 `NEW/` 这类目录 |

## 后果

**正面：**
远端仓库只长契约层，别人 clone 下来看到的就是"能照着干活的那部分"；本机层继续按作者的节奏长，
不必为公开性做措辞。R10 让"本机点得开、clone 后是死路"这类错从此可判（此前 R8 只判存在性，看不见它）。

**负面 / 需要接受的代价：**
① 本机层**仍留在已有提交记录里**——这套排除不是保密措施，只是不再让远端继续长出这些内容；
真要干净得重写历史，本批没做。② 归档件脱离 git 跟踪 ⇒ 移动不再留下改名记录，来历只能靠稿末那一行自述。
③ R10 对 `docs/adr/` 与 `DESIGN.md` 网开两面（前者只增不改、后者属禁区），它们里面指向本机层的老链接
仍是裸链接，读者需按本 ADR 理解。

**后续需要跟进的事项：**
- `docs/design/authority/DESIGN.md` 文档版本行里那处指向 `docs/history/` 的指针是裸链接；改它要动 `[LOCK]` 文件，**等用户点头**。
- 路线图上"记忆与上下文重构"那一阶段做设计时，新稿进 `docs/design/` 根，旧稿按本 ADR 第 3 条搬 `archive/`。
- `STRUCTURE.md` 里 `docs/prototype/` 仍在入库层；若将来也要排除，照 R10 的口径办，别在文档里另列名单。
