# ADR-0015：Phase 6 随包分发 Node 运行时目录

- 状态：定稿
- 日期：2026-10-28
- 关联：ADR-0009、ADR-0004；research/03；design/phase-2/runtime-spike.md；design/phase-6/runtime.md

## 背景

ADR-0009 选定 Node 兼容子进程作为 A 轨运行时，并把“随包目录还是 Node SEA”留到 Phase 6 开工前定稿。两条路都能运行扩展，差别在分发、升级与签名：

- **目录**：把钉死版本的 `node` 可执行文件与许可证放在应用目录下，适配器用它启动扩展入口。
- **SEA**：用 Node 的单可执行应用能力，把运行时和入口打成一个可执行文件。

Phase 2 的 spike 只验证了“系统 Node 能跑样本”，没有验证 SEA。

## 决策

Phase 6 采用**随包 Node 运行时目录**，不使用 SEA：

1. 发布产物带 `runtime/node/`（Windows `node.exe`，macOS/Linux 对应二进制），版本钉死并在 `runtime/README.md` 记录版本、来源与校验值；许可证文件同目录。
2. `adapter.Options.NodePath` 指定运行时；生产由 `cmd/locowrk` 从应用目录解析。开发期未找到目录时可回退到 PATH 的 `node` 并打印警告；发布构建缺运行时时 fail-closed，不启动 A 轨扩展。
3. 启动前检查 `node --version` 与钉死版本；不一致只禁用 A 轨并给出诊断，不尝试自动升级。
4. `plugin.json` 的 `entrypoint` 仍是打包后的 JS 入口；适配器命令变为 `<NodePath> <entrypoint>`（mock 插件可继续直接执行自身）。
5. 运行时升级独立提交，重跑 Phase 2 样本、Phase 6 扩展样本与进程树清理测试。

## 理由

- **简单可复现**：目录形态就是 Node 官方产物，不需要额外构建链；SEA 产物仍需平台工具链，且与原生模块/签名交互更多。
- **升级与回滚**：替换目录即可，和扩展包分开；SEA 要把运行时与应用入口重新打包。
- **体积相近**：SEA 不会显著减小 Node 运行时；主要成本都在发布包。
- **调试与审计**：目录内的版本、许可证与校验值可直接核对；SEA 需要额外记录构建参数。

## 后果

- 安装包增加约 50~100 MB；需要把 `node` 纳入签名与更新清单（发布工程 backlog）。
- 运行时不进 git；CI 从固定 URL 下载并用校验值验证，离线构建需预置缓存。
- 适配器测试需要两种启动方式：Node 入口（真实扩展）与直接可执行（mock 插件）。
- 若后续要求“单文件绿色版”或目录形态在三平台不可行，另写 ADR 重新评估 SEA。

## 护栏

- 不在运行期下载 Node、不执行 `npm install`、不远程加载扩展代码。
- 发布构建不允许静默回退系统 Node；开发回退必须显式警告。
- 运行时与扩展的许可证、版本、校验值随发布物保留。
