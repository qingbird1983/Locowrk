# ADR-0001：文档与变更记账规则改用仓库模板那一套

- 状态：已接受
- 日期：2026-10-17
- 决策人：青鸟（定方向） / Qoder（执行与取证）
- 出处：用户 2026-10-17 指令「废除之前仓库的文档约束与规则，按照 `F:\Users\Warehouse template` 的方向制定新规则；
  历史归类加索引即可；接下来的工作按新规则重排；之前的没有必要再改成新规则」；
  当时的成本底数与方案草案见 [`docs/history/doc-governance-plan-v1.md`](../history/doc-governance-plan-v1.md)
- 取代：无（本篇是这一族规则的第一篇；被它废掉的旧规矩没有单独成文，散在 AGENTS 与各规范里）
- 被取代：无

## 背景

事实（全部实测，不是印象）：

- 写完一版变更要动 **10 个文件**，同一个版本号在 6 份文档里出现 **11 次**；其中三份文件只为"把上一批搬走"而存在。
- 变更日志一版一整行，最长 **11,467 字节**；批次叙述里最长一行 **48,838 字节**。这种行读不动、
  diff 比不出，只能靠脚本改 —— 本仓库为改这些行写过一整套带 24 项自证的轮转脚本。
- agent 入口文件 188 行里有 **5,998 字节是进度叙述**，为把它压进 6,000 预算，历批反复删字；
  它是每个会话的注入源，进度一漂就误导之后所有会话。
- 「判据自纠」这类累计计数器散在 **8 份文件共 173 处**，每批要逐处加一 —— 这是必然漂移的读数。
- 已发生两次**自我声明落空**：一处写着"登记见台账 T11"，而 T11 记的是另一件事（那条欠账从未在册）；
  一处指针写着"本次搬出 v2.198"，而真正搬走的是 v2.199。
- 一次性验证脚本堆在 `tmp/` 共 **476 份，一份都没入库**（这条欠账挂了二十批）：看着有保障，
  实际下一批改结构就查不出来。
- 约束：用户一个人 + 一个 agent，没有代码评审者；界面效果由他亲自看；记忆与上下文整片即将被重新设计。

## 决策

- 根目录立四件入口文档：`AGENTS.md`（agent 规则唯一事实源，**≤100 行**，只写可判定规则与指针）、
  `STRUCTURE.md`（全仓唯一地图，只用两个标记：`★` 唯一事实源 / `[LOCK]` 禁区）、
  `README.md`（给人看的入口）、`CONTRIBUTING.md`（提交与记账约定）。
- 位置固定、格式不固定：现役设计放 `docs/design/`；**进度只写在 `docs/roadmap/`**，
  一行一个未完成阶段 + 勾选 + 一句人话状态，已完成的从这张表删掉。
- 每阶段的详细计划与**可测验收**放 `specs/<编号>-<名>/spec.md`；目录按需生长，不为将来预留空壳。
- 长期取舍与"否掉了什么"放 `docs/adr/NNNN-*.md`，**只增不改**；决策变了新写一篇并互相指向。
- 细节（改了哪些文件、实测读数、踩坑、遗留风险）只写在**提交正文**。
- 历史一律搬到 `docs/history/` 并建一份索引，**不再追加、不改写内容**；历史件内部的旧链接按原样留着。
- 命令统一走一条入口：`make check`（全量）/ `make quick`（秒级），实现只写在 `scripts/tasks.sh` 一处；
  没配的目标必须明确报错，不许静默通过。
- 废除以下旧规矩，**不许偷偷回来**（由 `scripts/check-docs.mjs` 拦）：agent 入口装进度、进度三条轮转、
  三条合计 6,000 字节预算、批次叙述各留最近 8 批、把最老一批搬进归档的脚本、每版一整行的变更日志、
  往设计稿正文追加落地注记、把累计计数器写进正文。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 把历史文档也改写成新形态（长行折短、逐批流水转成决策记录、文件名统一） | 用户明确"之前的没有必要再改成新规则"；且历史的价值就在于记录**当时怎么说**，改写等于伪造证据；成本还会吃掉整场治理 |
| 照模板机械建齐所有文件（`.editorconfig` / `.env.example` / `CLAUDE.md` / `GEMINI.md` 等） | 模板自己就要求"按需生长、不预留空目录空表格"；本项目没有多 agent 入口与 env 契约，建了就是没人读的壳 |
| 保留变更日志与 8 批窗口，只是把收尾档位调轻 | 实测成本本体就是这套多出处登记（一版 10 文件 14 处）；调轻档位不减落点，过一阵还会漂 |
| 让 `AGENTS.md` 继续装"当前进度"，只压缩措辞 | 它是每个会话的注入源；历批为压预算反复删字，删的正是最该保留的边界说明，进度本身却仍然漂 |
| 把 `tmp/` 那 476 份验证脚本全部收编成常驻回归 | 几十批的形状假设要逐份验证到今天是否仍成立，会把一批恒真判据永久固化；只把长期挡得住错的少数几条升进 `scripts/`，其余明确作废 |
| 把八道结构闸合并成 4 道大闸 | 未拍板，且报错定位要重映射；本次只处理**已经失效或一名两义**的那两条（文档窗口闸删除、形态闸拆成报告档与拦截档），其余原样保留 —— 它们抓到过真问题 |
| 进度不进文档，完全靠 git log | 他要的是"接下来做哪些、现在走到哪"；git log 是给机器追溯用的，不能当人的看板 |
| 路线图保留全部已完成阶段（历史一目了然） | 一份 925 行的表里 90% 是已完成，真正要看的未完成项被埋掉；历史归 `docs/history/`，读那里 |

## 后果

**正面：** 一版变更的落点从 10 个文件降到"进度表那一行 + 一次提交"；agent 注入源从 26.9 KB 降到约 7.9 KB；
读得到、比得出、不必再用脚本改文档；每件事只有一个真源，"两处手写必漂"这一族从根上少掉。

**负面 / 需要接受的代价：** 在役文档与代码注释里的旧链接要逐个重放（本刀已改 4 处，含 `docs/design/authority/DESIGN.md`
里那句进度表路径 —— 只换路径不动语义）；历史件正文里的旧链接**故意不改**，靠 `docs/history/README.md`
的映射表兜底；细节搬进提交正文后，"翻文档看历史"变成"翻 git 看历史"，需要一点习惯；
`make` 成为默认入口，但本机仍需 `pnpm`/`cargo` 在位。

**后续需要跟进的事项：**

- [ ] 把 `docs/design/` 里已兑现的设计稿归入 `docs/history/`，并修在役面的链接
- [ ] 审计报告与修复台账：先把 §7 里没结的欠账抄进路线图与阶段计划，再整体归档
- [ ] 旧的记忆 × KV 专项进度表并入唯一路线图（它自称第二张进度表，与新规则冲突）
- [ ] 其余检查脚本逐条给"留 / 改 / 合 / 删"，并解释每条为什么卡、卡了会怎样
- [ ] 旧规矩用词若在某天变成正当需求（例如真需要发版日志），必须先新写一篇 ADR 取代本篇相关条目
