# ADR-0002：门禁与闸门按模板重写修订

- 状态：已接受
- 日期：2026-10-17
- 决策人：用户（原话见「参考」）／执行：agent
- 出处：文档治理阶段 G5 刀；实测底数写在本文「背景」与提交正文
- 取代：无

## 背景

开工前的状态：八道结构闸 + 长度闸 + 两道前端形态闸 + 三个 CI 作业 + 一份 pre-commit，
外加 `tmp/` 里 **283 份**一次性判据脚本（从未入库，台账 T8 挂着这条欠账挂了 20 批）。

用户的话是「闸门本身都是你们自己加的越加越多 补卡才怪了」和「没到位的活过度的 重写修订下就行了」。
所以这一刀的判断标准只有一条：**这条闸挡的是不是"没人盯着就会做错"的事**。

取证找到的事实（全部实跑，不是推断）：

1. **CI 从没跑过一次。** `git remote -v` 为空，298 个提交一个没 push。
2. **CI 里手抄的闸清单已经漏了两道。** hygiene 作业逐条写了 6 个 `run:`，现役 8 道里的
   「预留对账」与「文档规则」不在其中 —— 而它自己头注还写着"这份列举此前就漏过两道"，
   承认了问题却没补上步骤。
3. **CI 里有一条天天必红的步骤。** 「拆分登记表重放」实跑 **9 份里 8 份红**，
   红在"新增代码无登记"——那是拆分之后代码继续正常演化的结果。它把**一次性历史证明**
   做成了**常驻判据**，注定越用越红。
4. **`check-style.mjs` 一名两义。** 不带 `--staged` 时恒 `rc=0`（只报告），带 `--staged` 才拦。
   同一个名字两种行为，被 `tasks.sh` 用 `|| true` 接进门禁 = 那条门禁是空转。
   实测全量存量 **0 处判错**，所以"只报告"这个保护已经没有对象。
5. **长度闸的基线是一颗每批都会变的数字**（`BASELINE=22`，注释里记着 40→22 共 16 次手工收紧，
   76 行历史占了脚本一半篇幅）。会漂的数字钉进判据 = 下一批它自己红，而且红得和代码没关系。
6. **第五道闸（拆分形状，657 行）有一半在重复编译器的活。** 用最小 Rust 夹具实跑：
   `mod x;` 而无文件 → **E0583**；兄弟簇引用私有项 → **E0433**；子簇缺 `use super::` → **E0425**；
   摘掉父模块的 glob 传导 → **E0425**；簇名撞子模块 → **E0255**。
   这四档 `cargo clippy --all-targets`（本来就在 `make check` 与 CI 里必跑）权威地管着。
   而**孤儿源文件**（`x.rs` 在、没 `mod x;`）实跑 `rc=0` —— rustc 一声不响，
   那个文件里的测试直接从运行面上消失。这一档只有文本闸看得见。
7. **跨文件对账类判据每批新建一道 = 闸只增不减。** 历批的 `tmp/q*-shape.mjs` 一共十几份，
   内容多是"同一件事在几个地方各写了一遍"这一类，本质是同一种判据。

## 决策

1. **闸的清单只有一个出处 = `scripts/tasks.sh` 的 `t_gates`。** CI 的 hygiene 作业改成一行
   `sh scripts/tasks.sh gates`；Makefile 改成兜底转发（`%: ; @sh scripts/tasks.sh $@`），
   不再逐条写 14 行。pre-commit 保留"哪一面触发哪一条"（这是 git 语义，且路径写错会响亮失败），
   但**删掉它对每条闸挡什么错的复述**——那份复述实测已经漂了三处。
2. **`check-style.mjs` 两个档同语义**：有没有一级判错决定退出码，`--staged` 只决定扫哪些文件。
   加下限：全量档扫到 0 个 `.vue` 判红（闸瞎了不是干净）。`tasks.sh` 里那句 `|| true` 删掉。
3. **长度闸从计数基线改成点名名单**：超限文件逐个列在脚本里，数由两边集合现算；
   新增超限判红，拆净一个就删一行。16 次收紧史整体搬进 `docs/history/check-length-baseline.md`（只读）。
   扫描面改成**单一出处**，并逐根设下限——第一版我把下限写成"总数 ≥ 200"，
   变异对照（只扫 `crates`）实测读数 206 通过，闸瞎了还反过来劝我把名单删空；
   逐根下限才抓得住"某个根没扫"。
4. **第五道闸只留编译器挡不到的三档**：S0 词法尺子自证、S1 孤儿源文件、S2 测试夹具与用例混住；
   S4 撞名降为报告。**删档的理由是实跑错误号**，写进脚本头注，而不是"看着重复"。
5. **拆分登记表重放撤出常驻门禁与 CI**，改成 `make ledger LEDGER=<名>` 手动跑，
   跑之前先打印一句"这份表证明的是当年那一刀"。九份登记表继续留在仓库里当证据档案。
6. **新增第九道闸 `scripts/check-single-source.mjs` = "同一事实只许一个出处"这类对账的唯一收口处。**
   今天两项：记忆目录名里那段 `"projects"` 生产面只许 1 处；界面字号基座三面同数。
   它自带 `--selftest`（内存变异，不碰磁盘）。**今后要加这类对账是往它的 CHECKS 表里加一项，
   不是再立一道闸** —— 这条就是"越加越多"的止损阀。
7. **`make selftest` 成一档**，进 `make quick` 与 `make check`。规矩：改过闸本身就要跑它。
8. **门禁按改动面分三档写进 CONTRIBUTING**（提交档 / 秒级档 / 全量档），
   不再是"每批跑 22 项全量"这种一刀切。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 八道闸合并成一道大脚本 | 合并只减少**文件数**，不减少**判据数**；红的时候反而要说清是哪一类。真正要减的是"每批新建一道"的习惯，那由决策 6 的止损阀解决 |
| 把 `tmp/` 283 份判据全部收编进 `scripts/` | 其中绝大多数是"那一刀的验收"，不是活代码的不变量。全收编 = 闸数从 9 变成 200+，正是用户批评的那件事 |
| 给每条闸都配 must-fail 自测并常驻 | 8×N 的自测矩阵本身就是"越加越多还要越多自测"。改成：**新闸入库时**必须带一条实跑红证（写进提交正文），存量闸只在被改动时跑 `make selftest`；本批给新闸与两个改动过的闸现场补了对照 |
| 第五道闸整条删掉（"编译器都会管"） | 实测孤儿源文件 `rc=0`：rustc 不管，文件里的测试会静默消失。删整条 = 把这个真实盲区还给"人工纪律" |
| 保留 ledger 重放在 CI，只把红的两份标豁免 | 豁免是**把判据改成恒真**。它红不是代码坏了，是这个模式不该常驻（历史原文 vs 当前产物必然漂）；留在 CI 只会训练人去绕过红 |
| pre-commit 直接跑 `make check` | 全量档含三处 cargo 测试与前端构建，提交闸会从秒级变成分钟级；人们会开始用 `--no-verify`，那时闸真的就没了 |
| CI 那份手抄清单补上漏的两道闸就行 | 治标。下一次加闸还会漏。根因是"清单存在两处"，所以把 CI 改成调用唯一清单 |

## 后果

**正面：**

- 加一道闸现在只需要改 `tasks.sh` 一处，CI 与 `make` 自动跟上；pre-commit 仍要加一行触发条件（刻意保留，理由见决策 1）。
- 闸的**总数**有止损阀：对账类判据不再各立门户。
- 长度闸不再需要"每批改一个数字"；超限文件从"计数"变成"带理由的名单"。
- 第五道闸 657 行 → 502 行，删掉的每一档都留有实跑错误号可查；留下来的三档各有一条实跑红的对照。

**负面 / 需要接受的代价：**

- 秒级反馈的覆盖面变小：孤儿文件、夹具混住这类仍由闸管，而可见性/引用句类错误要等到跑 cargo 才知道（快几十秒，但不再是"编译之前"）。
- ledger 重放撤出 CI 后，**没人会再自动重放它**。接受这个代价的前提是：它本来证明的就是一次性事实。
- CI 依然一次没跑过（本仓库没有远端）。这一刀让 CI 与本地同源了，但"CI 是防线"这句话仍然要等到真的 push 才成立。

**后续需要跟进的事项：**

- `tmp/` 283 份脚本的逐条处置（作废或删除）——已作为台账 T8 的一部分登记在
  [`specs/03-structural-debt`](../../specs/03-structural-debt/spec.md)，其中"该常驻的"已按决策 6 落了一条。
- 旧文档并档还剩一张：`docs/design/Memory-KV Roadmap.md` 自称第二张进度表，未完成项要并进路线图。
- `docs/reports/` 已在本刀抄完欠账并搬入 `docs/history/audit/`，此项从路线图结掉。
