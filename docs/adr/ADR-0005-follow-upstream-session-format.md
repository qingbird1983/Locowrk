# ADR-0005：沿用上游 JSONL 会话格式，不自立格式

- 状态：定稿
- 日期：2026-10-28
- 关联：architecture/05；research/01

## 背景

会话是产品的核心资产：要能恢复、分叉、压缩、导入导出，还要与 pi/`sky-valley/pi` 互操作。自研格式会让恢复语义、压缩、工具结果展示逐步分叉，且要自己维护迁移。

## 决策

- 会话磁盘格式完全沿用 `sky-valley/pi` 的追加式 JSONL（与 pi 兼容）。
- 读写只通过 `coding` 包的 `StartSession`、`ResumeSession`、`LoadSessionTree`、`LoadBranch`、`LatestSession` 等 API。
- 桌面端与插件不得直接写会话文件；导出走投影数据，不直接拷贝内部 entry。
- 若未来需要扩展字段，先确认上游是否已有；没有则写 ADR，并保证旧读者可忽略未知类型。

## 理由

- 恢复、压缩、`context_edit`、分支的语义已在上游实现并被大量测试覆盖。
- 与 pi CLI 共用目录与格式：用户可以在终端与桌面之间接力。
- 上游负责迁移（v1→v3）；我们不必维护第二套兼容矩阵。
- 降低“桌面端显示的内容”和“模型实际上下文”不一致的风险。

## 备选（否决）

- **自研格式（如 SQLite）**：查询方便，但会立即失去互操作与上游恢复语义；SQLite 可作为索引缓存，不能作为事实来源。
- **直接复制 JSONL 做导出**：把内部 entry 暴露成公开格式，未来无法演进。
- **只存消息数组**：丢失工具结果、压缩、模型切换等恢复所需信息。

## 后果

- 与上游版本强耦合：升级要验证会话迁移与投影。
- 会话文件可能包含敏感内容（工具输出、路径）；权限、备份、删除策略必须明确（standards/06）。
- 大工具输出由上游截断并落临时文件；桌面端不要重复存一份全文。
- 索引/搜索可以另建缓存，但缓存可随时重建，且不得成为唯一副本。
