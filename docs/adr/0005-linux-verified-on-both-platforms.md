# ADR-0005：Linux 这块账正面修，同一条断言两个平台都要跑

- 状态：已接受
- 日期：2026-10-17
- 决策人：青鸟（原话"这样不行，感觉还是开版 把 Linux 这块帐彻底修复吧。包括前面禁止绕开的"）
- 出处：真 CI run 39035337606（kernel 作业 SIGSEGV）· 本机 WSL Ubuntu-24.04 复现（gdb 栈与逐条读数进提交正文）·
  台账 [`specs/03`](../../specs/03-structural-debt/spec.md) 的 T18
- 取代：Supersedes [`ADR-0004`](0004-ci-paths-windows-only.md)
- 被取代：无

## 背景

ADR-0004 把四条 Linux 上红的内核用例标成 `#[cfg(windows)]`，口径是"路径语义只在 Windows 上验证"。
本轮按用户要求复核这四条 + 内核作业上那条崩溃，实测结论与当时的判断**不一致**：

1. 崩溃不是断言不成立，是测试进程被段错误打死（`signal: 11, SIGSEGV`）。栈显示插件句柄的 `Box<dyn
   PluginState>` 被释放时 vtable 槽已是 `0x0` —— 同一份内存释放了两次。
2. 崩溃前真正红的那句断言（"回退后 update 该报无新版"）在 **Windows 上是靠平台副作用过关的**：
   本机实测报错原文是 `另一个程序正在使用此文件，进程无法访问。(os error 32)`，即覆盖正在装载的 dll 被
   系统拒绝，`is_err()` 恰好成立。Linux 没这把锁 ⇒ update 成功。回退到旧版后市场里明明摆着更新版本，
   按 §1「可回退」的语义这时就该升得回去 —— **这条是出题出了错**。
3. 四条路径断言里，`fsutil` 那条的 POSIX 报错（`cannot resolve any existing ancestor`）也不是"语义不同"：
   `<根>/sub/no_such/../../..` 这种串最后一个组件是 `..`，`Path::file_name()` 返回 None，于是本该判成
   "越界"的路径提前撞墙。Windows 上看不见这一层，因为它的 canonicalize 会把缺失段的 `..` 也折掉。

约束：改动的落点 `plugin-api` 是冻结 ABI 的**边上**（改实现可以，改既有对外签名不行）；这台开发机是 Windows，
Linux 侧只能靠本机 WSL 或云端 CI 取证。

## 决策

撤掉 ADR-0004 那四个 `#[cfg(windows)]` 标记，把账在实现侧修平，让**同一份断言在 Windows 与 Linux 上都跑通**：

- `..` / `.` 的词法折叠做成**一个出处**（`plugin_api::wskey::lexical_fold`，`win` 是显式参数而不是平台分支），
  记忆键位与文件围栏都调它；围栏在校验前先折叠，拒绝理由由此回到"越界"这条裁决上。
- 目录名安全化把 `\` 与 `/` 同等当边界（与同模块 `key_file_stem` 的既有口径对齐），并补一道：产物名里
  残留的连续点一律压掉，`..` 不许进目录名。
- `PluginRegistry::load` 的幂等闸门**同时看 graveyard**：逻辑卸载只是把 Arc 挪进保留区，映像仍在内存里，
  只查在册表会让同一份产物被第二次 dlopen。判据是 `Arc::ptr_eq`（有可观测差异，改前红）。
- `NativeBackend::_lib` 改成 `ManuallyDrop<Library>`：把"永不 dlclose"（DESIGN 附录 C 纪律一）从注释
  落成类型事实；真会卸载的只剩 `loader.rs` 的"加载即失败"豁免。
- 那句 update 断言按正确语义重写：回退后 update 该升回最新版，"无新版"改由"当前已是市场最新"来验。
- 入口口径改回：AGENTS.md §1 的"不在范围内"删掉 Linux；本仓承诺两个平台都有证据。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| 维持 ADR-0004 的 `#[cfg(windows)]` 跳过 | 用户 2026-10-17 明令禁止绕开；且复核后这四条里有两条根本不是"平台语义不适用"，标记等于把实现缺陷登记成平台差异 |
| 给那条 SIGSEGV 也加平台标记，或删掉整条用例 | 全仓**唯一**暴露生命周期缺陷的证据就是它。为了绿把它藏起来，等于把"Windows 上永远看不见"写进制度 |
| CI 换成 Windows 机器跑 | 只是让云端重复本机天天在跑的那一批，不新增任何证据；私有仓 Windows 按 2 倍计免费分钟数，且要动禁区 |
| 不装 WSL，改完直接推云端验证 | 云端一轮四分钟起，而且拿不到栈——SIGSEGV 的定位靠的是本机 gdb + 同一份用例重复跑；等 CI 会把"不许靠猜改代码"逼成猜 |
| 用 `#[cfg(unix)]` / `#[cfg(windows)]` 各写各的断言 | 两侧各按各的想象出题，就没人担保它们说的是同一件事。本次要的是同一条断言在两台机器上都成立 |
| 只修崩溃、把那句 update 断言留着不动 | 崩溃修好之后断言仍会红；而把它留成"只有 Windows 的锁能过"的形态，下次换个占用顺序还会以另一种方式崩 |

## 后果

**正面：**
Linux 侧从此有真证据（本机 WSL 全量 + 云端 ubuntu 双通道），且这台 Windows 机器上的读数一字未改地继续承重。
暴露出两个与平台无关的真缺陷：同一份插件产物可被第二次 dlopen（幂等闸门漏看保留区），以及
"永不 dlclose"只活在注释里。围栏与键位现在共用同一套折叠算式，少一个会漂的副本。

**负面 / 需要接受的代价：**
插件模块常驻到进程退出（这是纪律一本身的要求，但它现在被强制执行了）：长期会话里反复装/卸载插件
不会归还那部分内存。词法折叠不解析符号链接——`x` 若真是符号链接，`<根>/x/../b` 与 `<根>/b` 仍可能
落成两个键位，这一面**仍然没有证据**，见下方跟进项。改目录名算式会让历史上含 `..` 或反斜杠的
workspace 换一个新的项目目录名（本机记忆数据是测试残留，用户 2026-10 已裁定无所谓；真发布前要重估）。

**后续需要跟进的事项：**
- [`ADR-0004`](0004-ci-paths-windows-only.md) 的「被取代」字段填本篇编号（模板明许可改这一栏）。
- 符号链接那一面要单独出题：Linux 上"折叠 vs 真实解析"的差集需要一批新用例，别把它混进本轮的收口口径。
- 台账 T19（`check-docs.mjs` 的扫描面不含 `specs/`，判据自称口径与实现不符）与本条无关，另开一刀。
- WSL 复现环境的装法与镜像速度读数只进提交正文，不在本篇重复。
