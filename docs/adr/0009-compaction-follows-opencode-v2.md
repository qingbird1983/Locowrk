# ADR-0009：上下文压缩按 OpenCode V2 整块重写，只保留「阈值可调」一处自己的东西

- 状态：已接受
- 日期：2026-10-21
- 决策人：青鸟（原话「完全抛弃现在的上下文压缩机制，参考 opencode 完全复刻对齐，包括怎么压缩、触发机制、压缩提示词、压缩格式」「可以完全删除干净现在的上下文管理机制然后重写」「唯独我们要单独增加的，就是自动触发压缩机制的阈值是可以用户调整（按 token 或按百分比都可以）」「按照 opencode 的完全用主模型，都可以考虑的」）
- 出处：[`specs/13-opencode-compaction`](../../specs/13-opencode-compaction/spec.md) ·
  上一轮裁定见 [ADR-0008](0008-aux-call-budget-vs-main-retry.md)（辅助调用预算）
- 取代：无
- 被取代：无

## 背景

改这一刀之前，本仓的上下文压缩由五块自研拼成：一条**独立的辅助通路**（`llm/aux_client.rs`
直呼客户端）、四份**自研**摘要提示词、一枚**绝对 token** 阈值滑杆、一条**自研**折叠消息格式
（`[earlier conversation summarized]`）、一套**自研**失败分类。

拼起来的代价不在"功能少"，在五处各自都成立、凑起来就不成立：

1. **主轮能用 ≠ 摘要能用**。辅助通路绕过 `AppLlm::prepare`、不带会话 hooks、不带真实
   system、不吃会话级模型覆盖、输出上限口径另算 ⇒ 同一时刻两套配置解析。用户看到的症状是
   「主对话好好地在跑，压缩却报『摘要模型没登上（网络或额度）』」。
2. **提示词不是上游那套**。自研四份稿子 ⇒ 摘要形态、校验口径、失败分类全与上游不同，
   于是每一处都要自己判断"对不对"，而判断的依据是记忆而不是原文。
3. **阈值不跟窗口走**。绝对 token 滑杆（100K–800K）对窗口 976K 的模型是"早得离谱"，
   对窗口 128K 的模型是"几乎贴边" ⇒ 同一个数在两种模型上含义完全不同。
4. **折叠产物自研**。落进日志的摘要头一行与压缩层量出来的那一条从此可以不同字 ⇒
   "撤销后窗口对不上"、"界面上说省了 3 万，重放时只省 2.8 万"。
5. **失败分类自研**。后端只回判据名、人话住语言包，两侧要对齐；而自研的那一套没有原文可对，
   于是"新增一条判据忘了补文案"这类漂移没有任何机械面能发现。

上游（`opencode` 的 `packages/core/src/session/compaction.ts`）这几件事是一体的：同一套请求
装配（走主对话那条管线）、同一份逐字提示词、同一套收缩矩阵、同一种 checkpoint 折叠、同一张
失败分类表。**对齐上游的收益不只是"像"**，而是这五处各自的"对不对"从此有了一个**可逐行复刻
的原文**。

## 决策

**整块换掉，按上游逐行复刻；只保留一处我们自己的东西。**

1. **压缩请求走主对话那条装配链**。内核新增 `Kernel::prepare_request(session, session_id)`：
   跑 `derive_messages → waterfall_pre → tool_catalog → waterfall_request` 那条**与主对话轮
   完全相同**的链，装配完**不发送**；摘要提示词作为**最后一条 user 消息**追加（hooks 看到
   的是加提示词之前的请求，同上游）。`llm/aux_client.rs` 整条删除——第二份拼装不许存在。
2. **提示词逐字照抄上游**（`SUMMARY_TEMPLATE` / `SUMMARY_RULES` / 共享五段 / 更新分支 /
   `NUDGE`），住资产文件 `prompts/compact/`，改文案不动代码。输出格式标题也是英文（上游口径）。
3. **三种触发**照上游：`auto`（每步边界，到线才压）/ `manual`（`/压缩`，**自动压缩关着也照样
   能压**）/ `overflow`（供应商按"太长"拒收后压一次、重试一次）。
4. **收缩矩阵**照上游：原样 → 去保留区 → 压成文本丢最老（`[N older exchange(s) omitted]`
   逐字）→ 70% / 50% / 35% 递减带；用尽即失败。
5. **折叠产物逐字照上游**：一条 checkpoint user 消息（`<conversation-checkpoint>` + 那句说明
   + `<summary>` + （保留区非空时）`<recent-context>`）；保留区**只存指针**、文本**读时重建**；
   工具输出截断 **1250 字符**。
6. **失败判据名统一成上游那 9 条**，手动与自动共用同一张表；熔断**不占判据名**（走相位
   `paused`）。
7. **唯一保留项**：自动触发阈值改成**占模型窗口的百分比**，三档 25% / 50% / 85%，缺省 **50%**；
   门槛算式 = `min(窗口 × 百分比, 窗口 − 输出预留)`；窗口未知 ⇒ **不自动触发**（靠 overflow
   兜底）。旧的绝对 token 滑杆**退役**（老配置里那枚键保留在文件里不报错，但不再被读）。
8. **保留两枚偏离上游的保险**（用户已拍板）：总时长预算（90s 三档，ADR-0008）与连败 3 次
   熔断。理由见下节。

## 被否决的方案

| 方案 | 否决原因 |
| --- | --- |
| **只换提示词，不动装配** | 病根不在提示词。辅助通路绕过的那些东西（真实 system、会话级模型覆盖、同一套输出上限）照样不在 ⇒ "主轮能用 ≠ 摘要能用"照旧，而用户看到的症状一模一样。 |
| **保留 `llm/aux_client.rs`，只让它吃会话模型** | 那一处是最表面的症状。aux 通路**整体**是第二份拼装；让它吃会话模型只补了其中一格，而真实 system / hooks / 工具目录仍然缺席。 |
| **保留绝对 token 滑杆，再加一枚百分比** | 两个阈值 = 两个出处。而且绝对数与百分比在同一台机器上同时生效时，"到底按哪个触发"没有答案；用户也无法判断"这次为什么压了"。 |
| **删掉总时长预算**（纯照上游） | 本仓主对话轮是「重试不设上限」；压缩请求一旦改走**主模型管线**就会继承这条。不加预算 = 把 ADR-0008 治过的"卡在思考中、且停不下来"原样请回来——而用户点名的抱怨正是"慢得吓人、好长时间后显示没压缩"。 |
| **删掉熔断**（纯照上游） | 上游失败就失败、靠会话重试策略兜；本仓这枚已经在界面上有一相（`specs/12` 刀②）。去掉它 = "老是失败"重新变成黑盒，而这正是用户抱怨过的第二件事。 |
| **阈值做成自由填数的输入框** | 用户没有依据判断"填多少算合适"，而填错了的表现是"提前压缩"或"撞窗才压"，两者都要靠他自己观察才能发现。按 AGENTS 的可配置原则②，数值型不确定项走**三档预置**，开发类与危险类才进开发者分区。 |
| **压缩摘要单独换一个便宜模型** | 上游没有这层语义（压缩用会话的模型）。而本仓没有"摘要模型档位"这套设置；真要加回 aux 通路，问题就回到第一条。 |

## 后果

**正面：**

- 压缩与主对话**同一份请求装配** ⇒ "主轮能用"蕴含"摘要能用"，第一号症状从根上消失。
- 提示词 / 输出校验 / 收缩矩阵 / checkpoint / 失败分类**全部有逐行可复刻的原文** ⇒ 今后判断
  "对不对"靠对照上游，不靠记忆。
- 阈值跟窗口走 ⇒ 换模型不用重算阈值；同一个百分比在不同窗口的模型上含义一致。
- 失败判据名两侧对账由**机械闸**盯（`SS24` 扫后端 `REASONS` 那张表与前端文案表）⇒
  "新增一条忘了补文案"不再靠自觉。

**负面 / 需要接受的代价：**

- 压缩请求吃**真实工具定义**（上游同款，靠提示词禁调用）⇒ 压缩那一趟的请求体比自研那版大。
- 判据名整表换掉 ⇒ 老会话日志里的旧判据名不再有对应文案（界面只对**新发生**的失败用新表；
  旧记录不在转录里重放判据）。
- 绝对 token 滑杆退役 ⇒ 老配置里那枚键**保留在文件里但不再被读**（不删用户数据），设置面
  不再显示它；用户看到的触发点会**变**（从"100K 就压"变成"窗口的一半就压"）。
- 判据迁移触动的同源闸档位（`SS19a` / `SS19b2` / `SS20a` / `SS20b` / `SS21b` / `SS24` / `SS25`）
  必须**改判据或退役**，不许留一档读着旧形状的判据——闸本身是这一刀交付的一部分。

**后续需要跟进的事项：**

- 供应商原生压缩（native compact）**不实现**：需要供应商侧的 compact 端点/触发器，本仓没有
  对等能力（上游依赖见 `packages/ai/src/route/client.ts`）。上游同款不做。
- `docs/adr/` 本篇只增不改；将来若要改回绝对档或加"模式切换"，**新写一篇**并在本篇
  「被取代」字段指向它。
- 老会话里已落盘的旧格式摘要**不迁移**（它就是一段文本，仍能被下一次压缩吃进去）。
