# ADR-0001：内核直接复用 `sky-valley/pi`，不自研、不嵌 Node

- 状态：已取代（2026-10-28，见 [ADR-0012](ADR-0012-fork-kernel-into-repo.md)；内核已 fork 进仓库 `pi/`）
- 日期：2026-10-28
- 关联：architecture/01、02；research/01

## 背景

目标是把 pi 的 Agent 能力带到桌面端。可选路线有三条：自己用 Go 重写内核；把 pi 的 npm 包嵌入 Node 进程复用；复用现成的纯 Go 移植版 `sky-valley/pi`。项目立项方案已判断“内核直接复用，不自研”，本 ADR 把它固化为决策并写明代价。

## 决策

以 `github.com/sky-valley/pi` 作为库依赖提供内核能力（`ai`、`agent`、`coding`），**不重写 Agent 循环、模型协议、工具与会话**；升级以固定提交为单位，独立提交、全量测试后合入。

## 理由

- 上游移植已覆盖：多 Provider 流式协议、Agent 循环、8 个内置工具、JSONL 会话、压缩、系统提示词、技能发现，且测试量约为实现代码的 1.2 倍。
- 纯 Go、无 cgo，与桌面端单二进制目标一致；不需要 Node 运行时。
- 行为以 pi 为蓝本，会话格式兼容，未来可与 pi CLI 互相恢复。
- 把有限精力留给真正的差异点：桌面宿主、插件适配与界面。

## 备选（否决）

- **自研内核**：成本最高（数月），且要重新踩协议与工具语义的坑；与“桌面端”这一项目定位不匹配。
- **嵌入 Node 复用 pi**：引入双运行时，持久化、崩溃、审批边界复杂；分发必须捆绑 Node。
- **fork `sky-valley/pi` 后大改**：失去上游同步能力；本项目只需要在其上做薄封装。

## 后果

- 正面：起步快、语义可信、会话互操作。
- 负面/约束：
  - 上游**没有 pi 的 extensions runtime**，A 轨兼容要由本项目适配层补（见 ADR-0003）。
  - 上游**没有 prompt templates**，不能对外宣称支持。
  - 上游仓库没有 CI；本仓库的 `go test -race ./...` 是唯一防线。
  - 上游 API 可能破坏性变更（其自身的 mirror 策略允许 break）；升级必须走演练流程。
  - 上游是“镜像 pi 的 SDK 半边”，不包含 TUI/host 层，正好符合本项目定位。

## 版本策略

- 当前钉 `6f6131ba`（2026-10-25，`env/v1.4.28-14-g6f6131b`）。
- 升级：独立分支 → 全量测试 → 核对事件常量、`SessionOptions`、流事件、会话迁移 → 更新 research/01 与 CHANGELOG。
- 需要局部补丁时，优先向上游提交；确需临时补丁，用 `replace` 仅限本地开发，禁止入库，并以 ADR 记录。
