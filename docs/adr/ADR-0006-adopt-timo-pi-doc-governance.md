# ADR-0006：采用 Timo-pi 式文档与规范治理

- 状态：定稿
- 日期：2026-10-28
- 关联：docs/README.md；standards/01 ~ 09；research/04

## 背景

项目由 AI 会话接力开发，所有者不读代码。没有强约束时，文档会退化成流水账、决策只存在对话里、上下文随会话丢失、体量无限膨胀。参考仓库 Timo-pi 已经用一套文档治理跑通多个阶段，可直接借鉴其结构，而不是重新发明。

## 决策

采用以下治理骨架（细节见各规范）：

1. `docs/` 是唯一事实来源；每篇有状态（草稿/评审中/定稿）与关联；新增文档必须登记 `docs/README.md`。
2. 重大决策写 ADR：编号递增、只增不改、推翻旧决策写新篇。
3. 九篇规范：仓库结构、Git、文档、代码、测试、安全、AI 协作、体量控制、规范复查。
4. `CHANGELOG.md` 是唯一追加式流水，面向非技术读者；`docs/` 其余文档覆盖式修订。
5. 路线图 `docs/roadmap/00-roadmap.md` 是唯一进度看板；根 README 不放状态。
6. `.agents/` 保存 AI 工作记忆：`CONTEXT.md` 覆盖式交接、`handoff/` 滚动 5 份、`pitfalls/` 与 `skills/` 沉淀；有硬预算。
7. 每阶段：文档定稿 → 实现 → 逐条验收 → 进度报告（含体量核对与规范复查）→ tag。
8. 体量预算：单篇文档/ADR/设计稿、文档总数、代码文件/函数、依赖数量都有上限。
9. 规范自身可复查：漏洞、过严、过松、矛盾四问；触发信号出现当轮修。

## 与参考仓库的差异（有意为之）

| 项 | Timo-pi | 本项目 |
|---|---|---|
| 语言/技术栈 | Rust + gpui-kit + NSH | Go + MyGo + 子进程插件 |
| 内核来源 | 自研 Rust 内核 | 依赖 `sky-valley/pi` |
| 门禁 | fmt / clippy / cargo test / check-size | gofmt / go vet / go test -race / check-size（Phase 1 建立） |
| 构建产物治理 | Cargo `target/` 容量预算 | Go build cache 不在仓库；二进制与前端资产另管 |
| 插件 | A 轨 JS shim + B 轨 TSX/NSH | A 轨适配器 + B 轨 Go 原生/WebView |
| 文档基线 | 多阶段累计 | 新建，Phase 0 一次性建立 |

## 理由

- 结构经过实践检验，能直接回答“新会话如何接手、决策如何留痕、阶段如何验收”。
- 把“过程”和“事实”分开，避免 docs 被会话记录污染。
- 预算与复查机制防止文档和规范自身膨胀。

## 后果

- 前期文档量大，但后续返工少；所有者在 Phase 0 需要一次集中确认。
- 规范是硬约束：违反要么改正，要么先改规范（走 ADR），不允许“这次先这样”。
- 语言约定：文档中文、代码/标识符/commit 英文；对所有者汇报用非技术语言。
