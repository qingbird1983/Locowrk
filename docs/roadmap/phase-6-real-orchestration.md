# Phase 6：真实 Pi 编排插件与技能复用

- 状态：草稿
- 日期：2026-10-28
- 关联：ADR-0003；architecture/04；research/02

## 1. 目标

把真实 pi 编排插件接进 A 轨，验证 single/parallel/chain/async 委派与 steering 回传；加载用户/项目技能，并让 TUI 调用被静默降级为诊断而非崩溃。

## 2. 开工前置条件

- Phase 2 协议与适配器稳定；Phase 3/4 的 UI 能消费编排事件。
- **A 轨接入形态已定稿**（桥接 TS 扩展 vs Go 重写），写入 ADR。
- 选定 1~2 个真实扩展作为验收样本，记录版本与来源。

## 3. 做什么

### 3.1 接入

- **桥接模式**：宿主内嵌 JS 运行时（QuickJS/WASM 等）或独立 Node 兼容进程，提供 pi 扩展 API shim；只映射编排能力。
- **重写模式**：按扩展语义用 Go 实现，保持对外行为与事件一致。
- 扩展发现：用户目录 + 项目目录（项目需信任）；版本/依赖校验；失败隔离。
- 工具注册：进入内核工具表，走同一套校验/审阅/取消。

### 3.2 编排能力

- 子代理：spawn/settle 事件、状态、取消、结果回传。
- workflow：阶段推进、失败分支、重试。
- 异步任务：后台进度、完成通知。
- steering：桌面输入可插入当前运行；`steering_applied` 事件可见。

### 3.3 技能

- 用户级技能自动加载；项目级技能需显式信任。
- 技能诊断可见（frontmatter 错误、重名、路径非法）。
- 系统提示词中技能注入的结果可在“本会话上下文”里核对。

## 4. 不做什么

- 不承诺兼容 TUI 渲染、快捷键、终端主题。
- 不做 MCP（等上游或另立项）。
- 不做 prompt templates（上游未移植）。

## 5. 验收场景

1. **真实扩展加载**：选定扩展成功启动；能力清单与诊断可见。
2. **parallel 委派**：一次触发两个子代理并行，桌面端同时看到两个节点与各自工具过程；先完成者先 settle。
3. **chain/async**：链式步骤按顺序推进；异步任务完成后通知，取消能终止。
4. **steering**：运行中从桌面输入补充指令，下一轮请求带上；事件流出现 `steering_applied`。
5. **UI 降级**：扩展调用 `ctx.ui.*`/快捷键，收到 `ErrUIUnsupported`，其余功能正常；诊断不刷屏。
6. **技能**：用户技能被注入；项目技能在未信任时不加载、信任后加载、撤销后消失。
7. **故障**：扩展抛异常/崩溃，宿主记录并禁用该扩展，不影响其他会话。
8. **回归**：Phase 1 的事件 fixture 与 Phase 2 的协议测试仍全绿。

## 6. 交付物

- 真实扩展接入与样本配置（不含密钥、不含个人路径）。
- 兼容性矩阵（能力/降级/不支持）。
- 技能信任 UI 与诊断。
- Phase 6 报告：真实读数、已知差异、Phase 7 建议。

## 7. 风险

- 桥接层复杂度失控：先只支持编排 API 子集，明确不支持清单；必要时退回重写模式。
- 扩展依赖 Node 生态：限制为打包产物，不在运行期 `npm install`。
- 上游语义变化：以固定 pi 版本为样本，升级单独评估。
- 安全：扩展等同 Agent 权限，必须默认无能力、显式授权、可审计。
