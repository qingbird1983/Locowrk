# Phase 6：真实 Pi 编排插件与技能复用

- 状态：草稿
- 日期：2026-10-28
- 关联：ADR-0003、ADR-0008；architecture/04；research/02

## 1. 目标

按 Phase 2 选定的运行时（ADR-0009）把真实 pi 编排插件接进 A 轨，验证 single/parallel/chain/async 委派与 steering 回传；加载用户/项目技能，并落实三分类矩阵：支持项可用、缓做项返回“未实现”、TUI 项 no-op + 诊断。

## 2. 开工前置条件

- Phase 2 协议、适配器与三分类骨架稳定；ADR-0009 已选定运行时。
- Phase 3/4 的 UI 能消费编排事件与兼容性诊断。
- 选定 1~2 个真实扩展作为验收样本，记录版本与来源。

## 3. 做什么

### 3.1 接入

- 按 ADR-0009 的运行时接入（QuickJS + 打包 / Node 兼容子进程 / Go 重写之一）；不再在阶段内改选型。
- 扩展发现：用户目录 + 项目目录（项目需信任）；版本/依赖校验；失败隔离。
- 工具注册：进入内核工具表，走同一套校验/审阅/取消。
- 三分类：shim 成员齐全；支持项真实实现，缓做项 `not_implemented`，TUI 项 no-op + `unsupported` 诊断；基础对话框映射宿主。

### 3.2 编排能力

- 子代理：spawn/settle 事件、状态、取消、结果回传。
- workflow：阶段推进、失败分支、重试。
- 异步任务：后台进度、完成通知。
- steering：桌面输入可插入当前运行；`steering_applied` 事件可见。

### 3.3 技能

- 用户级技能自动加载；项目级技能需显式信任。
- 技能诊断可见（frontmatter 错误、重名、路径非法）。
- 系统提示词中技能注入的结果可在“本会话上下文”里核对。

## 4. 不做什么

- 不承诺兼容 TUI 渲染、快捷键、终端主题。
- 不做 MCP（等上游或另立项）。
- 不做 prompt templates（上游未移植）。

## 5. 验收场景

1. **真实扩展加载**：选定扩展成功启动；能力清单与诊断可见。
2. **parallel 委派**：一次触发两个子代理并行，桌面端同时看到两个节点与各自工具过程；先完成者先 settle。
3. **chain/async**：链式步骤按顺序推进；异步任务完成后通知，取消能终止。
4. **steering**：运行中从桌面输入补充指令，下一轮请求带上；事件流出现 `steering_applied`。
5. **UI 降级**：扩展调用 `ctx.ui.setWidget`/快捷键，返回零值、扩展继续、诊断只记一次；`ctx.ui.notify` 映射为宿主通知/对话框。
6. **缓做项**：扩展调用 session 写入等缓做成员，收到 `not_implemented` 诊断且不中断。
7. **技能**：用户技能被注入；项目技能在未信任时不加载、信任后加载、撤销后消失。
8. **故障**：扩展抛异常/崩溃，宿主记录并禁用该扩展，不影响其他会话。
9. **回归**：Phase 1 的事件 fixture 与 Phase 2 的协议/三分类测试仍全绿。

## 6. 交付物

- 真实扩展接入与样本配置（不含密钥、不含个人路径）。
- 三分类兼容矩阵的最终状态（支持/缓做/不支持）与诊断面板。
- 技能信任 UI 与诊断。
- Phase 6 报告：真实读数、已知差异、Phase 7 建议。

## 7. 风险

- shim 覆盖不足：先保证编排主干与基础对话框，其余明确缓做/不支持，不临时扩表。
- 扩展依赖 Node 生态：限制为打包产物，不在运行期 `npm install`。
- 上游语义变化：以固定 pi 版本为样本，升级单独评估。
- 安全：扩展等同 Agent 权限，必须默认无能力、显式授权、可审计。
