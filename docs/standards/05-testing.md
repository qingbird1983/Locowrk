# 规范 05：测试与验收

- 状态：定稿
- 日期：2026-10-28

## 1. 测试分层

| 层 | 对象 | 手段 |
|---|---|---|
| 单元 | 包内逻辑（bus、过滤、翻译） | Go `testing`，同包 `_test.go` |
| 集成 | 跨包契约（kernel↔bus、adapter↔子进程） | `internal/*/..._test.go` 或 `tests/` |
| 协议适配 | 模型流/工具 schema/事件序列 | **fixture 录制回放**；禁止 CI 直连 LLM |
| UI | MyGo 视图、插件帧生命周期 | 无窗口视图测试（Phase 3/4 起） |
| 端到端 | 阶段验收场景 | 人工按场景执行 + 可脚本化部分脚本化 |

## 2. 硬性测试义务（不达不算完成）

1. **事件契约**：10 类生命周期事件与上游常量一一映射；多会话不串流；`Seq` 单调。
2. **会话往返**：写入 → 恢复 → 投影，消息/工具结果/压缩/模型切换语义不变。
3. **接缝回归**：architecture/03 每条接缝至少一个可执行检查点；新增接缝必须同时加检查点。
4. **崩溃安全**：截断 JSONL 末行、工具输出超长、进程被杀，恢复不 panic、不丢已有数据。
5. **权限/审阅**：拒绝路径必须“零副作用”（不写文件、不 spawn），并有测试证据。
6. **子进程**：启动失败、运行中崩溃、心跳丢失、RPC 超时、孙进程占管道，全部覆盖。
7. **UI 生命周期**：插件状态中不得出现 `ui.Element`；多帧构建不 panic。

## 3. 确定性与可复现

- 时间、ID、随机源尽量注入；测试不依赖真实时钟顺序。
- 测试使用临时目录（`t.TempDir()`）；会话相关测试把 `HOME`/`USERPROFILE` 指向临时主目录（上游 `AgentDir` 不读环境变量覆盖），不写用户真实数据。
- 禁止测试访问网络或依赖外部服务状态；模型相关一律 faux/fixture。
- 测试结束清理子进程、临时文件、环境变量；禁止污染后续测试。

## 4. 门禁与覆盖率

- 门禁：`scripts/check-docs.sh` + `gofmt -l` + `go vet ./...` + `go test -race ./...`（Phase 1 起）。
- 单元测试必须能独立运行；集成测试不得依赖执行顺序。
- 内核相关包行覆盖率目标 ≥70%（报告披露、不设卡）；不达标在阶段报告说明原因。
- 性能相关阶段（3/4/5）必须有可复现的读数（延迟、CPU、内存），不能只写“感觉流畅”。

## 5. 回归纪律

- 修复缺陷必须先写“能复现的失败测试”，再修复；该测试永久保留。
- flaky 测试即修或隔离（`t.Skip` + issue 引用），禁止长期带 flaky 绿灯。
- 上游升级后，先跑契约/fixture 测试，再跑真实冒烟；不以“编译通过”作为兼容证据。

## 6. 验收流程

- 每阶段验收 = 逐条执行 phase 文档“验收场景” + 《阶段进度报告》记录结果。
- 一票否决项：该阶段 phase 文档中标注的场景（如 Phase 1 的会话恢复、Phase 2 的崩溃隔离）；未通过不得打 `phase-N.end`。
- 验收证据（日志、截图、读数、录屏）放 `docs/design/phase-N/` 或链接，不入大二进制。
