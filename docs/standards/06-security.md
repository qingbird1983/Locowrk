# 规范 06：安全与隐私

- 状态：定稿
- 日期：2026-10-28

## 1. 威胁模型（一句话）

本项目以本机用户权限运行，会执行模型驱动的工具（改文件/跑命令）与第三方插件代码——安全设计围绕“**默认最小能力，一切显式授权**”。

## 2. 仓库卫生

- 密钥/凭证/令牌**严禁**入库：`.env*` 已 gitignore；示例只允许 `.env.example` 占位符。
- 个人绝对路径不入库（文档引用外部项目用 URL 或相对描述）。
- 提交前自查；CI 的文档门禁会扫描常见个人路径；Phase 1 起增加简单 secret 扫描。
- 一旦发现密钥泄露入历史：立即吊销该密钥，再清理历史，并记录事故。

## 3. 凭证存储

- API key 等凭证：桌面端入**系统钥匙串**（MyGo Secrets 或平台 API）；CLI/开发期允许环境变量。
- 配置文件只存**引用**（如 `keyRef: keychain:pi/anthropic` 或 `$ENV:ANTHROPIC_API_KEY`），不存明文。
- 日志、事件、诊断、插件协议必须脱敏：key/token/`Authorization`/`*_API_KEY` 值一律遮蔽。
- 钥匙串不可用时 **fail-closed**：提示用户，不回退到明文文件。

## 4. 工具执行安全

- 工具分级：只读（read/ls/find/grep）、写入（write/edit）、执行（bash/powershell）。
- 危险操作（删除、覆盖、不可逆命令）必须经用户确认；确认策略可配置，默认从严。
- 审阅接缝在 `BeforeToolCall`：拒绝必须零副作用（不写文件、不 spawn），并记录原因。
- 不做 VS Code 式“项目信任”大而全门控；但**项目内技能/插件默认不加载**，需显式授权（接缝 #11）。
- 工具输出落临时文件时使用私有权限与唯一路径；避免把敏感内容写进可预测位置。

## 5. 插件与扩展安全（两轨一致）

- **默认无能力**：文件、网络、执行、环境变量都要 manifest 声明 + 用户逐项批准。
- **硬拒绝**：`.env*`、SSH 凭证、`.git/**` 的读写；全树写删；未声明的网络域。
- 插件不得直接操作窗口、菜单、快捷键、宿主内部状态；只能经宿主 API。
- 子进程：进程树清理、输出速率上限、内存上限、RPC 超时、心跳；崩溃不得拖垮宿主。
- 每次能力拒绝与高风险授权必须留审计记录，用户可查。
- 插件 UI 只接受声明式描述；不执行插件下发的代码/脚本。

## 6. 供应链

- 依赖准入按 standards/04 §5；`go.sum` 入库；固定提交/版本。
- 升级窗口化：内核与 MyGo 升级独立提交；升级前跑全量测试与安全相关用例。
- 许可证检查：只允许 MIT/BSD/Apache-2.0 等兼容许可证；GPL/LGPL 代码不得复制进本仓库。
- 构建产物与签名密钥不入库；发布签名流程单独文档化。

## 7. 隐私与遥测

- 默认**零遥测**、零上报；仓库内内核的 `pi/telemetry` 必须显式关闭并验证。
- 崩溃报告只在用户点击后生成，先展示将发送的内容；默认不含会话正文与路径。
- 会话内容属于用户；删除会话即删除文件；备份行为由操作系统决定，UI 说清楚。
- 插件读取会话/文件必须经宿主 API 并受能力限制；不得批量导出未授权数据。

## 8. 漏洞报告

- 暂以仓库 issue 私密方式报告；正式渠道由所有者决定后补充。
- 修复优先级：数据泄露/远程执行 > 权限绕过 > 拒绝服务 > 信息暴露。
