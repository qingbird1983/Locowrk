# 调研 02：pi 的扩展面与本项目的兼容边界

- 状态：定稿
- 日期：2026-10-28
- 关联：ADR-0003；architecture/04

> 依据：立项方案 v1.1、`sky-valley/pi` 的 UPSTREAM 范围裁定、pi 公开文档。上游 TS 源码未随本仓库抓取；**具体事件名与 API 签名在 Phase 2 必须对照上游源码复核**，本文只锁定“分类与边界”。

## 1. pi 的四层扩展体系

| 层 | 形态 | 与界面的关系 | 本项目策略 |
|---|---|---|---|
| **Extensions** | TypeScript 模块，运行在宿主提供的 API 上 | 混合：工具/命令/钩子与 UI 无关；`ctx.ui.*`、快捷键是终端专属 | 选择性兼容（A 轨） |
| **Skills** | `SKILL.md` + 可选脚本/资源 | 无关 | 直接复用（上游已移植） |
| **Prompt Templates** | Markdown 模板 | 无关 | 上游未移植；本项目暂不支持 |
| **Themes** | 终端颜色 token | 终端专属 | 丢弃；桌面视觉由 MyGo/宿主主题掌控 |

## 2. Extensions 的能力面（按桌面兼容性分类）

| 能力 | 典型 API | 桌面处理 | 理由 |
|---|---|---|---|
| 注册工具 | `registerTool(...)` | 兼容 | 输入/输出是结构化数据，与 UI 正交 |
| 注册命令 | `registerCommand(...)` | 兼容（映射为桌面命令面板/斜杠命令） | 命令是行为，不是渲染 |
| 事件钩子 | `on(...)` | 兼容（按事件白名单） | 可观察/拦截 Agent 行为 |
| 修改提示词/上下文 | 钩子 + 会话 API | 兼容（需审计） | 与模型交互有关 |
| 子代理 / workflow / 异步编排 | 扩展自行实现或调用宿主 | 兼容（A 轨核心价值） | 编排逻辑与终端无关 |
| `ctx.ui.overlay` / `select` / `input` / `confirm` | `ctx.ui.*` | **拒绝** `ErrUIUnsupported` | 终端组件在桌面无意义 |
| 快捷键 | `registerShortcut(...)` | **拒绝** | 快捷键归宿主；插件不得抢占 |
| 自定义渲染器 | TUI renderer | **丢弃** | 桌面用原生插件重建等价信息 |
| 主题 | 终端颜色 | **丢弃** | 桌面主题体系不同 |

## 3. 为什么“拒绝”而不是“降级为空操作”

- 空操作会让插件以为界面已显示，继续走错误分支，产生难以诊断的行为。
- 显式错误让插件可以分支处理（“桌面不支持，我改用日志/返回值”）。
- 宿主能给出一次性诊断，用户知道哪个插件被降级、为什么。

约定：拒绝返回结构化错误码 `unsupported`，附 `capability` 与 `hint`；同一插件同一能力只提示一次。

## 4. 关键未知（Phase 2 复核清单）

1. 上游 Extensions API 的准确模块名、导出符号与初始化方式。
2. 事件钩子的完整名单、触发顺序、能否修改参数/结果。
3. `registerTool` 的参数 schema 方言（TypeBox → JSON Schema 的边界）。
4. `ctx.ui.*` 的完整方法集与返回值语义（决定拒绝的粒度）。
5. 扩展的加载顺序、依赖解析、失败隔离与热重载语义。
6. 扩展与子代理/命令/模板之间的相互调用关系。

## 5. 对本项目的直接结论

- **不要把“兼容 pi 插件”当宣传语**；准确说法是“兼容编排型扩展，终端界面能力显式拒绝”。
- A 轨适配器必须有**能力清单**与**诊断面板**，这是产品的一部分，不是调试附件。
- B 轨桌面插件不是“翻译 TUI”，而是围绕事件流重新设计的信息呈现；两者不要混为一谈。
- Skills 是当前性价比最高的复用面：上游已实现发现、校验与注入，我们只需做信任 UI 与展示。
