> **本文件是 UI 的唯一权威文档。** 阶段：UI 正式设计（2026-10-01 用户裁定范围「**壳 + 对话主区先定稿**，其余视图后续分批」）。 视觉参考：**PI-Desktop**（Electron + React，Codex 风格单色桌面工作台），用户 2026-10-01 指定「照搬」——本文的色板、量纲、行形态均出自其源码与实机截图。 可预览原型：**`docs/design/ui-prototype/index.html`**（静态 HTML，无构建、无 CDN、 无外部字体，浏览器直接打开；11 个状态 + 明暗双主题切换）。 **视觉与交互先在原型里迭代定稿，再落 `desktop/src/`。**
>
> 实现落点：`desktop/src/`（`components/shell/` + `components/chat/` + `components/patterns/` + `style.css` tokens）。
>
> 变更纪律（§七 第 5 条照旧）：**改壳骨架或模式组件本身 = 规则变更，先改本文件再动码。**

## 一、目的

功能越多 UI 越乱的根因是**缺落位规则**：新功能来了不知道该放哪个按钮、哪个面板、 点了往哪流。本文件把规则定死，后续批次照表扩容：

1. 新功能 = 新数据流（store）+ 模式组件的实例化 + §四流向图加一行；
2. 不改壳骨架（§二）、不发明新交互形态（§三）；
3. 想放的东西在表里没有落位 → 先改本文件（对齐规则），再写码。

### 2.2 铁则：一条 46px 带，没有独立标题栏

参考对象**没有独立的标题栏组件**。窗口顶部唯一一条 chrome 带由三个区域的头**等高拼成**：

1. 侧栏头 / 会话顶栏 / 工作面板头 **高度一律 `--lw-toolbar-h`（46px）**，背景各自跟随所在列， 相邻处**不设边框**，视觉连续；
2. 拖拽区**嵌在带内的空白处**（侧栏头的空白段 + 顶栏的标题段），**不放独立拖拽条**；
3. 带内一切按钮/输入一律 `no-drag`（`-webkit-app-region: no-drag` 或 Tauri 等价物）， **按钮区禁止与拖拽区重叠**；
4. 带内控件高度一律 `--lw-ctl`（28px）——46 = 28 + 上下各 9px；
5. 窗口控制浮在带右端 `--lw-wincontrols`（120px）车道上（三个约 40×46 的平面字形按钮， 图标 12px）。**面板关闭时顶栏右端预留该车道；面板打开时由面板头接管**（同一时刻只有 一个区域为车道负责，避免两个区域各留一次造成空洞）。 **关闭钮 hover = 红底白字形 `#c42b1c`（Win11 标准配置，v4.0 用户裁定）**； **面板开关钉窗（v4.1 用户裁定）**：开关 `position:fixed; top:9px; right:120px; z-30`——**不参与任何随面板开合收缩的布局**（文档流方案里主区自身会缩，开关必被 挤动）；面板打开时面板头以 `padding-right = 车道 + 40px` 为它留槽（原「关闭面板」 钮的位置，`\\\\\\\\\\\\\\\[+\\\\\\\\\\\\\\\]\\\\\\\\\\\\\\\[⤢\\\\\\\\\\\\\\\]` 在其左侧），开合前后开关坐标逐像素不变；
6. 侧栏折叠后，侧栏切换按钮出现在顶栏左侧的 lead 槽——**该槽恒在**（展开时宽 0）， 它是零宽导致标题零跳变，**折叠不得使正文列位移**。

### 2.3 侧栏组织：项目工作区接管（v3.9 重写；用户 2026-10-04 issue 批裁定）

**项目工作区接管对话管理**（v3.9，用户 issue 批 #4）：侧栏不再有独立的「会话」组与 时间桶——对话一律以「任务」身份挂在项目下，时间桶标签退役，组内按最近活动降序直排。 层级仍**固定两级**，不要再加一级：

```
＋ 新建任务        Ctrl+N          ← 顶部动作区（v3.9）：三行动作，不再是胶囊输入 + 小方钮
⌕ 搜索            Ctrl+K          ←   「搜索」= §3.15 命令面板（全部可操作项，不是搜会话）
⌗ 插件市场                        ←   原「扩展」上移改名（issue #11）
项目        ▾        ⇅  ＋          ← 组头行（issue #6）：▾ 左对齐紧跟文字，筛选/新建右对齐 hover 显形
  📁 Locowrk           ⋯ ＋       ← 项目行（issue #7⑧）：文件夹双态=折叠/展开；⋯菜单+新建任务 hover 显形
  │ 任务 A                     ← 任务行（issue #9 + 用户裁定）：名与项目文字**同一左缘不缩进**，名前发丝线
  │ 任务 B ●                      挂在文件夹字形下方；状态点 = 工作状态图标
  📁 qingbirdwork
```

* **「项目」组头行（issue #6）**：11.5px `--lw-ink-4` 标签行。文字后紧跟 12px 下三角 （左对齐），点击 = **折叠所有项目**（已全折叠时再点 = 全部展开，字形 chevronDown/ chevronRight 随状态换形，禁旋转）；右对齐「筛选 / 新建项目」两个 16px 图标钮， **隐藏状态、鼠标悬停组头行时显形**（同会话行 `…` 的显形纪律）。筛选 = 菜单 「全部 / 只看进行中」（前端过滤，不发明后端）；新建项目 = 原生目录选择对话框 （`pick_directory`，§7 规则 8 同族）→ 追加进设置 `tools.fsRoots`，保存即生效。
* **项目行（issue #7⑧）**：28px 行 = **14px 文件夹字形（双态：折叠 = 闭文件夹、 展开 = 开文件夹，v3.9 起不再画前置 chevron）** + 13px 项目名 + 可选 6px 运行点； hover 显形右对齐「⋯ / ＋」两图标——**⋯ = 项目菜单**（§3.20 形态：新建任务 / 在文件夹中显示（`reveal_in_explorer`，仅 fsRoots 根目录合法）/ 移除项目 （danger，v4.12 用户裁定「移除项目无效」修复 = 从 fsRoots 移除且**移除即从侧栏消失**——归属不在 fsRoots 的组不再进树；会话与归属数据不动，重新添加同目录整组恢复，全部会话仍可从 ⌘K 到达）），**＋ = 在该项目下新建任务** （新会话带工作区归属：首条消息发出后端建会话即 `session_associate` 到该项目）。 点击行体 = 折叠/展开（折叠态照旧持久化进侧栏偏好，键 = workspace 存储路径）。
* **任务行（issue #9 + 用户裁定）**：28px 行形态不变（§3.6 行规则全部适用）； **任务名不缩进——与项目名文字同一左缘（28px，上下左对齐）**；任务名前画 **1px 竖向发丝线**（树形引导线，`--lw-line-strong`，高=行高、不接横臂，挂在项目行 文件夹字形中心下方）；任务名前的工作状态图标 = 既有状态点体系（运行中 4px 脉动点 / 待审批 4px danger 点，§3.6）。
* **组集合（v4.12 修订，原 v2.50/v2.55「fsRoots ∪ 已关联会话」口径作废）**：**组集合 = fsRoots**——fsRoots 已配置但无会话的根照常成组（空组只渲染头行）；会话按 `session.workspace` 归组，**归属不在 fsRoots 的会话不进树**（与下条「无归属会话不进树」同一口径：移除项目 = 项目从侧栏消失、其任务随项目退场，归属数据不动）；组名取存储路径末段；有会话的组按组内最近活动降序，空组垫后保 fsRoots 序。
* **只保留项目工作区（v3.9 用户裁定，issue #4 的严格口径）**：无归属会话**不进侧栏 树**——顶层「会话」组与「未分组」组都不存在；全部会话仍可从 ⌘K 命令面板到达 （§3.15 会话组照列），行尾 `…` 菜单「移入工作区」可归位进项目。
* **顶部动作区（v3.9，issue #5⑪）**：侧栏体顶部三行 30px 动作行（icon 15px + 13px 文案 + 行尾键帽）：**新建任务（Ctrl+N）** / **搜索（Ctrl+K，打开 §3.15 命令面板—— 搜的是页面全部可操作项，不是搜会话）** / **插件市场**（原侧栏底「扩展」上移改名）。 原搜索胶囊输入框与「正文命中」段退役——正文搜索并入命令面板（§3.15 v3.9 增补）。
* 分组头/行 hover `--lw-wash-2`；可折叠（折叠态持久化进 `sidebar 偏好`）。
* 会话行 28px、圆角 8px、`0 8px` 内边距、13px 文案、超长省略；**选中行 = `--lw-wash-3` 填充，禁止左侧色条**；hover = `--lw-wash-2`；行尾 `…` 按钮仅 hover/选中时出现（重命名 / 导出 / 移入移出工作区 / 删除，§3.6）。
* 侧栏头右侧 = 侧栏折叠按钮；**不放品牌名以外的内容**。
* **折叠**：宽 0（150ms），体不卸载（保滚动位置）。
* **拖拽调宽（v3.9 修订，issue #1）**：手柄嵌在侧栏右缘，`position:absolute; top:0; right:0; bottom:0; width:8px; cursor:col-resize; touch-action:none`； **范围 240–520px、缺省 275px**；可见提示 = `::after` 2×32px 圆角条（`--lw-ink-1` 20%）， 仅 hover / 聚焦 / 拖拽时显形，聚焦与拖拽时换 `--lw-accent`，聚焦不画外框；
* **拖拽中**根节点置 `data-sidebar-resizing="true"`，全局 `cursor:col-resize !important` + `user-select:none !important`；指针 `setPointerCapture` + 全套指针事件；
* **键盘可达**：`role="separator"` 全套 aria + `←/→` 步进 16px、`Home/End` 到两端、双击复位；
* **宽度跨重启持久化**；**折叠 ≠ 宽度 0**：折叠是独立状态，展开时回到记住的宽度；
* **拖拽自由调宽（v3.9 修订，issue #1）**：拖拽只在 240–520 内自由拉大拉小—— 向左拖到最小值**钳制停在 240**，**不得触发折叠/隐藏**（旧规"拖到小于最小值即折叠" 废弃：用户左拉是想调窄，不是想藏掉侧栏）；折叠功能本身保留，仍由折叠按钮 / `Ctrl+B` 显式触发（§2.4）。

### 2.4 目的地与导航

**不引入独立图标栏**（与我 2026-10-01 首版提案不同，按参考对象实机纠正）：参考对象把目的地 做成**侧栏底部的图标按钮**，275px 的侧栏因此一栏两用，窗口顶部不再被第二栏切走宽度。

| 入口 | 位置 | 备注 |
|---|---|---|
| 对话 | 隐式（侧栏项目结构就是对话入口） | 不占图标位 |
| 新建任务 / 搜索 / 插件市场 | 侧栏顶部动作区三行（v3.9，issue #5⑪） | 插件市场 = 原「扩展」上移改名；搜索 = ⌘K 面板 |
| 记忆 / 定时 / 设置 | 侧栏底图标按钮（此序，v3.9 issue #12） | 各 28px，图标 15px，aria-pressed |
| 通知 | 侧栏底图标，点开 popover，不是页面 | 见 §3.13 |
| 命令面板 | Ctrl/⌘ + K + 侧栏「搜索」行 | 唯一「跳任何地方」的入口，§3.15 |
| 工作面板开关 | 会话顶栏右侧独立成组 | 只在对话目的地有意义；首页空态下隐藏、不可展开（v3.9，issue #10） |

**目的地一律整页接管 ③④⑤**（用户 2026-10-01 纠正；参考对象源码 `page !== "chat"` 时渲染 整页路由，设置更极端——连 chat shell 都不渲染）。切换规则：

* **对话视图不卸载**：目的地切换时用 `hidden` + `inert` 把 chat shell 挂起，回来即恢复 滚动位置与在跑的会话（参考对象先例）；
* 非对话目的地在侧栏右侧铺满（占据 ③④⑤ 的位置），**侧栏 ① 保持显示**（会话随时可切回）；
* 每个目的地的**页头形态固定**：20px 标题 + 右侧主按钮（accent 实心）+ `…` 溢出菜单； 需要子页签时用 §3.2 的计数页签，不新开导航层。

### 2.5 工作面板

工具产物（diff / 文件 / 预览 / 工具产物 / 子 Agent 转录）的**第二展示面**——对话不再被 产物挤爆的关键。形态对齐参考对象：

* **宽度 = 三栏预算，不是固定上下限**（照参考对象 `work-panel-resize.ts`）：最小 244px、 缺省 360px、**无固定上限**——上限 = `容器宽 − 侧栏宽 − 主区地板 450px`，宽窗口可以把 宽度花在面板上；**主区地板 450px 是硬的**（= composer 工具条不折行的宽度），顶到地板时 **先让侧栏折叠**，再谈面板；
* **拖拽柄**：`position:absolute; inset-block:0; left:-5px; width:10px; z-index:30; cursor:col-resize; touch-action:none`；可见提示 = `::after` 2×32px 圆角条（`--lw-ink-1` 20%）， hover / `:active` / `:focus-visible` / 拖拽中才显形，聚焦与拖拽时换 `--lw-accent`； `:focus-visible` 不画外框（圆角条本身就是焦点提示）；拖拽中根节点置 `data-work-panel-resizing="true"`，全局 `cursor:col-resize !important` + `user-select:none !important`；
* **键盘与复位**：柄 `tabIndex=0`、`role="separator"` + `aria-orientation="vertical"` + `aria-valuemin/valuenow/valuemax`；`双击 = 复位缺省宽`（clamp 到当前预算内）、 `Home/End` 到两端、方向键步进 16px；指针路径用 `setPointerCapture` + pointerdown/move/up/cancel + `lostpointercapture`；
* 头部：`+` 新建页签（空态即**启动器清单**：审阅 / 文件 / 浏览器 / 子 Agent 转录 / 工具产物）+ 页签条（可关闭）+ 最大化 / 还原（**斜对角双箭头图标**，v4.0）—— **「关闭面板」钮退役（v4.0 用户裁定）：开合统一走顶栏开关**，面板头不再重复出第二 关闭口；**面板头 `padding-right = 车道 + 40px` 为钉窗开关留槽（v4.1）**；
* **插件可贡献页签类型与启动器条目**——这是「一切皆插件」在 UI 上的第一个真兑现点 （参考对象里「Git 透镜」「依赖审计」就是这么来的），贡献项带 `插件` 徽章；
* **面板打开/宽度/页签是跨会话保持的壳状态**，不是某个会话的从属物。

**✅ v2.52 骨架落地（拆批：本批 = 骨架 + §3.16 子 Agent 转录页签这一种内置页签；插件 贡献槽位随插件批次走 plugin-api 末尾追加，启动器清单只列已实装条目，不发明占位）**：

* **预算**：面板宽 = `clamp(244, 容器宽 − 侧栏宽（折叠算 0）− 450)`，缺省 360； **主区地板 450 是硬的**——拖宽顶到当前预算且侧栏还展开时，**先折叠侧栏**（腾出预算） 再继续贴新预算钳制；窗口缩放时实时收口；
* **拖柄**：`inset-block:0; left:-5px; width:10px; z-30` + 全局锁 `data-work-panel-resizing` + `setPointerCapture`；`::after` 2×32 圆角条 （`--lw-ink-1` 20%，hover/active/focus/drag 显形，聚焦与拖拽换 `--lw-accent`， 聚焦不画外框）；键盘 = `role="separator"` + 方向键 16px + `Home/End` 到预算两端 + 双击复位 360；`aria-valuemax` = 当前预算（动态）；
* **最大化/还原**：最大化 = 宽取当前预算最大（主区保持 450 地板），还原 = 回先前宽度； **v4.0 用户裁定改版**：最大化 = **视口 − 侧栏宽**（直接覆盖对话区，主区地板在最大化态 **不保**）——侧栏展开 = 顶到侧栏左缘，**侧栏折叠 = 满窗口最大化**；侧栏开合时最大化 宽度实时跟随；**面板 `z-20` 压过对话区浮起的 composer 坞（z-12）/列宽柄（z-11）** ——覆盖态浮层残影不再透出（常态开面板与主区无水平重叠，此 z 只在覆盖态生效）；
* **壳状态**：开合与宽度持久化进 localStorage 面板偏好（`work-panel.v1`）；页签 （进程内）跨会话保持、不跨重启——重启后面板按持久化开合态恢复但页签为空 （诚实：子转录文件还在，可从子 Agent 卡/启动器重开）；
* **入口**：会话顶栏右侧独立成组的开关（`panel` 字形，`aria-pressed`，§2.4）+ §3.10 子代理行展开体的「查看完整对话」文本钮（v4.13 卡退役后入口在行里）。

### 2.7 主对话区列宽（第三条调宽轴，用户 2026-10-01 指出；参考对象 `ConversationWidthHandles` / D439）

**主区内容列自己也能调宽**，而且**与 composer 严格同步**。参考对象源码注释里记着一个真实 bug： 不显式同步"每条消息的正文宽"时，列加宽了而消息行冻在默认值上——**所以这条必须按"同源"来写**。

* **一个变量，三个消费点**：列宽偏好只存**一份**（`--lw-content-max`），同时喂 **转录列**、 **composer 列**、**每条消息的正文宽**。三者同宽**是同一个变量保证的，不是三处各自对齐**—— 任何一处单独写死宽度都是 bug（§3.11 composer 已按此改）；
* **列宽是"偏好值"，实战宽度 = `min(主区宽, 偏好值)`**：侧栏展开或面板打开把主区挤窄时， 列被自动压缩而**偏好值不被改写**；主区变宽后回到偏好宽度；
* **数值**：缺省 **760**、拖拽/键盘下限 **560**、单侧留白 **24**（→ 上限 = `主区宽 − 48`， 留白是给调宽热区与 minimap 用的）。落地以 `shared` 的 `DEFAULT\\\\\\\\\\\\\\\_/MIN_CHAT_CONTENT_MAX_WIDTH`、`CHAT_CONTENT_WIDTH_GUTTER` 为唯一真源，本文不复制为第二份常量；
* **双柄、中心对称（"对等"的准确含义）**：左右各一个柄，柄的位置由列宽与中心算出 （`max(0, (100% − 列宽) / 2 − 16px)`；v4.0：**16 = 柄宽 12px 全部落到列外 + 4px 空隙** ——可见提示条与正文之间留白，柄不再骑在列缘上；旧值 −6px 使提示条贴着正文），**两柄改的 是同一个偏好值**，列始终居中。 **指针位移 1px ⇒ 列宽变化 2px**（左柄 `start − 2Δ`、右柄 `start + 2Δ`）—— 因为动一边等于两边对称各动一半。这一条不写清楚，实现者一定会写成 1:1 而后发现"拖不动/拖过头"；
* **转录列与 composer 列的对齐由滚动槽对称保证（v4.0）**：转录滚动区 `scrollbar-gutter: stable both-edges`——滚动条槽两侧对称预留，两列同以主区中线居中 （旧 `stable` 只在右缘留槽，转录列中心左移半个槽宽 ≈5px，正文整体左偏错位）；
* **触发区 = 12px 隐形热区**（`cursor: col-resize`、`pointer-events: auto`；容器 `pointer-events: none` 且 `inset: 0 0 <composer 高>` ——**热区下沿停在 composer 顶部**， 不许覆盖输入框，否则点输入框会变成拖宽）；
* **可见提示 = 2×40px 圆角竖条**，竖直居中，`--lw-ink-1` **18%**（暗）/ **12%**（亮， 刻意更淡——同一条规则在亮色下不该读成"亮缝"）；静止不可见，hover / focus-visible 淡入； **拖拽中高度 40 → 56px、加深到 32%（暗）/ 20%（亮）**（"变长变深"＝正在拖）；
* **聚焦不画外框**，改用 `box-shadow: 0 0 0 2px color-mix(accent 22%)` 软环 （柄没有填色底，硬外框会显得飘在半空）；
* **拖拽中零延迟**：拖拽期间临时把列宽过渡关掉（`transition: none`）——列宽必须跟手； 仅**程序化改宽**（双击复位 / 键盘 / 窗口变化）才走 §6.6 ④ 的滑动过渡；
* **性能**：`pointermove` 用 `requestAnimationFrame` 节流，每帧最多一次渲染；
* **键盘**：`role="separator"` + `aria-orientation="vertical"` + `aria-valuemin/now/max` + `aria-valuetext`（"对话宽度 760 像素"）+ `tabIndex=0`；`←/→` 步进 **16px（Shift = 32px）**， 方向按柄的 `data-side` 判定（左柄 ← 变宽、右柄 → 变宽）；`Home` = 复位缺省； `End` = 最宽（按当前主区宽 clamp）；**`Esc` 取消本次拖拽**；
* **取消语义**：`pointercancel` 与 `Esc` 都回到**起始宽度**且**不落盘**——取消就是取消，不留痕；
* **双击 = 复位缺省 760**（并落盘）；
* **持久化走设置、不走 localStorage**：列宽是"设置"级偏好（随设置同步/备份），落在 settings 的 `chat.contentMaxWidth`（§3.2 `ChatSection`）；写失败只留 live 值，下次拖拽重试；
* **实时上限**：用 `ResizeObserver` 跟主区宽，`clamp(偏好值, 560, 主区宽 − 48)`—— 窗口缩小后旧偏好值不会溢出；
* **不参与三栏预算**（§2.5）：列宽只是主区内部的 `max-width`，**不占用布局宽度**—— 所以 **450px 主区地板仍然是硬的**，列宽偏好再大也挤不掉面板与侧栏。

### 3.5 数字呈现规范

| ❌ 机器语言 | ✅ 人的语言 |
|---|---|
| 262,144 token | 256K |
| 52,428.8 token | ≈51.2K（compactNumber 按 1024 进位） |
| 102,400 字节 | 100KB |
| 1790770863（时间戳） | 3 天前 |
| 87 个工具 / 20 个暴露 | 已优化 87 → 20 |

* 大数用档位（K/M/G）、小数取整、单位不重复（写 `256K`，不写 `256K token`）。

|---|---|
| 计划 | 只有 Pure 放行，写操作全拒 |

| 完全访问 | 全部放行，只记审计日志 |

* **边界**：参考对象把「权限」（ask / accept-edits / auto）与「默认模式」（智能体 / 规划 / 目标）做成**两个独立控件**。Locowrk 的四档把"计划"折进了权限梯子（项目自己的裁定，照办）； 将来若加"默认模式"轴，**必须是 chip 旁边第二个独立控件，不得折进这个菜单**—— 一个菜单里混两个语义轴，用户无法从文案推断后果。
* **chip 显示"实际生效档位"，不显示"用户选的档位"**：若某个工具的审批被强制拦下 （硬底线 / 子 Agent 冒泡 / 沙箱自身拒绝），chip 必须反映**当时真正生效的档位**， 否则用户会看到"完全访问"却仍被拦，以为自己的设置没生效—— **档位标签是状态显示，不是愿望显示**。

### 3.16 子 Agent 转录（工作面板页签，`components/shell/SubagentTranscriptTab.vue`）

§3.10 的子代理行「查看完整对话」是**入口**，这里是**子会话自己的转录**。⑮ 的"子内活动不投影"约束的是 **父会话转录**，不是"用户不能看"——想看时必须有地方看得到（本项目的可见可审计取向）。

* 页签名 = 子 Agent 名（如 `ui-designer`）+ bot 字形；可关闭、可与审阅/文件等其他页签并存；
* 页内**复用 §3.7–3.9 的同一套行语法**（过程组 / 工具行 / 思考行）——子转录不是第二套 UI， 这样"父里看到的摘要"与"子里看到的细节"是同一套心智模型；
* **composer 在本页签禁用**，底部固定一条说明：`子 Agent 由主 Agent 驱动，无法在此输入。` ——只读面必须自证只读，否则用户会以为能插话；
* 子转录里的工具行**照常带副作用徽章**；审批仍在父侧弹同一扇门，这里只是记录；
* **数据来源需后端补一条**（§8.2）：⑲ 起子会话转录**不落盘**（⑮ 黑盒的既有边界）。 两条通路择一：① **子会话也落盘**再走 `session_history` 重放（推荐：零新事件类型、 复用重放、跨重启可回看，且不动 ⑮ 的"父转录不掺入"语义）；② 子会话事件走**独立通道** 只喂面板。推荐 ①。

**✅ v2.52 落地（取推荐 ①，宿主接收器形态，零 ABI 变更）**：

* **落盘**：kernel-agent 新 `SubTranscriptSink` trait（`close(child_id, own_from, &child)`，`SubagentTool` 构造期**可选注入**——headless 不注入 = 维持纯黑盒）； `run_child` 收束时把子**自身段**（`own_from..`，fork 前缀不带）交给宿主；desktop 实现写 `<数据根>/sub-transcripts/<child_id>.jsonl`（id 走 `session_file` 白名单 校验；写前删旧文件防残留）。**子事件不进父日志**（膨胀归零），⑮"父转录不掺入 子内活动"原样不动；
* **读取**：`subagent_transcript(child_id)` 命令 = 盘上 load + 与 `session_history` **同一 `project_events` 全量投影**（前端数据形状与主转录一致）→ 页签内构造 chat store 同款条目数组，**复用 MessageRow / ToolRow 同一套行组件**（§3.7–3.9 同一心智模型；近似如实记录：本批平铺过程行、不做过程组合成组——那是 ChatTranscript 的 walk 逻辑，后续随面板页签丰富批次接入）；子内 `ApprovalDecided` 同投影成 记录条（审批在父侧决策，这里只是记录）；
* **页签名** = `子 Agent` + 任务 prompt 截断摘要（⑮ `subagent_run` 没有 name 参数， 不发明）；bot 字形；可关闭，可多开并存；
* **只读自证**：页签内不渲染 composer，底部固定一条 `子 Agent 由主 Agent 驱动， 无法在此输入。`；
* **跨重启**：转录文件在，面板页签（进程内）不跨重启——从子代理行或启动器清单 重开即重放（历史会话的子转录同样可看）。

* **记录条 = 投影不是本地生产**：`SessionEvent::ApprovalDecided` 由 Kernel 落日志（纪律 6）， `project_events` 把它映射成 `agent://approval-resolved`（`tool` 从同切片 `ToolCall` 按 `call_id` 解析）——实时与历史重放**同一来源**，无双条、重启后记录不丢；前端只消费。 记录条文案 `已允许 · {动作名}` / `已拒绝 · {动作名}`（决策粒度 once/session 不入日志事件， 文案不区分——记录条的可审计事实是"批没批"，不是"按的哪个钮"）；
* **三键的"允许本次对话" = 桌面 `ApprovalHub` 进程内豁免集**（`(session_id, tool)`，命中即 `resolve` 直接放行、不再推请求）；进程退出即失效——"本次对话"的诚实边界，重启后重新问；
* **超时自动拒绝 = `ApprovalHub` 桌面定时器**（缺省 100s，`§8.3-5` 阈值待裁定；请求置位即 起 `tokio::spawn` 计时，`decide` 先到先清，超时 `deny("超时自动拒绝…（fail-closed）")`）—— 不受 WebView 后台节流影响；前端卡片只做秒数倒计显示，不重复执行拒绝；
* **载荷扩展**：`ApprovalRequestPayload` + `description`（`ToolSpec.description`，理由行数据源）； 风险三档由 `side_effect` 前端映射（`Irreversible→高` / `Compensable→中` / 缺省按高）； ㉘·B 起 + `workspace`（会话真实归属，环境行数据源）与 `external`（外部路径门命中， 前端据此藏「允许本次对话」）；环境行 = `workspace` → `tools.fsRoots\\\\\\\\\\\\\\\[0\\\\\\\\\\\\\\\]` → `临时会话` 三级回落；
* **提问行用 §3.18 中文动作名**（原型裸工具 id 与 §3.18 纪律冲突，以本文为准）； `ApprovalModal` 退役；决策成功后焦点回 composer。

### 3.18 工具与动作的人类呈现（工具 id 不许直显）

用户 2026-10-01 裁定：**所有动作与工具都必须显示中文名**，不许把 `fs_edit` / `shell_read` 这类内部 id 直接甩给用户；**参数摘要必须加工过，不许裸复制命令**。

**动作名映射**（落 `locales/{zh-CN,en}.ts` 的 `tool.action.\\\\\\\\\\\\\\\*` 区，是 i18n key 不是硬编码中文）：

* `shell` / `shell_read` → **运行**；`sandbox_run` → **沙箱运行**
* `fs_read` → **读取**；`fs_write` → **写入**；`fs_edit` → **编辑**；`fs_delete` → **删除**； `fs_restore` → **恢复文件**
* `git_status` → **查看状态**；`git_diff` → **查看差异**；`git_commit` → **提交**； 其余 `git\\\\\\\\\\\\\\\_\\\\\\\\\\\\\\\*` → **Git 操作**
* `memory_write` → **记住**；`memory_read` / `memory_search` → **检索记忆**
* `search_tools` → **检索工具**；`subagent_run` → **派生**；`schedule_create` → **创建定时任务**； `notify` → **发送通知**
* `mcp\\\\\\\\\\\\\\\_\\\\\\\\\\\\\\\*` → **MCP：{server} 的 {tool}**（server / tool 取真名做参数）
* 表外工具（第三方插件）= 取 manifest 的本地化 `name`；**manifest 没给 name 时回落工具 id 并附 `插件` 徽章**——回落是例外，不是常态。

**参数摘要的加工规则（按工具类型分派，不是统一 clip 原始值）**：

* **命令类**（`shell\\\\\\\\\\\\\\\*` / `sandbox_run`）：**先剥包装**——去掉 `cd "<路径>" && …` 前缀、 去掉最外层 `bash -lc "…"`；`&&` 串联时只显示第一个有意义的命令，其余记 `… +N`；再 `clip`。 **严禁**把 `cd "$PI_SCRATCH_DIR" && sed -n '236,252p' verify3.mjs` 原样倒出来。
* **文件类**（`fs_read` / `fs_edit` / `fs_write` / `fs_delete`）：摘要 = **工作区相对路径** （能相对就相对）+ 行数或变更统计（`292 行` / `+42 −18`）。**不显示绝对盘符**—— `C:/Users/42527/…` 是噪声，全路径留给 tooltip 与展开明细。
* **对象类**（参数是 JSON 对象的工具）：显示**键值的自然语言摘要**——取 1–2 个最有信息量的 值（`prompt` / `query` / `url` / `key`）写成 `键：值`，**绝不显示 `{`、`}` 与引号**； 多余键记 `… +N`。
* **分支/服务器类**（`mcp\\\\\\\\\\\\\\\_\\\\\\\\\\\\\\\*`）：摘要 = `{server} / {tool}`。
* 兜底：`clip(第一个原始值, 48)`（现状行为），**仅当上面全部不匹配时**使用。

**"思考"行同理**：推理原文里的 markdown 记号（`\\\\\\\\\\\\\\\*\\\\\\\\\\\\\\\*`、反引号）与多余换行在**摘要态**剥掉， 只留纯文本首句；原文在展开态照原样呈现（不篡改事实）。

**明细态人话化（v4.13 修订「展开态才是诚实面」）**：诚实 ≠ 原始——摘要态人话的规则不变；**展开明细的默认视图也是人话**（§3.8 渲染表：字段名中文标签 / 枚举中文 / 值带单位 / 时间相对化 / 路径相对化），**原始 JSON 收进「原始数据」折叠入口**（默认收起，给工程师）。工具 id / 全路径 / 版本在原始数据与调试面板仍可查——「两态各司其职」升级为三层：**摘要人话 → 明细人话 → 原始数据兜底**。摘要态的「禁止裸显工具 id」纪律不变；表外工具回落 = 类型词「工具」+ 描述列显工具 id（mono），原始性不再出现在折叠行。

### 3.19 控件族（表单与按钮，两主题共用）

**唯一允许的控件形态表**；新控件先在此扩表再上页面。控件高度统一 `--lw-field-h`（≈38px）， 图标控件统一 `--lw-ctl`（28px），圆角取 §6.3 阶梯。

* **按钮**：内边距 `7px 12px`、13px、gap 6px、`:active` 缩放 0.98（150ms）。三变体： `primary`（`--lw-accent` 底 + `--lw-accent-ink` 字）/ `secondary`（`--lw-wash-2` 底）/ `ghost`（无底无框，hover `--lw-wash-2` + `--lw-ink-1`）。**禁用 = opacity .55 + `not-allowed`，不改色**（改色会与"危险"语义撞车）。
* **图标按钮**：`28×28`、圆角 12、透明底、`--lw-ink-2`，hover `--lw-wash-2` + `--lw-ink-1`； 字形 15px（窗口控制 12px）。**必有 `aria-label`**。
* **字段**：`padding 9px 11px`、`min-height --lw-field-h`、`--lw-wash-2` 底、**无边框**； 聚焦 = 底换 `--lw-raised` + `box-shadow: 0 0 0 2px color-mix(accent 22%)`； 占位符 `--lw-ink-5`；`readonly` / `disabled` 降为 `--lw-ink-3` + `cursor: default`； 密码框右侧内嵌 reveal 按钮（故 `padding-right: 34px`）。 **select 与 input 必须等高**——native select 闭合盒天然矮约 2px，一律用 `min-height` 锁死， **不许各页自己调**。
* **开关**：`32×20`、圆角全。关 = `--lw-wash-3` 底 + 1px `--lw-line-strong` 环 + 旋钮 `--lw-ink-4`（暗）/ 白（亮）居左；开 = `--lw-accent` 底 + 旋钮 `--lw-accent-ink` 居右。 **极性翻转**（旋钮颜色也跟着反，不只滑动）。无文案，语义由左侧行标题承担。
* **分段控件**：轨 `--lw-wash-2` + 圆角全 + 2px 内边距；项 `5px 12px`、12.5px； 选中项 = `--lw-raised` 底 + `--lw-shadow-raised`（**"抬起"而非变色**）。二到四选一用它。
* **下拉**：任何"看起来像输入框"的下拉必须与字段同高同形；触发器与菜单分离 （触发器可以是一个 chip）。
* **数字输入**：右对齐、宽 140px、可带单位后缀（`%` / `秒` / `token`）。
* **复选框**：16×16、圆角 4、1.5px `--lw-ink-2` 边；选中 = `--lw-accent` 底 + `--lw-accent-ink` 勾； 禁用 opacity .4。
* **帮助提示 `ⓘ`**：跟在行标题或字段标签后的一个小字形按钮（`cursor: help`，`aria-label` 即解释文案），hover / 聚焦弹 tooltip（§3.21）。**解释文案只放这一处**——行里不再多写一行说明： "行标题 + 右侧控件"是行卡唯一常态，解释是**按需展开**的。
* **行卡**（设置与列表共用）：`--lw-wash-1` 底、圆角 14、`14px 16px`、flex space-between、 gap 24；行标题 13.5px / 500 / 1.3；可选 detail 12px `--lw-ink-2`（**放"当前值"不放解释**）； 控件列 `flex:0 0 auto`、右对齐、`max-width 240px`。
* **徽章**：圆角全、`2px 8px`、11px；中性 = `--lw-wash-3` 底 + `--lw-ink-2` 字；语义 = 该色 16% 底 + 该色作字（§3.4 分族）。

### 3.20 右键菜单与行尾 `…` 菜单

同一套浮层形态，`min-width 184px`、宽随内容、`padding 5px`、圆角 14、 `1px --lw-line-subtle`、`--lw-bg-elevated` + `--lw-shadow-dialog`、`z-index 60`（§五）。

* 项：`7px 8px`、12.5px、圆角 10、gap 8px、左对齐、hover `--lw-wash-2`；
* **危险项**（删除 / 卸载）整行 `--lw-danger` 字色 + hover 时 danger 10% 底， **图标继承字色**（一个危险信号就够，不给第二个）；
* 分隔线：1px `--lw-line-subtle` + `5px 6px` 外边距；
* **先测量再显示**（`visibility: hidden` 开局，避免在视口原点闪一帧）；超出视口自动翻转 / 限位；`Esc` 关闭并**把焦点还给触发控件**；`↑/↓` 在项间移动焦点、`Enter` 执行。

### 3.21 Tooltip

* 短提示（按钮名、快捷键）：`padding 3px 7px`、圆角 10、11px、`--lw-raised` 底 + `--lw-shadow-raised`、`--lw-ink-2` 字、**单行不折**；
* 长解释（帮助文案、完整路径、参数全文）：`white-space: normal`、 `max-width: min(360px, calc(100vw - 16px))`、左对齐；
* 一律挂 `body`（否则被壳的 `isolation: isolate` 困在遮罩下），`z-index 60`，`pointer-events: none`；
* **键盘可达性由 `aria-label` 承担**（tooltip 是鼠标增强，不能是唯一通路）； 延迟 400ms 出现，移开即消失，不做淡入淡出以外的一切效果。

### 3.22 Toast

栈挂窗口右下（`z-index 50`，距边 16px，纵向 gap 8px），**同屏最多 3 条**，超出排队。

* 单条：`min-width 280px / max-width 420px`、`padding 12px 14px`、圆角 12、 `--lw-bg-elevated` + `1px --lw-line` + `--lw-shadow-dialog`；
* **左侧 6px 状态点（ok / warn / danger），不给整条染底**——染底会把"信息"变成"警报"， 用户会开始无视 toast；
* 标题 12.5px `--lw-ink-1`、正文 12px `--lw-ink-3`；可选一个 ghost 动作（如 `查看详情`）；
* 自动消失 4s（带动作按钮的 8s），**hover 暂停计时**，`Esc` 关栈顶；
* 入场 = 淡入 + 右侧滑入 8px（§6.6 动效②）；
* **toast 只承载"刚发生的事"**：需要用户处理的（审批、待决）不许只发 toast——它会被无视。

### 3.23 加载态与骨架

**三种加载形状各不相同**（不要一律转圈）：

* **目的地懒加载**：路由区居中一个 18px 旋转指示器（700ms linear）。**不铺骨架**—— 页面结构未知时铺骨架是骗人；
* **会话冷切换**（切会话正在重放日志）：对话顶栏下方一条 **2px 高进度轨**，28% 宽的不定段 720ms 来回扫；composer 置 `pointer-events: none`（不能往正在离开的会话发消息）；
* **向上翻旧消息**：列表顶部一条 `min-height 26px` 的 12px 文案 + 12px 下边距；
* **骨架屏**只在**结构已知**时用（列表条目、插件卡）：骨架块高 10px / 圆角全 / `--lw-wash-2` 底，1.4s 呼吸（归 §6.6 的"运行指示"同类）；
* **加载与空态必须可区分**：加载中不给"暂无数据"文案（那是撒谎），空态不给骨架（那是拖延）。

### 3.24 启动与控制面（参考对象有、本项目至今缺失）

* **启动画面**：`position: fixed; inset: 0; z-index 1300`，居中品牌标记 72px + 名称 16px / 600 / `-0.02em` + 一条 120×3px 的不定进度条。**只在冷启动出现**，壳就绪即淡出 200ms；
* **启动恢复面**：冷启动超过 8s 未就绪 → 换成**可操作**的恢复面（阶段文案 + `重试` + `打开日志`），`z-index 1400`。**永远不要给用户一个只会转圈的窗口**；
* **内核/后端不可用横幅**：嵌在 46px 带之下、内容区之上的一条，warn / danger 7% 染底 + 左侧 6px 状态点 + 一行文案 + 可选 `打开日志`。**致命态才用 danger 染底并阻断交互**， 可恢复态只用 warn 且不阻断；
* **更新提示条**（`z-index 45`）：同横幅形态，但只在有新版时出现，右侧一个 `查看` + 一个关闭按钮；**不自动跳转、不遮内容**。

### 3.25 键盘快捷键（Locowrk 落地表）

* `Ctrl/⌘ + K` → 命令面板（§3.15，唯一"跳任何地方"入口）

### 3.26 选择与光标纪律

**原生右键菜单（v3.9 用户裁定）**：界面空白处右击弹出的 WebView2/Chromium 原生菜单 （前进/后退/检查等）**与界面无关联，全局禁用**（`main.ts` 挂 contextmenu 拦截）； **输入框 / 文本域 / contenteditable 保留原生菜单**——复制/粘贴仍可用。行内右键语义 （§3.20 右键菜单）不受影响。

* **默认不可选**：界面默认 `user-select: none`（桌面应用不是网页，误选会让人以为能复制）。 **白名单**才可选：`input` / `textarea` / `\\\\\\\\\\\\\\\[contenteditable\\\\\\\\\\\\\\\]` / `.selectable` （助手正文、代码块、工具行内容、id / 路径 / 参数）/ 用户消息气泡。 白名单容器里的 **`button` 重新置为不可选**（否则"复制"按钮的图标会被选进去）；
* **光标**：可点 = `pointer`；禁用 = `not-allowed` + opacity .55；拖拽柄 = `col-resize`； 帮助 = `help`；拖拽进行中全局强制 `col-resize` / `grabbing` + 禁选（§2.3 / §2.5）；
* **选中样式**：`::selection` 用 `color-mix(--lw-ink-1 18%)` 底，**不用系统蓝**（单色纪律）。

### 3.27 窗口尺寸与退让顺序

* **最小窗口宽 1024px、最小高 640px**：`450`（主区地板）+ `244`（面板最小）+ `240`（侧栏最小）
  * 边距 + 窗口控制车道 ≈ 960，取 1024 留余量；
* **首次启动** 1280×820 居中；**不记住窗口尺寸**（那是窗口管理器的事，应用不自作主张）；
* **视口变窄的退让顺序固定**：① 面板先缩到 244 → ② **侧栏折叠** → ③ 面板继续缩到 244 之下（紧凑档 1px，由"侧栏重开"路径临时借用）→ ④ **主区守 450 地板不动**；
* 用户把窗口拉到 < 1024 时同样按上述顺序，**宁可面板小到 1px，不可把对话压坏**。

### 3.32 设置页整页组装（本轮原型未覆盖，规范在此补齐）

设置是**独立的壳模式**，不是"对话区里换个内容"：参考对象在 `page === "settings"` 时 连 `.app-chat-shell` 都 `hidden` + `inert`，**整个对话壳不渲染**。Locowrk 同此：设置页自带 46px 带（头 = 导航轨顶部：拖拽区 + 搜索框），**不复用会话顶栏**。

**板面切换模型（v3.4，用户 2026-10-02 裁定，替代 v3.3 的"长页堆叠 + 滚动侦测"）**： 导航轨点击 = **切换当前分区板面**——右栏同一时刻只渲染当前分区的分区组件，分区之间 不堆叠、无滚动定位、无滚动侦测、无锚点闪烁；页头标题跟随当前分区。当前分区状态放壳 store（跨目的地往返与重启内会话保持）；⌘K 命中设置分区 = 打开设置目的地并直接切到该 板面（板面切换即定位；§3.15 的"闪一下"随滚动定位一并取消）。搜索过滤只作用于导航轨 候选，命中后点击即切板面。

**一、导航轨是"数据驱动的扁平索引"，不是手写 JSX**（参考对象最值得抄的一条架构决定）

* 每个分区声明一条记录：`{ id, group, labelKey, icon, searchKeys }`；**同一个索引同时喂导航轨 与 ⌘K 命令面板**（参考对象放在 `lib/settings-search` 共享模块）。这样"新增分区忘了加搜索" 这类漂移在结构上不可能发生；
* 落点：新建 **`lib/settings-index.ts`** 作为唯一真源；§3.2 的"settings.json 分区 ↔ 面板分区 一一对应"由它机械保证（对不上就是构建期错误，不是运行时才发现）；
* 导航轨渲染 = 按 `group` 分组、组内**按索引顺序**出项（不排序，顺序即索引顺序）。

**二、Locowrk 的 12 个分区 → 4 个组**

* **偏好**：外观（appearance）/ 语言（locale）/ 对话（chat）/ 快捷键（shortcut）
* **智能体**：模型（llm）/ 上下文（context）/ 记忆（memory）/ 嵌入（embedding）
* **能力与安全**：插件（plugins）/ 命令终端（shell）/ 工具与分发（tools）（用户 2026-10-02 裁定：设置页展示名去「暴露」字；机制名 exposure 不变）
* **系统**：会话与数据（dataDir + 保留策略）/ 关于与更新

组标签 11.5px `--lw-ink-4`；实验性分区在项尾挂 `实验`（warn）徽章； **插件可贡献设置目的地**——导航轨末尾一个「扩展」组（参考对象 `settings.groupExtensions` 先例），贡献项带插件图标。这与 §2.5「插件贡献面板页签」是**同一套贡献机制**的两个落点， 不要各写一套。

**三、搜索**

* 轨顶圆角搜索框（§3.19 字段形态）；**搜分区名 + 分区内每一行的标题文案**（行的 i18n key 在索引里预声明，所以搜索是"索引驱动"而不是"渲染后爬 DOM"）；
* 无结果给一行 `没有匹配的设置`；搜索时只留命中项，**组标签随之变空则隐藏**；
* **从 ⌘K 命中进入设置时：直接切到该分区板面**（板面切换即定位；v3.4 起无滚动无闪烁）。

**四、保存模型：就地保存，没有全局"保存"按钮**

* 行内改动即写 settings（§五"默认不弹"纪律）；成功**不弹 toast**，失败走 §3.22 + 行内错误条；
* 立即生效类（主题 / 语言 / 字号 / 对话行为）不加确认、不留"未保存"态；
* **需要重启才生效的项在行下写明**（如命令终端的高危解锁），不许只靠 tooltip。

**五、恢复面（参考对象 `settings-recovery` 先例）**

settings.json 读取或解析失败时**绝不空白页**：给一个居中的恢复面（错误摘要 + `打开设置文件` + `恢复默认` + `重试`）。理由与 §3.24 启动恢复面同一条：**设置页坏了，用户就失去了唯一的自救入口**。

**六、关于与更新分区**

### 3.34 消息编辑重发（MessageRow 编辑态，✅ v2.57）

§8.2 缓办行落地。用户气泡 hover 动作区（复制旁）出现**编辑**钮（pencil 12px）：

* **出现条件（宁缺勿假）**：①重放过的消息（`session_history` 投影的 `UserMessage` 带事件位 `pos`）；②当前**最后一条**用户消息（本进程实时发送的无事件位，后端按 「最后一条用户消息」解析）。两者都不满足（运行中、或本进程发消息后又继续聊过的 中间消息）不出钮——不发明半可用的入口；
* **编辑态**：气泡原位换成自适应文本域（prefill 原文），Enter = 提交重发、 Shift+Enter 换行、Esc = 取消还原；运行中不可进入编辑态；
* **提交 = 截断 + 重发**：`session_truncate_after(session_id, pos?)`——后端忙锁 try_lock 守卫（运行中拒绝）、校验截断位是 UserMessage，`rewind_to + fork` 截断 （⑨ 先例）+ persist rewrite 物理同步（`.undo.bak` 留痕同 ⑲）；前端本地从该气泡 起丢掉条目，随后走**既有 send 通道**重发新文本（本地回显 + 流式，审批/用量/隐式 提取全部复用，不开第二条链路）。会话事件只追加不删（纪律 5）在磁盘面的例外同 undo；
* **已知边界**：被截掉轮次的子 Agent 转录文件（§3.16）留在 `sub-transcripts/` 不追删 （零进父日志，UI 无入口引用，无害残留）；`.undo.bak` 只留最近一次。

### 3.36 记忆树影子运行（M2）：/整理 命令 + 设置行 + 开发者观测（✅ v2.65）

**影子运行口径先行**：树只写不接管——对话组装零改动（现网照常 ctx-compact + memory-sqlite），全部 UI 面向 = 一条斜杠命令 + 两处设置行 + 开发者观测面板。 树视图 / 整理系统消息 / 「未整理尾巴」指示器属 M3，本批不渲染。

**① 斜杠命令 `/整理`（别名 `/organize`）**：

* composer 输入 `/整理` 或 `/organize` 回车 = **前端拦截**，不进对话流、不建 用户气泡——手动命令是元操作不是会话内容；`/org` 前缀等模糊形式不拦（宁缺 勿假，误触整理比打错字更烦）；

* **system 尾部挂「记忆树目录」**：L0 标题清单（`- b2: 标题` 行，创建序），+ 一句英文使用说明（`memory_expand(bundle_id, level)` 指引）。**目录只增不改** （纪律 3）：新捆追加在清单末尾；占位捆（整理在途）不进目录（防止占位行 出现又消失 = 隐性前缀改写）；用户编辑标题（M5）= 显式变更接受失效；
* **消息 = 未整理尾巴**，二档尾巴策略（树 v2 §7.2，§3.2 记忆区设置行）：
  * **A 边界结算（缺省）**：尾巴 = 自上次整理以来的全部原文（`bundled_until` 排他游标切片）；两次整理之间组装纯追加（前缀缓存全程命中），每次整理 = 一次计划内大失效；切点落在 User 之前由整理侧纪律保证，组装侧兜底**前进到 尾巴内第一条 User 消息**（防协议非法的半轮开头）；

* 头行（v4.11·重做，照参考图）= `N 条排队中`（12.5px / 600 `--lw-ink-1`）+ 展开/收起 chevron；**右** = `继续` 键（仅暂停态渲染，见下）+ 垃圾桶（清空全部排队，chat store `clearQueue`）+ 深色圆形 ↑（28px accent 实心 = 立即发送队首，抢占语义）；每行 = 消息预览 **单行省略**（12.5px，`title` 给全文）+ 行悬停显 `✕` 删除单条（静态观感 = 参考图，动作不可见）。
* **自动派发**：当前轮**成功收束**后逐条自动发送队首（一条一轮，收束再下一条）； **`立即发送` = 打断通道**——把该条移出队列 → 中止当前轮（§3.39④）→ 轮次收束后 立即发送该条，其余保持排队。
* **暂停语义**：手动**停止**或轮次**出错**后 `drainPaused = true`——队列不再自动 派发，头行出现 `继续` 键（点击恢复派发）；用户再次手动发送任何消息也恢复派发。
* 输入框占位符运行中切换为「AI 正在执行，输入将排队…」（如实预告行为）。

**③ 回到底部按钮 + 流式跟随滚动（`ChatTranscript.vue`）**：

* **跟随态（item 9 用户裁定「默认主动滚动，永远显示最近的会话」）**：滚动容器 维护 `following` 状态（距底 ≤48px = 在跟随）——**任何条目变化（含流式 delta 增长正文/思考行）都即时贴底**，不只 `items.length` 变化时（旧实现的缺口：流式 长回复不跟随）；用户向上滚动即解除跟随，**不打断阅读**；切会话/重放重置为跟随。
* **回到底部按钮**（item 5「一键到最近会话」）：解除跟随且有条目时，输入坞上缘 中点上方 8px 悬浮 32px 圆形钮（`--lw-bg-composer` 底 + `--lw-shadow-composer`
  * ↓ 字形）——点击平滑贴底并恢复跟随；在跟随态不渲染。

**④ 停止生成（`agent_stop` 命令，item 6）**：发送键停止态 / `Esc`（无卡时）触发：

* 后端每轮注册**会话级中止标记**（`StopFlags` 注册表）；LLM 流式通道在**每个 delta 回调点**检查标记（`LlmStreamSink::should_stop`，内核 append-only 缺省 方法）——命中即停止拉流，**已流出的部分正文作为该步收束内容如实落日志**（不 虚构结尾、不补写工具调用），轮次正常收束（TurnDone）。
* 已在执行的工具调用**不可中断**（进程面无杀手）——中止在下一步边界生效；等待 审批/选择卡时停止 = 全部待决**按拒绝/跳过**收束（fail-closed，不留悬空卡）。
* 前端：`stopRequested` 置位 → 该轮过程组头行显示 `已停止`（§3.7）；**队列转 暂停**（§3.39②）；转录不弹系统气泡（参考对象同——部分正文保留，头行如实标注）。

### 3.40 三栏响应式：收缩级联 + overlay 展开带（✅ v2.111 双模式地基；

### v2.112 按用户口述定稿——**收缩看级联、展开看档位、400 是硬限位不是警告位**）

> 限制评审尺度（用户原文，永久适用）：「任何限制，先问一句：它有没有改变用户的 使用习惯？**改了 → PASS（否决）。没改 → 加分。**」「能不能用」和「怎么用」是 两件事——限制不能碰能力只能调形态。**级联折叠是形态调整（收起的栏随时可经 按钮重开，400\~800 还是浮层形态），不碰能力，合法**；按钮禁用/隐藏碰能力，非法 （v2.109 曾犯，v2.110 修）。用户 2026-10-06 口述定稿原文落档：「左右栏同时打开 拉窄窗口，到一定阈值右栏先收缩，继续拉小到一定阈值左栏收缩，剩下中间会话区； 会话区还可以继续拉小，最小限位 400px；到达 400 取消警告词——窗口已经限制了 还要警告什么；窗口在最小 400 状态时左右栏限制一边可展开，400\~800 时展开是 悬浮式展开；左右栏在到达 800 时应该就都收缩了，只剩下最主要的主会话区。」

**① 断点与档位**（断点常量 `lib/breakpoints.ts` = 1400/1100/800/400）：

| 窗口宽 | 档位 | 形态 |
|---|---|---|
| ≥ 1400px | push | 三栏可全开（右栏仍仅手动展开时显示——非对称裁定） |
| 1100–1399px | push | 右栏已级联收起（跌破 1400 时）；主区 + 左栏 |
| 800–1099px | push | 纯主区——左栏也已级联收起（跌破 1100 时），「到达 800 两栏全收」 |
| 400–799px | overlay | 默认纯主区；两切换钮照常可用，展开 = 浮层（一次一边） |
| < 400px | — | 不存在：应用 minWidth 400 硬限位，无提示层（「窗口已经限制了，还要警告什么」——v2.109 的 narrow-veil 整体退役，tooNarrow 旗标与 narrow.\* 文案键随删） |

**② 收缩级联（拉窄方向；沿触发——只在跨越断点线的那一刻折叠，带内手动展开 不被回弹，否则按钮可用性是假的）**：

1. **跌破 1400 → 右栏收**（第一级）：右栏若开着即真实关闭 + **开意图消费** （`locowrk.work-panel.v1.open` 落 false），回宽**永不**自动弹回（非对称 裁定 ③）。挂载首校准同规（窄窗启动清悬空旧值）。
2. **跌破 1100 → 左栏收**（第二级）：瞬态 `sidebarAutoFold`（**不写手动位、 不落盘**）；**回升 > 1100 自动展开**（「如果之前是自动折叠的」）。用户在 带内（800–1099）点展开钮 = 推翻级联，停靠展开（手动优先），再跨越断点线 才重新级联。
3. **跌破 800 → 进 overlay 带**：两栏全收（浮层展开态复位；右栏若还开着 ——带内手动开的——一并真实关闭 + 意图消费）。只剩主会话区，主区可继续 拉小到 400 限位。

**③ 展开行为——非对称（放大方向，规格原文落档禁止「修对称」）**：左栏是 导航 → 窗口放大自动恢复（>1100，自动折叠的）；右栏是辅助 → 窗口放大**永不** 自动弹出（>1400 无任何自动展开；消费过的意图必须手动重开）。为什么不对称： 自动恢复省事 vs 自动弹出打扰，有意的设计不是 bug。

**④ overlay 带（400–799）**：展开 = 浮层——fixed 出文档流（z-26）+ translateX 滑入滑出，最大宽 = 窗口 2/3；**左右互斥只能开一边**（互斥方向 不对称：开右栏挤掉左栏 = 瞬态 `overlaySidebarFold`，关右栏自动解除恢复； 开左栏挤掉右栏 = 右栏真实关闭 + 意图消费，回宽不弹回）；**遮罩**（z-25， `--lw-scrim`）点击收起当前浮层——z 序让右上钉窗钮（z-30）/窗口控制车道 （z-1000）恒在遮罩之上，浮层开着右上钮永远可点。**模式切换保留状态**： 出带时右栏开着 → 变停靠（手动意图保留，非对称）；左栏浮层态复位回级联管辖 （>1100 自动展开）。

**⑤ 交互元素**（任何 ≥400px 宽度全部可用——rubric：按钮永不冻结）： 左栏切换 = 窗口左上角单一钮两态（开 = 侧栏头内收起钮、合 = 顶栏 lead 槽 展开钮，任何时刻恰一个可见）；右栏切换 = 右上角固定单钮；左缘/右缘拖宽 手柄照旧；首页空态右栏钮隐藏不变（§2.4 v2.59 页面语义，非宽度限制）。

**⑥ 实现**：`lib/breakpoints.ts` = XL 1400（右栏级联线 = 意图消费点）/ LG 1100（左栏级联线）/ MD 800（overlay 带顶）/ SM 400（overlay 带底 = 应用 minWidth，tauri.conf 同值）。shell store：`sidebarAutoFold`（左栏 级联瞬态）+ `overlaySidebarOpen`（带内浮层展开态）+ `overlaySidebarFold` （互斥瞬态）+ `overlayMode`；`tooNarrow`/`viewportLeftOk`/`viewportRightOk` 退役；`sidebarCollapsed` getter 分档——overlay 带 = `!overlaySidebarOpen ‖ overlaySidebarFold`，push = `手动位 ‖ sidebarAutoFold`。`toggleSidebar()` 分档：overlay 带翻浮层态（开左栏消费右栏意图）；push 带被级联折叠时的 展开请求 = 清 `sidebarAutoFold`（推翻级联、停靠展开），否则翻手动位。 `use-responsive-shell` 持 `prevW` 做**沿检测**：跨 1400 消费右栏意图、 跨 1100 翻 `sidebarAutoFold`、跨 800 进带全收/出带复位浮层态；挂载校准 消费悬空面板意图。互斥收口仍 = `shell.toggleSidebar()` + `workPanel.setOpen()` 两个唯一写入口，Ctrl+B/Ctrl+J/钮/⌘K/遮罩/程序化入口零旁路。WorkPanel 渲染门控 = `workPanel.open`；overlay 带浮层宽 JS 钳 min(偏好宽, 2/3)。

## 五、弹层规则

| 形态 | 判据 | 实例 |
|---|---|---|
| Modal（收窄） | 必须一次说清一个集合，且不答就不能做别的事（名单 / 数量 / 破坏范围） | 批量卸载二次确认 |

### 6.6 动效系统（v3.2 重写，本节是动效的唯一权威）

**一、动效 token（两主题共用，`tokens.css` 必须齐全）**

时长四档：

* `--dur-instant: 90ms` —— 按压反馈（`:active` 缩放）
* `--dur-fast: 150ms` —— 状态色变、**一切退场**
* `--dur-base: 200ms` —— 入场、展开、滑动指示器、进度
* `--dur-slow: 300ms` —— 一次性强调、跳回最新

缓动四条：

* `--ease-out: cubic-bezier(.22, 1, .36, 1)` —— **入场 / 展开**（起步快、尾巴极缓）
* `--ease-in: cubic-bezier(.4, 0, 1, 1)` —— **退场 / 收起**（起步缓、尾巴快）
* `--ease-standard: cubic-bezier(.2, 0, 0, 1)` —— 颜色 / 状态 / 微调（两端都有缓冲）
* `--ease-slide: cubic-bezier(.32, .72, 0, 1)` —— **滑动类专用**（胶囊指示器、抽屉、 折叠高度）：前段快、尾部极缓，读起来是"滑到位并停住"
* **命名是权威的**：`--dur-instant|fast|base|slow` 与 `--ease-out|in|standard|slide` 这八个名字为准； 原型 `tokens.css` 里的旧名 `--motion-fast|normal|slow` 是历史残留，落地时统一改名。

**明确禁止过冲 / 回弹 / 弹跳（overshoot / spring / bounce）**——这是有意画的边界：密集 UI 里 过冲会让相邻元素互相干扰，也会让人怀疑"是不是又动了一下"。要"缓冲感"靠 `--ease-slide` 的长尾， **不靠过冲**。（日后确实想要，先改本条再实现。）

**二、动效类别（封闭清单；新动效先在此扩表，不许在组件里即兴写）**

**① 状态色变** —— `--dur-fast` + `--ease-standard`：hover / focus / disabled 的底色与字色。 这是**唯一**允许在 `@layer base` 写全局 transition 的一类（组件不再散写）。

**② 入场** —— `--dur-base` + `--ease-out`：

* 浮层（弹窗 / popover / 菜单 / 命令面板）：`opacity 0→1` + `scale(.96)→1`；菜单类再加 `translateY(-4px)→0`；
* **遮罩比内容先到**：遮罩只做 `opacity`，用 `--dur-fast`（否则会出现"内容先亮起来、 背景后变暗"的错序）；
* 系统记录条：`opacity` + `translateY(-6px)→0`；toast：`opacity` + `translateX(8px)→0`；
* 列表项插入：`opacity` + `translateY(-4px)→0`；
* 抽屉（侧栏 / 工作面板）：侧栏 = 宽度驱动（`flex-basis` 宽 0↔`--lw-sidebar-w`， 实现 §2.3）；**工作面板与侧栏统一（v3.9，issue #2）= 同样宽度驱动**——挂载过渡 `width 0→预算 + opacity`，开 `--dur-base`/`--ease-out`、收 `--dur-fast`/`--ease-in` （`!important` 压过内联宽度；拖宽与视口变化不动画——transition 只挂在 enter/leave-active 上）。

**③ 退场** —— `--dur-fast` + `--ease-in`，**比入场快一档且用加速曲线**：退场是"我知道了"， 拖它就是拖用户。浮层退场 = 入场反向且**距离减半**（`scale(1)→.98`），不做对称的"慢慢缩回去"。

**④ 展开 / 收起（滑动 + 缓冲，本次新增）**：

* **高度驱动**：外层 `display: grid; grid-template-rows: 0fr → 1fr`、内层 `min-height: 0; overflow: hidden`；或由 JS 量出的 `scrollHeight` 驱动 `height`。 **禁止 `max-height: 9999px` 这类写法**——它让时长变成随机值（行越多越慢）；
* **展开**：高度 `--dur-base` + `--ease-slide`；内容 `opacity 0→1` **延后 40ms**—— 高度先起、内容后显，视觉上是"滑出来"而不是"撑开"；
* **收起**：高度 `--dur-fast` + `--ease-in`；`opacity 1→0` **不延后**（内容先淡、空间随后收）；
* **嵌套折叠**：一次操作**只动被操作的那一层**，其内部子单元 `transition: none`—— 否则一次收两层会变成"果冻"；
* **动画结束后移除 `overflow: hidden`**（否则聚焦环、阴影、绝对定位的浮层会被裁掉）；**收起开始时必须立即恢复 `overflow: hidden`**（v4.17 实抓：摘除态若带进收起后，0fr 盒高 0 但内容仍以 `opacity: 0` 参与命中测试 = 一张压在后续内容上的**透明点击盾**，表现为"必须先展开上面的组才能点到下面的组"；防御层 = 收起态展开体一律 `pointer-events: none`——不可见的内容永远不拦点击）；
* 动画期间不抢焦点；键盘触发的展开，**动画完成后**把焦点移入展开体第一项。

**⑤ 滑动指示器（胶囊 / 分段控件 / 页签，本次新增）**：

* 活动指示器 = 绝对定位的圆角块，**只动 `transform: translateX()` 与 `width`**——不动 `left`（那会触发重排），不动 `background`（那是突变）；
* 时长 `--dur-base`、缓动 `--ease-slide`；
* **首次挂载不播**（指示器直接落在正确位置），只在"选中项变化"时播；
* **连按不排队**：`transform` 天然从当前计算值继续，快速连按表现为"追着停下"， 不需要特殊处理；
* 指示器需要跨行时（页签条换行）**不播、直接跳**——滑过第二行会穿过文字。

**⑥ 进度与数值** —— `--dur-base` + `--ease-standard`：进度条宽度、用量环弧长。 **数字本身不插值**（跳字比滚动数字更好读）。

**⑦ 一次性强调（只播一次，禁止循环）** —— `--dur-slow` + `--ease-out`：**只用于需要用户决策 的元素**（审批卡入场时染底从该风险档的 10% 落到 7%）。这是把视线拉过去的唯一手段—— 不闪、不响、不弹。

**⑧ 运行指示点**（保留原例外条款）—— 4px 脉动点，`opacity .35 ↔ 1`，1s 无限： **唯一允许的常驻动画**。理由：它是"还在跑"的唯一信号，且只在真的有任务在跑时存在。

**三、显式禁止**

视差 · 回弹 / 过冲 · **整页横滑**（桌面没有返回手势，横滑会暗示"可以滑动"，是假承诺）· hover 位移（列表里会造成抖动，只允许变色）· chevron 旋转（只换字形）· 逐字打字机 · 骨架以外的装饰动画 · **全局 `transition: all`**（会与 hover 过渡互相打架，还会掩盖漏写的过渡）· 主题切换时给 `\\\\\\\\\\\\\\\*` 挂全局过渡（同样打架；主题切换只让根容器的底色与文字过渡一次 `--dur-base`）。

**四、焦点与滚动**

焦点环**不做过渡**（延迟会让人以为没聚焦）；滚动一律跟手（`scroll-behavior: auto`）， 只有"跳回最新"用一次 `--dur-slow` 平滑。

**五、无障碍（reduced motion）**

`prefers-reduced-motion: reduce` 时：所有 `transition-duration` / `animation-duration` 归 `0.01ms`，`scroll-behavior: auto`；**脉动点与一次性强调整块不显示**（`animation: none`）—— 而不是"变成 0.01ms 的无限闪烁"（那反而更刺眼）。

### 6.7 焦点环与滚动条

* **焦点环**：`:focus-visible { outline: 1.5px solid color-mix(in oklab, var(--lw-focus) 80%, transparent); outline-offset: 2px }`；字段类控件（填色会变）改用软环 `box-shadow: 0 0 0 2px color-mix(accent 22%, transparent)`。
* **滚动条**：10px，拇指**静止时透明**；仅当所属区域 hover / 含焦点 / 带 `data-scrolling="true"`（滚动中短暂置位）时显形， `color-mix(in oklab, var(--lw-ink-1) 16%, transparent)` + `background-clip: content-box`
  * 3px 透明边框；拇指自身 hover → 28%。滚动容器一律 `scrollbar-gutter: stable` （**副作用：正文列会比 composer 列左偏约 5px，属预期，不做魔法补偿**）。

## 七、扩展规则（功能性批次照做）

 1. **新数据** → 新 store 或既有 store 加字段；事件进 §4.1 表、命令进 §4.2 表。
 2. **新页面** → 先过 §2.4 判据（是否值得成为目的地；不是就进设置或行内）；集合类一律 §3.1 列表页模式起手。
 3. **新交互** → 先过 §五弹层规则（能行内的不 popover，能 popover 的不 modal）； 新徽章 → 进 §3.4 对应族。
 4. **settings.json 新分区** → §3.2 表加行，占位同批替换。
 5. **改壳骨架（§二）或模式组件本身** → 视为规则变更，**先改本文件再动码**。
 6. **新颜色** → 平面内只许 §6.1 的表面/wash/ink/line 角色 token；状态色只许 §3.4 五族 的语义角色类（`text-ok` / `bg-danger/16` 等）。**组件层禁止出现 Tailwind 的 `neutral-\\\\\\\\\\\\\\\*` 与任意 `hue-shade` 类**——§6.1 的 38 阶 hue 重映射表随本次改造**收缩到 语义色**。原型里新增的橙色标签 tint 走 `--lw-warn`。
 7. **新动效** → 只许 §6.6 的清单；新入场形态先改 §6.6 再实现。
 8. **原生系统对话框**（目录 / 文件选择）统一由 Rust command 封装（`pick_directory`）， tauri-plugin-dialog 仅 Rust 侧调用，前端零新增插件依赖。
 9. **新增 theme token 必须两形齐给**（hex + rgb 三元组，§6.2），并同步亮色块。
10. **视觉与交互先在 `docs/design/ui-prototype/` 迭代**，定稿后再落 Vue；原型不得引入 构建步骤或外部依赖。
11. **文案一律走 i18n**（`t()`）：zh / en 同批加键；**工具名与动作名也走 i18n**——§3.18 的 映射是 i18n key，不是硬编码中文。会话内容不是文案（§3.3 纪律照旧）。 **i18n 文案里的 vue-i18n 保留字符必须转义**：`@`（linked 语法）、`|`（复数分隔）、 `{}`（插值）写成 `{'@'}` / `{'|'}` / `{'{'}`——裸写会编译崩或被吞（㉕ 白屏、㉕·fix shellHint 被竖线劈成复数只显示"log"，两例同源）。
12. **无障碍基线**：图标按钮必有 `aria-label`；可折叠项必有 `aria-expanded`；modal 用 `role="dialog"` + `aria-modal`、菜单用 `role="menu"`、决策卡用 `role="region"`； `Esc` 关浮层栈顶；焦点环恒可见（`:focus-visible`，§6.7；**v3.6 用户裁定豁免： 字段类控件（文本/数值输入与下拉触发）聚焦不出环**，按钮/行类键盘环照旧）； **不许用纯颜色传达状态**（状态点必须配文案或 `aria-label`）。
13. **不许新增受控字面量**：字号 / 字重 / 行高 / 字距 / 圆角只能取 §6.5 / §6.3 的阶梯； 颜色只能取 §6.1 的角色 token；间距只能取 §6.4 的档位；控件尺寸只能取 §6.4 的三个常量。
14. **本文与原型的关系**：原型是抽样演示，**规范以本文件为准**——原型没做到、做不细的形态， 只要写在本文里就是必须实现的（用户 2026-10-01 裁定）。
15. **设置页抛光确立的细节规范全局适用（用户 2026-10-02 裁定"举一反三"）**：明暗两主题 双形态 token（规则 9）、字号/字重取 §6.5 阶梯、**可高亮行与行之间 2px 垂直间隙** （§3.31 导航轨先例——高亮瓦片不得粘连，侧栏会话行/列表行卡/面板页签同规）、浮层与 锚点/视口的间距计算（§五）、控件尺寸三常量（§6.4）——同一特性在任何页面只许有一套 实现，设置页定过的值就是全局值；新页面走查按同一清单对表。
16. **可配置原则（用户 2026-10-03 裁定，全局两条同源）**：①**数值**——凡需要数值设定且 存在不确定性的参数，一律进设置页成为可调项，不为用户做死限定（给合理缺省值）； ②**禁止项**——所有界面上写死的禁止/限制都要有开关可打开或关闭（含最危险的动作）， 开发相关与危险相关的开关/数值统一收进默认隐藏的「开发者」分区（§3.2，侧栏版本号 连点 7 次解锁）。可控项分「用户」「开发者」两层各归其位；新批次涉及即随批落开关， 不积压。
