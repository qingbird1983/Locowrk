# 记忆树看板设计（Memory Tree Board）v1.1

> **状态：待研究。本文是记忆面板的重构设计 + 无限画布看板的交互规格，不是已实施设计，别照它写码。**
> 立稿依据：用户 2026-10-11 需求——①记忆面板「现在整个是混合在一起的，查看很不方便」；②顶部下拉选项目；③项目下按日期列出每条会话；④点会话出「类似无限画布的看板」展示该会话所有总结；⑤总结展开标题 → 标题展开章节 → **全部展开后所有章节汇聚成完整会话流**（用户手绘草图定形：左总结、中标题×章节两列、最右一整块汇聚面板）；⑥看板**只查看不编辑**；⑦项目移除后记忆树跟着移除；⑧项目处一键进入缓存记忆目录；⑨先出 HTML 原型。
> **v1.1（同日走查反馈修订）**：ⓐ 层级终点改为「完整会话流」——一整块按事件序汇集该轮全部章节原文的面板，不是散在每张章节卡里；ⓑ **产品形态优先**：前端不为现役代码的半成品状态打折，代码喂不出的形态（会话流读取）列为后端必改项（§2.3）；ⓒ 外壳对齐现役 UI：左栏到顶深色 / 画布到顶浅色，**无上栏分色条、无发丝线分隔**；ⓓ 画布加**暗网格点阵底**（随画布平移缩放），防展开后卡片视觉发糊发乱。
> **v1.2（同日二次走查修订）**：ⓐ **原型地位裁定：原型只能作为实现 UI 的参考**——真实实施时禁止把原型里的演示性内容与已知错误搬进生产码。明确禁搬清单：**明暗主题按钮**（真实界面不放，设置页已有该能力，重复入口判错）；mock 数据、toast 演示文案、写死的日期分组同样只是演示件。ⓑ 左栏**底部补「返回主界面」按钮**——记忆页有入口必须有出口。ⓒ 修会话流**预显 bug**：点开总结时汇聚面板不得立刻出现，**该组全部标题与章节都展开后才汇聚出现**（逐层展开纪律，§3.2）。
> 配套原型：`docs/design/ui-prototype/memory-board.html`（v1.2，静态无构建，复用 `css/tokens.css`；**地位 = UI 参考，不是实现合同**，禁搬清单见上）。

## §0 与现役裁定的一个冲突点（需要用户拍板）

**项目移除的级联语义**。现状（v2.113 裁定，`ProjectGroup.vue:70`）：「移除项目 = 从 fsRoots 摘除」，**会话与记忆数据一律不动**，重新添加同目录整组恢复。用户要求「项目移除后记忆树跟着移除」= 破坏性级联，与 v2.113 相抵。

**调和方案（本稿推荐，原型按此演示）**：移除确认弹窗增加勾选项——

> ☐ 同时删除该项目的记忆数据（记忆树 + 项目事实层，**不可恢复**）

- 默认**不勾** = 保持 v2.113 非破坏语义（摘 fsRoots，数据原地保留）；
- 勾选后确认 = 级联删除 `<data-root>/memory-tree/<scope_dir(workspace)>/` 与 `<data-root>/memory/projects/<project_dir_name(workspace)>/` 两个目录（目录名算法已有碰撞安全测试，`storage.rs:261` / `memlayout/tests.rs:17`）。
- 无论勾不勾，**面板立即看不见该项目**：项目下拉数据源锚定 fsRoots（§4），摘除即消失——「跟着移除」在查看面上即时成立，数据是否物理删除交给用户勾选。
- ⚠ 符合仓库纪律「删除等高风险操作先向用户确认」；默认不勾保底，不悄悄删数据。

〔**落地注记（v2.208 · 提交 `8299622`，2026-10-17）——本格按用户裁定未开工，原话不擦，但三条实测要写在这里**：①**「一次性删两目录、幂等」在现役纪律下等于什么都没删**——`desktop/src-tauri/src/memory_reconcile.rs` 的判定矩阵明写「scope 目录整体缺席 = 复位手势 → **不删行**」，而首启导出 `run_initial_export` 按 `memories` sqlite 索引**补写文件** ⇒ 只删目录不动行 = 下次启动这两层被原样写回来（现役用例 `deleted_file_removes_row_but_missing_dir_keeps_rows` 就是这条纪律的见证，**不是待修 bug**）。②**真实状态面是四处而不是两处**：`memories` 行（机器真源）· 事实层目录 · `.sync` 标记子树（与事实层**不同父**，实盘 10 个孤儿候选）· 树投影目录。③**「不可恢复」这句措辞在现役形状下不成立**：投影可丢可重建、会话日志一条不删 ⇒ 重新整理会再长出一棵同样的树。三条连同「未归属在三层里名字不同（事实 `global/` · tree.md `_unaffiliated/` · 投影 `_root/`）」一起登记进队列 §5 表尾，作为**记忆/上下文重构的输入**（用户 2026-10-17 裁定见队列 §1 R4）。〕

**开放点（记档，不在本稿裁决）**：删除单条会话时树投影是否跟随删除——树是投影可重建（树 v2 §1.3），现状删除会话不动投影；本稿维持现状。

## §1 产品形态优先（v1.1 立原则）

**前端定义完整产品，代码为产品让路。** 现役记忆树代码是「事实库列表 + 会话档章节列表」的半成品查看面，本稿不迁就它的形态边界；现役投影喂不出的数据（§2.3 会话流）立为后端必改项。反过来说：现役投影已经有的数据（总结链、章节捆、原文切片、更新时间）看板**全部消费**，不发明平行存储。

## §2 数据对位与后端缺口

### 2.1 看板五层与现役投影的对应（90% 零新存储）

| 看板层 | 数据源 | 说明 |
|---|---|---|
| 会话（左栏行） | `TreeSummaryView`（`view.rs:15`：workspace / session_id / **updated_ms** / chapter_count / pending / paused_auto） | 按日期分组零后端改动；标题取 chat store，缺席回退 id 前缀 |
| 总结（画布第 1 列） | `RunSummaryView`（`view.rs:43`：text / event_from / event_to / created_at） | 每次整理收束的浓缩叙事；**画布最左列，全部默认可见**（用户草图：总结是唯一的树根） |
| 标题（第 2 列） | `MemoryChapter.title`（L0，≤40 字） | 点总结展开；归组 = 章节 `event_range` ⊆ 总结 `[from, to]`（推荐 view.rs 返回 chapter_ids，前端区间包含做兜底） |
| 章节（第 3 列） | `MemoryChapter.summary`（L1）+ 来源/手动徽章 | 点标题展开；章节卡是信息卡，**原文不在卡内展开**（v1.0 的做法废弃） |
| 完整会话流（第 4 列） | **新命令，见 2.3** | 一整块按事件序汇集的原文面板 |

### 2.2 边界情形（设计定死）

1. **孤儿章节**（区间不落任何总结：规则切分降级轮）→ 挂「未归总结」虚拟组，样式弱化，行为与普通组一致。
2. **占位章节**（`pending: true`）→ 标题列显示「整理中…」桩，不可再展开；会话流不含它（未定稿）。
3. **未整理尾巴**（`chaptered_until` 之后）→ 会话标签浮层里一行计数，不进画布。
4. **无总结会话** → 「未归总结」组兜底，画布不空。

### 2.3 后端必改项：会话流读取命令（现役缺）

现役只有**按章节**取原文（`memory_tree_original(session, workspace, chapter_id)`，`view.rs:254`），没有**按总结轮次取整段汇合流**的读取。补：

```
memory_tree_stream(session_id, workspace, group) -> StreamView
  group: 总结 id（RunSummary from:to）| "orphan"
  StreamView {
    sections: [ { chapter_id, title, source, edited, from, to,
                  rows: [ {index, kind, text} ] } ],   // 按章节 event_range 升序 = 事件序
    from, to, total_rows
  }
```

实现 = 现役 `tree_original` 的切片逻辑按区间循环拼装（后端拼装而非前端循环调 N 次命令：一次 IPC、原子视图、行号全局连续）。**落码时若 tree_original 内部可复用则抽公共函数**；这是本设计唯一实质后端新增，其余全是薄壳（§6）。

> **落地注记（队列 Q14 第二刀 · 2026-10-15 · 施工提交，版本号随本格收口一次性落，哈希看队列 Q14 行）**：命令已落 =
> `desktop/src-tauri/src/organize/stream_view.rs` 的 `tree_stream` + `memory_tree_stream`（`commands/organize.rs`
> 薄适配）。与本稿字面不同的三处定性，都是落码时判出来的、不是漂移：① **组键没有独立 id**——
> `RunSummary` 的真身就是整理区间，所以 group 直接用 `"from:to"`（`"orphan"` 是未归总结虚拟组）；
> ② **本会话总结链里查无此区间 = 拒**而不是给空面板——前端只会拿到 `memory_tree_chapters` 给过的键，
> 凑出一个不存在的是调用方 bug，演成空态等于把 bug 藏进空状态；③ **小节多一个 `error` 字段**，
> 那是 §3.3「某章节切片加载失败 → 该小节行内错误文案」的兑现，同时把「读不到」与「这一节没有内容」
> 分开（越界节 `rows` 为空 + `error` 在场）。抽公共函数那一半落成两处单点：切片口径 `rows_between`
> 同管单章与整组、未定稿过滤 `settled` 一处定义三处调用；`chapter_ids` 由 `chapters_in` 在后端算，
> 前端**不再按区间反查**（同一属性只许一个出处）。机器判据 = `tmp/q14b-shape.mjs`（含 Rust↔TS 字段
> 逐条对账，防「类型全绿而运行时 undefined」）与 `tmp/q14b-mutate.py`（七靶，含一条撤掉事件序排序的
> 窄靶——正常投影 id 序与事件序同序，只有倒序入树的用例抓得到它）。

## §3 交互规格（v1.1）

### 3.1 外壳——对齐现役 UI 骨架

```
┌─────────────┬────────────────────────────────────────────┐
│ 深色左栏     │  浅色画布区（到顶，无上栏、无发丝线）          │
│ （到顶）     │                                            │
│ 项目下拉 ▾  │   ◌ 网格点阵底（随画布平移缩放）               │
│ [打开记忆   │                                            │
│  目录]      │  [总结]─[标题]─[章节]─┬─[完整会话流]          │
│             │   （第1列）(第2列) (第3列)│  （第4列·汇聚）      │
│ ▾ 今天      │        ←——— 汇聚边—————┘                  │
│   ├ 会话 A  │                                            │
│   └ 会话 B  │            右下角：−/100%/＋/⤢适应           │
│ ▾ 昨天 …    │            左下角：会话标签浮层（标题·日期·尾巴）│
│             │                                            │
│ [返回主界面] │   ← 左栏底部，出口与入口成对                  │
└─────────────┴────────────────────────────────────────────┘
```

- **左栏**（~280px，`--lw-bg-side`，**贯穿到窗口顶**）：项目下拉（锚定 fsRoots，末位「未归属」仅当 `_root` scope 有投影；默认选中当前会话所属项目）+「打开记忆目录」一枚幽灵按钮 + 按日期分组的会话列表（今天 / 昨天 / 本周 / 更早；行 = 标题 + `N 总结 · N 章节` + 「整理中」徽章）+ **底部「返回主界面」按钮**（回到对话主视图——有入口必须有出口；真实实现**不放主题切换按钮**，明暗主题在设置页已有，重复入口判错）。栏内**不用发丝线分区**，用间距。
- **画布区**（`--lw-bg`，**到顶**）：**没有**上栏标题带、没有颜色分色、没有 `border-bottom` 发丝线——记忆页不是「顶栏 + 内容」骨架，是「左栏 + 画布」双栏骨架，与现役对话/设置页同构。
- **暗网格点阵底**（v1.1 新增）：画布世界层铺 `radial-gradient` 点阵（1px 点、~22px 间距，色 = `--lw-line-strong`），**随世界层一起平移缩放**（网格是世界的一部分，不是视口贴纸）——展开大面积卡片后仍能感知位移与层级，防「看疲脑」。
- 会话标签浮层（画布左下）：当前会话标题 + 日期 + 「未整理 N 条消息」尾计数，只读信息，非节点。

### 3.2 画布节点与展开链（用户草图定形）

四列横向脑图，**列 x 基线恒定**（展开不横推兄弟子树）：

| 列 | 节点 | 默认态 | 点击行为 |
|---|---|---|---|
| 1 总结 | 每轮总结一卡（全部默认可见） | 可见 | 展开/收起其标题子列 |
| 2 标题 | 窄条节点 | 收起 | 展开/收起其章节子列 |
| 3 章节 | 信息卡（L1 摘要 + 来源/手动徽章 + 事件区间） | 收起 | **定位会话**：滚动到该章在会话流中的小节 + 高亮闪烁（会话流未汇聚时给出「展开全部标题后汇集」提示） |
| 4 会话流 | **一整块高面板**（每展开的总结组一块） | **该组全部标题与章节都展开后才出现**（逐层展开，不预显） | 内部可滚动；小节头 = 章节标题 + 徽章，正文 = 原文切片行（用户/助手/工具分样式） |

- **逐层展开纪律（v1.2 修 bug 定死）**：点开总结**只**出现标题列；点开某标题**只**出现其章节卡；该总结组下**全部**非占位章节的标题都展开后，完整会话流才汇聚出现——任何一层未展开完，流面板不得提前现身（原型 v1.1 曾在点开总结时立即显示流面板 = 已修的预显 bug，**实施禁止照搬**）。收起任一标题，流面板随即收起。
- **汇聚语义**：会话流高度 = 该总结子树的纵向跨度（草图中右侧大盒），章节卡各有一条贝塞尔边**汇入**流面板左缘——「所有标题和章节展开后汇集为完整会话流」的直接可视化。
- **只读裁定**：全画布零编辑零删除零输入框；编辑留在 TreeSection（现状不动，合并再议）。点击语义只有展开/收起/定位三种。
- **连线**：SVG 三次贝塞尔、1px `--lw-line`（结构线非盒边框）；展开动画 = 150ms `--lw-ease-out` 的 opacity+transform（静态过渡，不触持续动画白名单）。
- **节点视觉**：全 `--lw-*` 令牌；层级靠左边色条浓度 + 字号递减（fs-ui-base → xs）区分，不用彩色分类；圆角嵌套降档（节点 `r-xs`、卡内 `r-2xs`）；来源徽章 = 中性 wash（记忆管理器）/ warn（规则切分、占位）。

### 3.3 状态与空态

项目无投影 → 画布区空态「该项目还没有整理过的会话」+ 指路 `/整理`；无总结会话 → 未归组兜底；会话流某章节切片加载失败 → 该小节行内错误文案；切会话重置展开态与视口并自动「适应」一次。

## §4 项目关联与生命周期

1. **关联事实**：树投影天然按项目分 scope（`memory-tree/<scope_dir(workspace)>/`，路径有损编码 + fnv1a 短哈希，`storage.rs:31`）；项目下拉锚定 fsRoots——移除项目（摘 fsRoots）后面板**即刻**不再显示。
2. **级联删除（可选勾选）**：见 §0。后端新增 `project_purge_memory(workspace)` 一次性删两目录，幂等（目录不存在 = 成功）；前端挂移除确认弹窗勾选项。〔**落地注记（v2.208）**：⏭ 本格按用户裁定未开工（队列 §1 R4）。两条实测要写在这里：①"删两目录"不足以保证删掉（§0 注记①②③）；②**现役根本没有"移除确认弹窗"**——`ProjectGroup.vue` 点一下就把项目从 fsRoots 摘掉，而带勾选的 Modal 只有 `ConfirmDialog.vue` 一个合法形态 ⇒ §6 表里这一行的真实工作量是「新建确认通路 + 扩展那一个组件」，不是 **S**。〕
3. **重加同目录**：不勾 = 整组恢复（现状语义保持）；勾选删除后重加 = 从零开始（如实）。

## §7 前端形态特例申请

无限画布 + 脑图连线 + 汇聚面板**不在**《Front-end Design Guidelines》15 类形态清单内——本文即申请书：**是什么**（记忆树只读导航画布：四列节点 + SVG 连线 + 一块滚动汇聚面板）；**在哪**（记忆页「记忆树」页签主区，左栏到顶深色 / 画布到顶浅色双栏骨架）；**为什么**（总结→标题→章节→会话流的父子导航在线性列表中无法同屏呈现；汇聚面板是用户草图明确的终点形态）；**影响**（新增画布容器 / 节点 / 连线 / 网格底四类构件 + pan/zoom/定位三种交互；字号圆角间距全走既有令牌、无彩色分类、无持续动画，不违反任何现存红线）。**获批后先修订标准再写码。**

> **落地注记（v2.206 · 队列 Q13 · 2026-10-15）**：申请已获批准（用户 2026-10-11 裁定 R2 =「特例视为已批准」），"先修订标准"那一刀已落 = 下位《Front-end Design Guidelines》**§二⑯「无限画布看板」（文档升 v2.2）** + 上位《UI Design System》§八新增「画布与节点」（文档升 v1.1）。**写画布代码时以 §二⑯ 为准，不照本稿 §3 抄**——批准过程按上位效力链与两道闸的实测改了七处，逐条列在 §二⑯ 末尾「订正清单」，本稿原文一律不擦。其中三件与本稿定性不同、必须知道：①节点圆角从 `r-xs` 抬到 **`r-md`**（画布属布局区不计档 ⇒ 节点是第一个圆角容器）；②节点**带 `--lw-line-subtle` 围边**且 hover 只走全站那张状态表（本稿 §3.2 写的"无边框"与原型写的"hover 变描边"都不采纳）；③连线条与网格底**同用 `--lw-line-strong`**（本稿 §3.2 的 `--lw-line` 在暗底上几乎不可见，原型自己就没用它）。
