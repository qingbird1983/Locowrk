# 设计：Phase 6 技能发现、信任与注入

- 状态：定稿
- 日期：2026-10-28
- 关联：architecture/05；research/02 §1；[extensions.md](extensions.md)；standards/06

## 1. 目标与非目标

**目标**：复用内核已有的 Agent Skills 发现/校验/注入；用户技能自动可用，项目技能必须显式信任；技能名称、描述、来源与诊断在桌面可见；撤销信任后新会话不再注入。

**不做**：技能编辑器、技能市场、远程安装、项目级 `.agents/skills`（上游不在此路径发现）、修改技能文件、把完整系统提示词展示给用户。

## 2. 发现来源（与 `pi/coding/resources.go` 一致）

| 来源 | 路径 | 条件 |
|---|---|---|
| 用户 pi | `~/.pi/agent/skills` | 总是 |
| 用户 AGENTS | `~/.agents/skills` | 总是；只补充不覆盖同名 |
| 项目 | `<cwd>/.pi/skills` | 工作区已信任 |

- 只认 `SKILL.md` 与其 frontmatter；名称/描述长度、非法字符、重名按内核校验。
- 用户目录优先；项目重名不覆盖，产生诊断。
- 不扫描 `<cwd>/.agents/skills`（上游不加载，避免绕过信任边界）。
- `HOME` 不可用时没有用户目录，不回退到相对路径（内核已处理）。

## 3. 信任模型

- **用户技能**：视为用户自己的资源，自动加载；状态面板仍列出名称/路径。
- **项目技能**：`SKILL.md` 的名称与描述会进入系统提示词，等同项目作者影响模型；默认不加载。
- 首次打开/新建会话时，若项目存在技能且未信任：
  - 原生确认框列出：工作区路径、技能数量、最多 5 个名称、诊断数量；
  - 选择“信任此工作区” → 写 `projectTrust[<canonical cwd>]` 与时间；本会话与后续会话生效；
  - 选择“暂不” → 只加载用户技能，状态面板显示“项目技能未信任”，可稍后信任；
  - 关闭窗口/取消不写设置。
- 撤销信任：设置中移除路径；**当前会话保持**（系统提示词已注入），下一次新建/恢复会话不再加载；状态面板明确提示“下次会话生效”。
- 项目扩展信任与技能信任分开：信任工作区只解锁技能发现，不自动信任 `.pi/extensions`。

## 4. 内核与门面

```go
// kernel
type SkillInfo struct {
    Name, Description, Path, BaseDir string
    Source string // user|project
    Disabled bool
}
type SkillDiagnostic struct { Type, Message, Path string }
func (s *Service) Skills(cwd string, projectTrusted bool) ([]SkillInfo, []SkillDiagnostic)
```

- 内部直接调用 `coding.LoadSkillsWithTrust(cwd, projectTrusted)`；不复制发现逻辑。
- `SessionOptions/OpenOptions.TrustProject` 在创建/恢复会话时传入；恢复旧会话同样使用当前信任状态。
- bridge 只暴露 DTO：`Skills(cwd) SkillsView`，包含 `trusted`、`user[]`、`project[]`、`diagnostics[]`、`injectedAt`。
- 系统提示词注入仍由内核完成；桌面不拼提示词、不读技能正文（除非用户点“查看”，只读展示路径与描述）。

## 5. UI

- **扩展状态面板**（与 A 轨共用）增加“技能”段：
  - 项目信任状态与按钮（信任/撤销）；
  - 用户/项目技能列表：名称、一句描述、来源；诊断用危险色；
  - “查看技能文件”用系统默认程序打开（只读，不内嵌编辑器）；
  - “本会话已注入 N 个技能”只显示数量与名称，不展示完整提示词。
- 首次信任确认框由原生层绘制，必须在页面之上；不在 WebView 内做模态。
- 撤销信任不弹二次确认以外的窗口；说明“下次会话生效”。

## 6. 设置

```json
"projectTrust": {"<abs cwd>": "2026-10-28T…"},
"projects": {"<abs cwd>": {"skills": ["name-a", "name-b"], "diagnostics": 1}}
```

- `projectTrust` 是唯一生效依据；`projects` 只是上次发现的缓存，缺失时重新扫描。
- 路径用规范化绝对路径；不做 glob/父目录继承（避免信任一个仓库顺带信任子目录）。
- 设置损坏按既有规则回退默认；不因信任读取失败而静默加载项目技能（fail-closed）。

## 7. 验收

1. 临时 HOME 放一个用户技能：新会话自动可用，状态面板可见。
2. 临时工作区放 `.pi/skills`：未信任时列表为空/只读提示，模型请求不含项目技能。
3. 信任后：技能出现；系统提示词包含名称/描述（用内核测试或调试接口断言，不靠模型回答）。
4. 撤销后：当前会话不变，新建会话不再包含。
5. 非法 frontmatter、重名、超长描述：诊断可见，其他技能仍加载。
6. 项目技能路径逃逸/符号链接：按内核规则拒绝并诊断；不读取工作区外文件。
7. 回归：用户技能在扩展未启用/扩展崩溃时仍正常。

## 8. 风险与待决

- **信任粒度**：Phase 6 按工作区路径；不做按技能逐个信任（上游也没有）。信任提示必须列清名称。
- **当前会话不可撤销**：系统提示词已发送给模型；撤销只影响后续会话，文案必须说清。
- **用户技能自动加载**：用户目录等同于用户授权；仍显示来源，便于排查。
- **模型侧效果**：自动化只能断言注入列表/系统提示词，模型是否“使用”技能留人工或真实 provider 冒烟。
- **与 A 轨扩展的边界**：扩展读取技能文件要经自身 Node 能力；宿主不额外授予文件权限。
