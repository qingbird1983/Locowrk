## §3 排序依据（三条硬判据，顺序由它们推出，不是凭感觉）

1. **基线时效窗口（最硬）**：改排序之前必须先有排序的观测面。
   ML §2.2 自陈 L1–L4 全是改排序，改完**无法证明变好**；§5.5 的 A/B 靠比对
   `memory_inject_log` 的注入 key 集合做差。M1/M2 一落地注入内容就变，before 那半边永久丢失，
   判断只能退回体感——这正是 v2.73 落地 autoExtract、后来以"实践确认无作用"退役那次的成因
   （ML §2.2 点名的是它）。所以 **L0 → 第一刀**。L0 不破坏下一条窗口：它只在 `usage.sqlite3`
   旁挂新表（ML §2.3(e) 明写不新建库），一行不写 `memories`。
2. **0 行红利窗口**：MR §6 要求「趁 `memories` 表 0 行时做 workspace 键位归一化，零成本」。
   2026-10-12 实测确认窗口仍在：`~/.Locowrk/memory.sqlite3` 的 `memories` 表 **0 行**，
   `memory/projects/` 下四个项目目录（Glance-main / Locowrk / TITY / Timo）的 `facts/` **全空**、
   `MEMORY.md` 都是空壳（16–17 字节只有一行标题）。M2 一开始写事实卡，同项目双键位
   （Windows 大小写 / 斜杠漂移）就会真的产生脏数据，归一化从"改一行代码"变成"迁用户数据"。
   所以 **归一化必须在 M1 内做掉、且 M1 在 M2 之前**。
3. **解锁数**：CF 的 C1 是 FP §7 依赖要点点名的最大汇聚点（B5 checkpoint、B8 分屏、C1′ steer、
   E3 远控四样全踩它）。一次动数据链路，省掉后面四条各自另起炉灶。所以 **C1 在功能面群里最先**，
   并为此在 Q11 先立前端测试基建（见下）。

12. **「新增一层限制」与「把已有写死值做成可调」是两件事，前者必须由「关掉逐字节回到改前」的判据补偿**（Q8·v2.192 立的口径，补 §6 第 8 条管不到的那一半）：第 8 条要求可调项的缺省等于改前那颗写死值——它的前提是**本来就有一颗常量**。而当一批的交付物是**新建一层此前不存在的闸门**（本批 = 工具结果预算，改前无任何管线级字节预算，CB §4.1 核实过），就没有「改前值」可取，缺省给多少都会改变存量行为。这时候不许含糊地引用第 8 条说「不适用」就过去，必须三件齐：①这层限制是**用户明确要的**（本批 = 2026-10-13「我觉得能否有个限制」），②界面留一条**能完全关掉**的档（0 = 不限制），③该档**逐字节回到改前**由测试钉住（本批 = `tool_result_budget_none_is_byte_identical` 拿 40 万字节输出比字节 + `tool_result_budget_bytes(0) == None`），并把这三件写进 ROADMAP 与 CHANGELOG。缺任何一件，「新增限制」就会伪装成「只是把数值做成可调」。

13. **时机型与结构型纪律只能用源码次序 / 调用存在性判据证明，「行为等价」的功能测试证明不了**（Q8b·v2.193 立的口径，批 Q6 §6 第 10 条「跨文件的关系必须有跨文件判据」的第二个人质）：本批有两类关系天生没有可观察的行为差异。**时机**——`release_pressure` 必须在 `kernel.step_as` **之前**（挪到之后就晚一整步，而晚一步在测试里长得和准没错一样：变异 **M7 正是这么改的，功能测试与 `pnpm build` 全绿**）；**结构**——泄压必须**调用**那个共用装配函数与那个共用纯函数，而不是自己把它们数字重拼一遍（变异 **M9 手工重拼 `TriggerInput` 六格，每一条用例的期望值都逐格等价 ⇒ 零红**）。两种情形的共同点：判据要盯**代码的形状**（源码 index 次序、调用是否存在、禁词不出现在代码面）而不是盯输出。落点 = `tmp/q8b-shapes.mjs` 的 S1（次序）与 S4（调用存在 + 禁自装配）；反向纪律同批 Q7 第⑤条同源——**这类判据必须先剥注释与测试面再判**，否则注释里如实引用「改前的写法」会让禁词判据恒红。凡一批的交付物里含「顺序/接线/共用某函数」这类断言，收口时必须自问：**有没有一条判据在它被改坏时会红？**没有就是没做完，登记为下一刀的第一件事而不是写进注释。
14. **等价判据必须打在「真有内容」的状态上：空串等于空串不算证明**（Q8c·v2.194 立的口径，历批「空转门禁」H1 的那一类，但对象从门禁换到了自己写的用例）：本批最值钱的一条判据是「补写前后注入目录逐字节相同」，第一版把首次组装排在**泄压之前**，那一刻树里还没有章节 ⇒ `before` 是空串，补写之后仍是空串 ⇒ 用例**绿**，而它什么也没证（前缀缓存的字节前提根本没进覆盖面）。暴露它的是我自己加的一句防御性断言（`before` 必须含 `- b1:`）。凡判据形如「X 前后不变 / 相同 / 未被改动」，收口时必须同时回答**被比较的那个东西在这一刻有内容吗**：这类判据应当配一条同面的「非空」断言，否则它可以在实现被完全摘掉的情况下永远绿。同族的第二次兑现 = 变异驱动那条 `cargo test --lib summary` 过滤串打空（`running 0 tests` 却 rc=0 = 假绿，把两条正确靶冤枉成不承重），处置同样不是「补一句措辞检查」而是**加下限**（数 `running N tests` 的 N）。
15. **文档表格行必须闭合，新判据上线的当批就把覆盖面全量跑一遍**（Q8c 结构修复批立的口径）：把带转义序列的长句写进文档时，行尾的闭合竖线会被当成真换行丢掉 ⇒ 表格行断成两截，而**六道结构闸一道都不红**（它们只看代码面），Markdown 里也只表现为那一列显示不齐，所以它能带着两处存量漂过 v2.185 与 v2.189 两批。本批的 F9d 形状判据第一次跑就把这两处抓了出来。⇒ 凡新增一条形状/文本判据，收口时不许只跑在本批改动面上，**对全仓同类对象跑一遍**；抓到的存量要么当场接回（照 `tmp/q8c-splice3.py`：先证「补上闭合之后列数与表头一致且每格非空」再写盘），要么登记为挂账，不许无声略过。**本条上线当批的全量实测**（`tmp/q8c-mdscan.mjs` 扫 `git ls-files -- "*.md"`）= 79 份入库 md · 断行命中 **4 处**：`docs/design/INDEX.md:47` 与 `:74`、`docs/design/NEW/Model Capability and Multimodal Phase Plan.md:154`、`docs/design/NEW/Reliability Reinforcement Design.md:755`。四处**登记挂账**而不在本刀接回：它们不在本批声明的改动面内，接回就等于「顺手重写别的文档」，而那正是改动面判据要抓的形状 ⇒ 落 **Q7c 之前的第一件事**，照 `tmp/q8c-splice3.py` 的三问（全文件扫得清单 → 补闭合后列数与表头一致且每格非空 → 下一行同表完整）逐处接回。〔**Q7c 第一刀已结清（v2.195 续批 · 登记在本批节内 ⑥/⑬）**：4 处逐字接回，全仓 59 份 md 断行读数 **0**，而且这条判据从此住在第七道闸的常驻档里（`DOC_TABLE_BREAKS` + 四个 md 目录的遍历自检 + 窄靶 M8/M9），不再依赖「下一批记得扫」；行尾同时从源头钉死 = `.gitattributes` 的 `*.md text eol=lf`。〕
