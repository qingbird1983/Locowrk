## §0 为什么必须治（成本实测，不是感觉）

| 实测事实 | 数字 | 说明 |
| --- | --- | --- |
| 一版变更（v2.208 收口）实际改动文件 | **10 个**（`git show --stat`） | AGENTS + ROADMAP + CHANGELOG + 队列 + MB 稿 + INDEX + 三份归档 + 台账 |
| 同一个版本号在在役文档里的提及次数 | **11 处 / 6 份文件** | ROADMAP 1 · CHANGELOG 2 · AGENTS 1 · 队列 1 · INDEX 1 · MB 稿 5 |
| 文档总量 | docs/**.md 61 份 · 4.13 MiB | 其中**四份历史件占 2.32 MiB = 53.5%**（CHANGELOG 归档 899KB · ROADMAP 归档 653KB · AUDIT-FIX-PLAN 416KB · AGENTS 归档 352KB） |
| "压行"形态（单行 > 2KB） | **13 份文件**有 · CHANGELOG 归档里 **127 条** · 最大行 **48,838 字节** | 后果三条：读不了（IDE 一行一屏）、diff 不可审（一行改动 = 整段重写）、**只能靠脚本改**（本批 `q15-rotate.py` 24 项自证才敢写盘） |
| CHANGELOG 在役文件 | 38 行装 **84 KB**，v2.208 那一行 **11,467 字节** | 它就是"每批必须写一段万字长行"的根源 |
| AGENTS.md（每个会话的注入源） | 26,872 字节 / 188 行 | 其中"进度三条"占 5,998 字节（22%）——**它是进度，不是规则**，历批为把它压进 6000 预算做过无数轮删字 |
| "判据自纠"计数器 | **8 份文件 · 173 处** | 每批要把累计数逐处 +1；它是"读数被钉进正文"的典型，必然漂 |
| 本批抓到的**失实引用** | 2 处 | ①v2.207 写「登记见台账 T11」，而 T11 是另一件事、该欠账**从未在册**；②两份指针行「本次搬出…（v2.198）」滞后一整批（真搬出的是 v2.199） |
| 本批自己的**判据失手** | 1 处 | 我用正则算"INDEX 漏了几份稿"读出 5 份，实为 0 ——文件名里的 `(ZCode Alignment)` 把 `[^)]+` 截断了。**命名形态能直接打断机器判据** |

结论：现在这套"窗口 + 轮转 + 归档 + 计数器 + 就地注记"是在用**越来越精巧的脚本**维持一个从不符合任何单一职责的文档结构。脚本每加一项自证，收口成本就再涨一截。治的不是文档内容，是**"一件事写几处"这个结构**。

## §3 治本那一刀：新的「每批收口清单」

现在写一版变更 = 14 处。治理后同一件事**只有一个落点**：

| 要记的东西 | 唯一落点 | 形态约束（可判定） |
| --- | --- | --- |
| 这批做完没有、进度到哪 | `docs/design/ROADMAP.md` 排期表那一行 | ⬜/◐/✅ + 版本号 + 提交哈希 + **一句话 ≤200 字节** |
| 为什么这么定 / 否掉了哪条路 | `docs/adr/NNNN-*.md` | 只在**有新决策**时写；「被否决的方案」必填 |
| 用户可感知的变化 | `CHANGELOG.md` | 一版 **≤3 短行**；无用户可见变化就不写（细节不许进来） |
| 实测读数、判据、踩坑、门禁 | **commit message 正文** | 一次提交一件事；细节天然随 git log 走，不进文档 |
| 欠账 / 待办 / 挂账 | 台账一处（`docs/history/reports-AUDIT-FIX-PLAN` 的 T 表）或队列 §5 | 一条一行，**引用只写编号不写内容** |
| 规则本身（拆分/命名/门禁口径） | `AGENTS.md` + `STRUCTURE.md` | 改规则才动它，与批次无关 |
| 判据自纠 / 累计计数 | **取消正文计数器**，改为一篇 ADR《判据纪律》+ commit 里写本批第几条 | 累计数 = 从 git log 现算，不写进文档 |

配套要撤的三件仪式（它们是成本的直接来源）：

1. **AGENTS 进度三条轮转 + 6000 字节预算 + 自指不动点** —— 整体删除（AGENTS 不再装进度）。
2. **ROADMAP/CHANGELOG 各 8 批窗口 + 归档搬出脚本** —— 取消窗口滚动；历史写完就静止，新批只写 commit。
3. **设计稿"就地落地注记"** —— 不再往稿里追加注记；稿的状态改由 `STRUCTURE.md` 一行标（已兑现/现役/存档）。

`scripts/check-doc-budget.mjs` 随之**重写**（它现在管的三条判据在新结构下都不成立）：新判据 = ①AGENTS ≤120 行 ②ROADMAP 一格一行且行 ≤200B ③ADR 只增不改（新文件必须 `docs/adr/NNNN-`）④STRUCTURE 覆盖全部 md（漏一份判红）⑤压行上限（单行 >4KB 判红，防"万字长行"回来）。

## §6 风险与回滚

| 风险 | 应对 |
| --- | --- |
| 搬家导致**引用落空**（代码注释、crate lib.rs 的 DESIGN 章节号、闸内路径常量、`.githooks/pre-commit` 暂存面正则） | 每刀都跑 `tmp/docimpact.mjs` 做"指向不存在文件的引用 = 0"这条硬判据；搬迁一律 `git mv` |
| 把 `check-doc-budget` 改成新判据时**改成恒真**（历批第 1 族事故） | 新闸必须带变异自证：故意造一份违反新判据的夹具，闸必须红 |
| AGENTS/DESIGN 是 [LOCK] 性质（规则语义动一处就影响所有会话） | 本计划只搬不改语义；**任何语义改动单独申请**，与搬家分刀 |
| ADR 转写时凭记忆写"当时为什么"，把历史写歪 | 只从 CHANGELOG/队列/台账**原文**摘录，每篇标出处与提交哈希；找不到原文的决策**不写** |
| 治理期间主线（Q17）停摆 | D1+D2 两刀内完成，其余刀可搭车；期间挂账不新增 |

**回滚**：每刀一个提交，`git revert` 单刀即可；D3/D5/D6 的文件移动有 `git log --follow` 与 docimpact 清单双证。
