# Organize Summary Design v1（整理段落总结：断层交接 + 项目跨会话锚点）

> 状态：v1 定稿并随批落地（v2.141）。裁定来源：用户 2026-10-10 口述三轮——
> ①整理时在章节标题之外增加一份「可追溯对话流的浓缩总结」；②总结只在整理
> 触发的下一轮拼进提示词，起断层交接作用，不每轮专门携带；③层级上总结在
> 该轮 N 份章节标题的上层（它是这批章节的浓缩）；④总结兼作项目跨会话的
> 进展记忆锚点。手动 `/整理` 斜杠命令已存在（v2.65），本批核实并让手动档
> 与总结管线天然协同。

## 1. 问题：整理边界上的信息悬崖

整理收束时原始上下文离场（`chaptered_until` 推进），模型只剩 system 目录里的
L0 标题——标题说明「聊过什么」，不说明「聊出了什么结论」。跨度一大，模型对
断层前的世界近乎全盲：要么瞎猜要么连环 expand（多轮工具往返）。

## 2. 设计：四层多分辨率记忆

```
RunSummary（轮级总结,每次整理 1 份）← 常驻（历史消息面）：浓缩/去噪/叙事
 ├─ b1 标题（L0）                  ← 常驻（system 目录）
 │   ├─ L1 摘要                    ← 按需（memory_expand level=1）
 │   └─ L2 原文                    ← 按需（memory_expand level=2）
 ├─ b2 标题
 └─ …（本轮 N 份章节都是这份总结的子节点）
```

- 总结 = 该轮整理区间的跨章节叙事（因果、转折、结论链——L1 逐章拼起来给
  不了的东西），**去除噪音**（重试过程/失败细节/冗长中间输出），**保留信号**
  （决定及理由、状态变化、结论、用户持久性指令引号原文、未决事项）。
  「试过 X 不行」这类有结论的失败是信号不是噪音。
- 分工纪律：持久性偏好的正式居所是 memory_write（v2.136 模型）；总结只负责
  叙事层如实携带。L1 = 章节级事实细节；总结 = 轮级流动叙事。去噪只发生在
  常驻层，L1/L2 无损保留 = 去噪是有安全网的降采样，不是销毁。

## 3. 交付形态：真实历史事件落在断层处（用户裁定②的物理化）

LLM 每轮无状态——「拼一次」若是瞬时碎片（不落日志），知识只活一轮，交接
失效。三种形态裁决：

| 形态 | 交付 | 老化 | 裁决 |
| --- | --- | --- | --- |
| A. 瞬时碎片拼接 | 只活一轮 | 无 | 否（是通知不是交接） |
| B. **落日志成真实事件** | 下一轮起随历史每轮在场 | 被下次整理收编进材料、滚动进新总结 | **采纳** |
| C. 常驻 system 目录 | 永久 | 不老化、线性膨胀 | 否（用户裁定不每轮专门带） |

B 形态的三个直接收益：

1. **前缀缓存零扰动**——总结走消息历史追加面，system 与目录一字不改；
   `prompt_layering` 锁的「目录增长前缀逐字节不变」原样成立。
2. **token 预算自收敛**——占尾巴预算，被 v2.138 真实锚点计账，被下次整理
   收走；不需要任何老化机制。
3. **不重蹈 v2.136 handoff 教训**——handoff 被删因它是「每轮重写的活文档」；
   总结是**封段一次成文的历史记录**（封闭期不可变），与 L1 同一哲学。

### 3.1 滚动收编（链式边界的必然要求）

下一刀的材料区间天然包含上一份总结（它落在上一刀边界之后）。记录员必须
**衔接而非丢弃**：新总结 = 新材料蒸馏 + 上一份总结里仍然相关的状态
（近详远略金字塔，越老的压得越扁）。否则每个新边界把更老段碾压回只剩标题，
交接对「更早的来龙去脉」失效。硬顶尺寸（提示词 ≤500 字 + 系统侧 2400 字符
硬钳）逼真压缩，防总结链越滚越肥。

### 3.2 事件与投影

- 新事件 `SessionEvent::ContextSummary { text }`（serde 零迁移，旧日志无此
  变体读入照常）。text 存**未包裹的总结正文**（语义层）。
- 投影（`project_messages`）= `Message::User`，content =
  `[context summary of earlier organized conversation]\n{text}`——沿用
  ContextCompacted 摘要消息的纯标记先例（session-store 无 system-reminder
  包裹惯例，免转义面）。位置 = 日志中的真实位：**下一刀边界后的第一条尾巴
  消息**（断层缝合处）。
- 材料（`build_items`）新 `MaterialKind::Summary` → 转录行 `[n] 总结: …`，
  记录员据此识别上一份总结并滚动收编；规则切分不以它为切点（非 User）。

### 3.3 交付机制：管道落树、下一轮开场排空

约束：内存 `Session` 是唯一写真源，磁盘 append 必须与内存索引对齐——旁路
整理管道（不持会话锁）**不得**直接写会话日志。因此：

1. 管道收束（recorder ok）时把总结文本落树投影：`MemoryTree.summaries:
   Vec<RunSummary { from, to, text, created_at }>`（serde default 零迁移；
   rule 降级无总结 = 不落 = 退化到今天的行为，宁缺勿假）。
2. **下一轮开场排空**（agent_chat / 调度引擎，持会话锁、先于 `run_turn`）：
   逐条检查 `summaries`，凡日志中 `(r.to, 下一条 r'.to]` 区间内尚无
   ContextSummary 事件的 = 未交付 → `session.append` + `append_slice` 落盘
   + 经 sink 推 `agent://context-summary`（实时与重放同形，v2.134 先例）。
   已交付判定自愈（无跨文件标记，崩溃不会双投）。
3. 常见时序下整理在收束后秒级完成，总结恰落在下一轮开场之前 = 精确的断层
   缝合位；若用户在整理在途时抢先发言，总结顺延到再下一轮开场、位置在
   最新轮之后（晚到但在场，记档边界）。

### 3.4 记录员输出协议

数组契约不动（`parse_drafts` 校验零变化）。总结走**尾随标记段**：

```
[JSON 数组]
===SUMMARY===
（段落总结正文，≤500 字）
```

- `parse_drafts` 内部先按标记切分再取数组（防总结正文里的 `[`/`]` 污染
  `extract_array` 的首尾定位）；`run_summary(raw)` 取标记后正文，trim +
  压行 + 2400 字符硬钳。无标记/空正文 = None（成功无总结，目录照常）。
- 四份家族提示词各按其风格补「段落总结」节：定义（这批章节的浓缩，供后续
  轮次了解来龙去脉）、信号/噪音清单、滚动收编要求、逐字保留纪律、尺寸上限。

### 3.5 观察面（不进 system，不做开关）

- **转录**：`AgentEvent::ContextSummary`（tag `context_summary`）——实时经
  sink 推、重放经 `project_events` 出，前端渲染为淡色系统块（SystemNotice
  同族、可展开）。
- **记忆页**：会话章节清单（TreeChaptersView）带 `summaries`，渲染在章节组
  上方；项目联合视图升 `ProjectTreeView { chapters, summaries }`——跨会话
  按时间正序的总结链 = 项目进展叙事锚点。
- **tree.md**（人读层）：每轮总结以引用块渲染在该轮章节组正上方（字面意义
  的「标题上层」）；reconcile 解析器对小节间杂行天然免疫（cur=None 丢弃），
  人改保护纪律不变。
- **不做设置开关**：自然降级（记录员失败 = 无总结）已覆盖故障面；质量 Iteration
  靠提示词，不加幻影旋钮（v2.136 教训：无用开关即幻影键）。

## 4. 手动触发（用户裁定⑤——已有能力核实归位）

`/整理`（`/organize`）斜杠命令自 v2.65 在位：前端拦截（chat.ts，不建用户
气泡）→ `organize_now` → `plan_manual`——**不经过阈值判定**（`should_auto_
organize` 不参与）、**不受反弹熔断限制且复位熔断态**、随时可触发、尾巴为空
才拒绝（「没有可整理的尾巴」）。本批零改动，手动整理与自动整理同管道，
recorder 档同样产出总结并按 §3.3 交付。

## 5. 已知边界（记档）

1. 抢先发言竞态：总结晚到一轮（位置在最新轮之后），晚到但在场。
2. 回退/fork 截断掉已交付的总结事件后，排空检查判「未交付」会重投一条
   （与树投影仍声称该区间已整理的既有 rewind 语义一致，不另造对账）。
3. 记录员编造风险被常驻放大（每轮在场的权威叙述）——提示词纪律（只用材料
   内信息）+ 结论可下钻验证（expand 对 L1/L2）缓解。
4. `memory_search_titles` 不搜总结正文（只搜标题）；跨会话总结检索走
   项目联合视图与 tree.md（检索扩展记档不立批）。
5. 会话已删后 RunSummary 随投影存在，`to` 指向的日志位失配——排空跳过，
   项目视图照常展示（投影语义）。
