# 唯一正身（authority）

> 这一层放**每个主题现在有效的那一份规范**。判据很简单：**改了代码必须回来同步它的那些文档**，就在这儿。
> 反过来，"打算这么做但还没做"的稿子不放这里（在 [`../`](../)），"已经做完/已被取代"的也不放这里（在 [`../archive/`](../archive/) · ⊘ 这两处不入库，clone 后只有 authority 这一层）。
> 全仓哪一层管什么，看 [`../../../STRUCTURE.md`](../../../STRUCTURE.md)；进度看 [`../../roadmap/`](../../roadmap/)。

## 冲突时谁说了算

三份文档内部也会互相打架，裁决顺序固定，不要临场发挥：

1. **内核与架构**（依赖边界、插件契约、副作用与撤销、会话事件）→ `DESIGN.md` 是唯一需求来源，附录 C 是八条纪律的完整版。
2. **界面层**（令牌、字号相对制、圆角嵌套、动效、暗档）→ `UI Design System.md` 最高；`../UI shell and patterns.md` 是它的**下位细则**，两者冲突以本层这份为准。
3. **前端形态**（同类只许一种形态、特例申请制、豁免凭证）→ `Front-end Design Guidelines.md`。它管"长什么样、怎么写"，与 2 那条管"数值与令牌"并不重复。
4. 其余主题各有一份正身（下表），**同主题不许出现第二份**：想新写一份先并进现有的，并不了就写进 `docs/adr/` 说明为什么必须两份。

## 这一层不放什么

- **不放实现细节与批次记录**：那些进提交正文（`CONTRIBUTING.md` 那张表规定了去处）。
- **不放进度**：进度只在 `../../roadmap/` 一行里，规范文件里不许出现"做没做完"的第二张表。
- **不放已兑现的历史设计稿**：它们在 `../archive/`，那里只读。
- **不放"打算做"的稿子**：它们在 `../`，等到真的成为某主题的正身规范那天再搬进来。
