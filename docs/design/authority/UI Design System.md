## 〇、最高优先级 UI 约束（违反 = 设计系统缺陷，不是风格偏好）

1. **界面字号只用语义档**：`--lw-fs-ui-xl / -lg / -base / -caption / -sm / -xs`（§四）。
   禁止裸 px 字号、禁止 `text-[13px]` 类任意值（现状门禁已管，语义档换血后门禁同步）。
2. **界面字号的可调性只经 `--lw-ui-font-size`**（新令牌，缺省 14px，设置页「外观」→「字号基座」驱动，值域 12–18 = Q14 第四刀 v2.207 落地；⚠ **可调 ≠ 整界面同尺**，存量绝对档未迁移期只对相对档生效，见附录 B 该行）。
   **永不**改 `html` 根字号实现界面缩放；图标、间距、圆角等几何量**不**随字号缩放。
3. **代码 / diff / 终端正文**保留独立字号设置，不受上条约束；但其**周围的控件、标签、
   头部、元信息**仍必须走语义字号档。

## 一、产品性格

Locowrk 是桌面优先（Tauri 2）的 AI 工作台。界面应当**冷静、致密、可操作**，而不是装饰性的。

为以下场景设计：

- 长时间会话（数小时不疲劳）
- 高信息密度（对话流 + 工具输出 + 面板并存）
- 可读的聊天与工具输出
- 键盘驱动的操作流
- 中英双语与可变文本长度（i18n 纪律：不依赖截断活命）
- 亮 / 暗双主题 + 跟随系统

避免：营销式大间距；俏皮渐变作为默认 UI 语言；大面积品牌色铺底；背景 / 卡片 / 浮层
层次含混。

## 二、主题

用户可选：跟随系统 / 亮色 / 暗色。令牌双主题覆盖已建（`:root` 暗色缺省 +
`:root[data-theme='light']`）。**一切新 UI 必须双主题都验**（含极窄窗宽）。

窗口镶边：Windows 用系统原生装饰 + 46px 顶带（`--lw-toolbar-h`）现行方案不变；
本文不引入蓝本的 macOS 红绿灯 / 全页 overlay 窗控条目（平台不适用，有意删减）。

## 三、色彩令牌

### 3.1 核心语义色（ZCode 角色 → Locowrk 令牌映射）

| ZCode 角色 | Locowrk 令牌 | 现状 | 用途 |
|---|---|---|---|
| Brand | `--lw-accent`（+ `-hover` / `-ink`） | 有 | **结构上等同 brand 槽位，取值保持中性墨色**（暗白/亮黑）——性格延续 ZCode 的「brand 克制」且更极简；未来要品牌色时只改值不改规则。用于关键强调、主动指示、主按钮底；**永不全页铺底** |
| Background | `--lw-bg` | 有 | 页面 / 工作区底 |
| Background Alt | `--lw-bg-side` / `--lw-bg-dock` | 有 | 侧栏 / 工作面板等结构性区域专用，**不得当通用卡片色** |
| Surface | `--lw-bg-secondary` / `--lw-raised` | 有 | 低提升容器面 |
| Card | `--lw-wash-1`（叠在 `--lw-bg` 上） | 有 | 标准内容卡底（操作型卡片，见 §八·卡片） |
| Selected / Hover | `--lw-wash-3` / `--lw-wash-2` | 有 | 选中 / 悬停（全站唯一） |
| Popover / Menu | `--lw-bg-elevated` | 有 | 浮层实底（不透明，v3.9 裁定保留） |
| Input | `--lw-wash-2`（井）/ `--lw-raised` | 有 | 可编辑区底；聚焦态提亮一档 |
| Text Primary/Secondary/Tertiary | `--lw-ink-1` / `-2` / `-3`（弱提示再往下 `-4`/`-5`） | 有 | 三级文本层次 |
| Border | `--lw-line`（`-subtle`/`-strong`） | 有 | 默认边线 / 分隔 |
| Success / Warning / Destructive | `--lw-ok` / `--lw-warn` / `--lw-danger` | 有 | 语义状态，只用于真实状态 |
| Diff Added / Removed | `--lw-diff-add` / `--lw-diff-del`（+ `--lw-rgb-*`） | **新增** | diff 专用对（附录 B）；**不得借 ok/danger** |
| Icon强调 | `--lw-info` / `--lw-purple` | 有 | 链接/中性强调与特殊维度色（子代理名等） |

### 3.2 按需新增的专用族（先立规则后立值，用到才加）

- **Git 文件状态族** `--lw-git-modified/added/deleted/renamed/untracked/ignored`：文件树 /
  变更列表专用，**不得借 diff 或 warn 色**。
- **等待确认徽章**：所有「等待用户」态（审批、提问、计划确认）用**同一种**待确认处理
  （现役脉动点 + 弱色徽章保留为该处理），同类等待文案不得呈现成不同状态。
- **查找高亮** `--lw-find-highlight`（+ `-active`）：仅用于页内搜索命中（做时间线查找时加）。

### 3.3 用色规则（照搬蓝本，纪律不变）

- 只用语义令牌，禁一次性色值与 `text-white/60` 类临时透明度拼接（现状门禁已管）。
- 页根 = `bg + ink-1`；普通内容容器 = wash-1 或 bg-secondary；浮层 = bg-elevated。
- **层级优先用文本层次表达**，其次才是加边框 / 加色。
- brand（accent）克制而有意图。
- 语义状态色不得为了「显得更响」而借用。
- 表面分层规则修订（取代下位文档「1px 边框只给浮层」）：**平面内分层 = wash 优先；
  边框引导的分离合法**——内容卡可用 `--lw-line-subtle` 全围边（蓝本 bg-card +
  border-card-border 同构），但同一视图内不得混多种卡片底，除非表达真实层次。
- 图标前景透明度：次级 / 三级图标整体绘制后与背景混合（次级 60%、三级浅 40% / 深 30%），
  避免多路径交点加深；hover/group-hover 状态同步图标层级。

## 四、字体

### 4.1 字族

- **UI Sans**：全站默认无衬线栈，用于几乎一切界面文本。
- **UI Mono**：路径、命令、代码、标识符、快捷键、哈希、模型 ID、终端类数据
  （现状 `.mono` 纪律延续）。

### 4.2 字号阶梯（相对制，本文件新立）

一切界面排版挂在 `--lw-ui-font-size`（缺省 14px）上：

| 档 | 公式 | 缺省值 | 语义角色 |
|---|---|---:|---|
| `--lw-fs-ui-xl` | base+4 | 18px | Markdown H1 / 一级阅读标题 |
| `--lw-fs-ui-lg` | base+2 | 16px | Markdown H2 / 二级阅读标题 |
| `--lw-fs-ui-base` | base | 14px | 正文、常用按钮、H3–H6、工作区/区块标题（H3/H4=semibold、H5=medium、H6=normal 靠字重分层） |
| `--lw-fs-ui-caption` | base−1 | 13px | 比正文低一档的紧凑说明 |
| `--lw-fs-ui-sm` | base−2 | 12px | 次要信息、帮助文本、tooltip 正文、行内代码 |
| `--lw-fs-ui-xs` | base−4 | 10px | 徽章、快捷键标签、计数、极弱元信息 |

规则：

- 选档**按内容角色**，不按孤立视觉偏好；字号层次与颜色层次是两个独立决策（次要文案配
  ink-2/ink-3，弱元信息配 ink-4）。
- `--lw-fs-10..14` 旧绝对档保留为**迁移期别名**；新写 UI 一律用 `fs-ui-*`，迁移完成后
  （附录 C）旧档收编进门禁豁免清单。
- 字重：标题/标签优先 `font-medium`，避免特重；正文与常用控件 `base + normal`。
- Markdown 阶梯：消息容器/正文/链接/表格 = ui-base；行内代码 = mono + ui-sm；代码块
  正文独立字号设置、代码块头 = ui-base；H1/H2 = xl/lg、H3–H6 = base。
- 尊重 i18n 膨胀：不写只对短英文成立的布局；不得把「截断」当唯一存活手段。

## 五、间距

基数 4px，用 `--lw-gap-*` 阶梯表达节奏：

| 值 | 用途 |
|---|---|
| gap-4 | 图标与文本的紧排 |
| gap-8 | 紧凑控件内边距 / 行内间隙 |
| gap-12 | 致密列表项 / 菜单行 |
| gap-16 | 标准卡片 / 面板内边距 |
| gap-24 | 大区块 / 对话框内部 |

规则：致密操作型 UI 默认从紧；重复使用少数几档，不造孤值（孤值须光学修正注释——现状
门禁保留）；flex + 文本必须 `min-w-0` 才允许截断；嵌套滚动 / 分栏必须 `min-h-0` /
`min-w-0`；宽度优先 `w-full + max-w-*`。

## 六、圆角（嵌套降档——蓝本最有价值的一条，全站新立）

圆角跟随**可见圆角容器的嵌套**，与组件重要性 / 布局深度无关。档位映射
（ZCode Tailwind 档 → `--lw-r-*`）：`xl(12px)→r-md`、`lg(8px)→r-xs`、`md(6px)→r-2xs`、
`sm(4px)→r-3xs`、`2xl(16px)→r-lg`。

- 布局区、普通包裹层、分组、分隔线**不计档**；第一个圆角容器从 **r-md（12px）**起，
  嵌套逐档降：r-md → r-xs → r-2xs → r-3xs（下限）。数最近的**真实**圆角容器，不数中间
  DOM；同层同档。
- 气泡、工具块、普通复合输入壳都按此嵌套走；**尺寸或重要性不构成用更大圆角的理由**。
- **2xl（r-lg，16px）白名单**（不得外溢）：①主聊天输入壳 ②会话状态浮板 ③toast
  ④品牌图标背板。主 composer 区域含其上下文头包裹层 = 布局，不计档。
- 基础控件（按钮 / 菜单触发 / 输入 / 下拉）：缺省 r-xs（8px），按最近圆角父容器降档
  （父 r-xs → 自身 r-2xs；父 r-2xs/r-3xs → 自身 r-3xs）。控件尺寸与主次强调**不**独立
  影响圆角。
- 对话框壳 = r-lg（16px），且**壳不计入内容层级**——内容里第一个圆角容器重新从 r-md 起。
- 菜单 / 下拉 / select 展开层 = r-xs 壳 + 行 r-2xs；子菜单独立起档，不继承触发器层级。
- `r-full` 只留给有意的胶囊 / 圆；禁任意圆角值与裸 `rounded`（现状双闸已管，档位语义
  按本节执行）。

## 七、尺寸

- 图标阶梯：12 / 14 / 16（蓝本 size-3/3.5/4 的对应），大图例可用 20/24。
- 控件高：`--lw-ctl`（28px 方形图标钮）/ `--lw-field-h`（38px 输入）两档为全站唯一
  （现状保留）；紧凑过滤行内输入允许 28px 档。
- 复用既有按钮尺寸变体，不新造高度体系；内容宽度优先流式（`w-full + max-w-*`）；
  固定宽只给菜单 / 浮层 / 对话框 / 稳定侧板。
- 普通业务 UI 禁任意 `w-[...]`/`h-[...]`；可滚动内容优先 `max-h-*` 而非定高；
  嵌套滚动区必须补 `min-h-0`。

## 八、组件

### 按钮

现役 4 种收敛（主实心 / ghost / 图标钮 / chip）保留为唯一实现；语义对齐蓝本：

- 主按钮 = accent 底 + accent-ink 字（缺省主动作）。
- **不得把一切动作都升为主按钮**；每个面板内保持清晰的动作层级。
- 图标钮恒方形；破坏性动作 = danger 语义填充；链接钮 = 纯文本 hover 下划线。

### 输入框

- 缺省 = wash-2 井 + line 边；hover 提一档；focus = 边线提亮 + 底提一档。
- 输入应当「平静、融入」，缺省不发光；语义错误态只用于真实校验错误；**不得把输入框
  装扮成卡片**。

### 卡片与面板（本文件对下位文档的关键修订点）

- 标准内容卡 = `wash-1` 或 `bg-secondary` 底 + `line-subtle` 全围边 + r-md + 16px 横向
  内边距；低强调容器 = 透明 + 仅文本层次。
- 卡片应当明显浮于页面底、低于浮层；卡面必须比浮层安静。
- 同一视图不得混多种卡底，除非编码真实层次。
- **下位文档「不要卡片」红线就此废止**：对话流工具步骤、产出物面板等操作型组件按
  蓝本「致密操作面板」形态使用卡片；但密度纪律不放松（§五/§七）。

### 菜单 / 浮层 / 对话框

- 菜单 = bg-elevated + 紧行 + r-xs 壳 + `--lw-shadow-pop`；行 = 紧凑动作行**不是小按钮**
  （稳定基线：28px 行高、r-2xs hover、gap-8、fs-ui-base）；hover 用 wash-2，禁强填充。
- 相邻选项行统一 2px 垂直间隙；禁用项保布局只降字色；分组靠弱分隔与排序，不靠堆子卡。
- 组合触发器（主动作 + 箭头）= 分体壳：左主动作右菜单键（PermissionCard 分体主钮即此
  形态，升为全站规则）。
- 浮层 zIndex：模态 60 / 下拉 70 / tooltip 80 / toast 90（现状阶梯保留）；交互浮层必须
  盖住被动 tooltip；菜单影从首帧到聚焦全程不丢。
- 对话框 = r-lg 壳 + `--lw-shadow-dialog`；三个预览类对话框（附件 / 反馈截图 / CUA 截图）
  允许 r-md。
- toast = bg-elevated/60 + 模糊 + r-lg 壳；堆叠定位只在共享 toast 组件里改。

### 标签页与选中态

- 非激活 tab 中性；激活 tab 用更强表面对比，**不用品牌色块**；列表行 / tab 选中 =
  wash-3（全站唯一）。

### 聊天、工具与开发者 UI（对话流复刻的规范锚）

- 聊天气泡按嵌套降档（r-md 起）；主输入壳 = r-lg 白名单例外。
- 工具输出 / 终端类块 / 路径 / 哈希 / 命令 → mono 偏向。
- **diff 必须用 diff 专用语义色**（§3.2），不得借 success/danger。
- 致密操作面板优先于营销卡风格。
- 状态词六态统一文案：等待中 / 执行中 / 已执行 / 执行失败 / 已拒绝 / 已停止。

### 画布与节点（特例类目；细则与全部数值见下位《Front-end Design Guidelines》§二⑯）

- 授权范围 = **可平移缩放的只读导航画布**（世界层 + 连线 + 汇聚面板）；编辑型画布、白板、
  图形编辑器不在授权内，要做得重新申请。
- 画布容器与网格底 = **布局区，不计圆角档**；节点是第一个圆角容器 ⇒ **r-md 起**、卡内降
  r-xs（§六 的字面执行，比设计稿原先写的 r-xs/r-2xs 高两档，以本文为准）。
- **网格底是全站唯一允许的背景渐变**：色位只准用线族 `--lw-line-strong`，不得借
  accent/diff/warn——点阵表达的是"世界可导航"，不是装饰纹理。
- 连线是**结构线不是盒边框** ⇒ 不受「卡上禁止 1px 边框」那条约束；描边 = `--lw-line`、1px。
- 画布与节点**不进浮层 zIndex 阶梯**（§八 菜单/浮层那条只管临时盖层）；画布内的常驻浮件
  按台面件处理（bg-elevated + `--lw-shadow-pop`，不写 z-index）。
- 汇聚面板内部的用户/助手/工具三类行**不许自造**，一律复用「聊天、工具与开发者 UI」那节；
  画布只决定它摆在哪里。
- **键盘全路径 + 最小窗宽可用是这一类的准入门槛**（§十三、§十二），不是加分项：画布不得
  成为任何动作的唯一入口。

## 九、层次与景深

克制的景深：主要靠背景对比、边线与圆角分层，阴影只做辅助。

- Base：无影，结构靠背景对比。
- Surface：极淡的边线引导分离（`--lw-elevation` 0.5px 描边 / `line-subtle`）。
- Overlay：`--lw-shadow-pop`（菜单 / 浮层 / 对话框）。
- Attention：`--lw-shadow-dialog` 仅 toast 与重要悬浮卡。

禁对普通布局用大软影；「背景分层」几乎总是比「阴影强度」重要。

## 十、动效

- 快而低戏：覆盖层用淡入 / 微缩 / 方向性滑入。
- 动效澄清状态变化，不装饰屏幕；主工作区禁长弹簧 / 俏皮动画（**禁过冲回弹**与现役
  `--ease-*` 纪律一致，`--ease-spring` 唯一授权点保留现状定义）。
- 时长四档 / 缓动五条 / 嵌套折叠只动被操作层 / 收起态 `pointer-events:none` 等现役
  §6.6 纪律全部保留（见下位文档《UI shell》§6.6，与蓝本不冲突）。
- **常驻循环动画白名单扩充为四条**：①运行脉动点 ②不定进度条扫光 ③运行态动词文字
  扫光（新增，工具卡「执行中」态专用）④欢迎吉祥物。其余常驻动画仍走特例申请。
- 折叠展开 = grid-rows 0fr→1fr、内容 opacity 延后 ~40ms、收起后延迟卸载（蓝本 300ms
  与现役 200ms 档并存，取 200ms 档 + 延迟卸载）。

## 十一、工作区布局

桌面工作区 = 独立框架拼装：会话列（顶栏 + 时间线 + composer 坞）、底部终端（可选）、
右侧工作面板（自有页签栏）。各框架**自有背景与边线**，面板间 4px 可调间隙；拖拽柄
4px 透明命中区 + hover/拖拽时 2px 弱化色指示条（沿边内收、圆头、无遮罩）。布局框架
不计入内容圆角档。

（Locowrk 现役映射：侧栏 + 主区[转录列 + composer 坞] + WorkPanel 页签 + 底部终端挂账，
几何令牌 §七 已有；分屏宿主为 backlog。）

## 十二、响应式

桌面优先。最小窗宽下的可用性是硬要求（主区地板 `--lw-main-min` 现役保留）：
先稳定基础布局，再用断点做布局 / 宽度 / 可见性 / 密度微调；**不跨断点改变组件语义**；
核心动作在任何宽度可达；对话框先一列向上生长。Locowrk 无移动端，蓝本移动条目不适用
（有意删减）。

## 十三、无障碍与国际化

- 键盘导航是一等交互路径（现役：菜单方向键、审批 1-3 直选、Esc 收口——保留并扩展）。
- 焦点可见（`--lw-focus` 现役方案保留）。
- 亮暗双主题下对比度都安全；**语义状态色必须搭配可读文本，永不只用颜色表意**。
- 布局容忍更长译文；能用文字标签就不用纯图标表意。

## 十四、实现指引

- 新令牌之前先复用既有语义令牌；新组件之前先复用 `components/patterns|ui` 原语。
- 出现新 UI 需求时，先判断它属于**结构 / 表面 / 交互 / 状态**哪一类，再选令牌。
- 拿不准时：**更安静的 UI + 更强的信息层次**。
- 新形态先修订标准再写码（特例申请制继续有效，申请对象 = 本文件 + 两下位文档）。

## Do

- 语义令牌一致使用；守住页面 / 卡片 / 浮层三种面的区分
- 控件紧凑、可操作；用文本层次表达密度
- 技术值与命令类内容用 mono
- 双主题都验；为跨平台渲染约束设计；为本地化与长标签留余地

## Don't

- 普通 UI 用一次性色值；大面积铺品牌色
- 没有系统理由地加任意圆角 / 阴影 / 宽高
- 菜单和对话框该致密时松散
- 语义错误 / 成功色用于非语义装饰
- 造只在一个主题里正确的组件；在工具密集界面用视觉新颖性换清晰度
