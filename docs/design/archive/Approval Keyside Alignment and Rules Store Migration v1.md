## 0. 结论（先给答案）

`permissions/` 目录里的规则文件名 = `{:08x}` of `fnv1a64(工作区串)`，而喂进去的串至今是**旁车原样串**。
本机实测：现有 **1 个规则文件、5 条 allow 规则**，全部由「本项目始终允许」在压测期间落下。

三条路都能走，差别只在**这 5 条规则要不要继续有效**：

- **甲（一次性显式迁移）**：文件名 + 文件内 `workspace` 字段一起换成归一形 ⇒ 规则连续有效，磁盘动 1 个文件。
- **乙（不迁移，只改代码）**：改完代码新授权写进归一形文件，旧文件**读不到** ⇒ 那 5 条命令重新弹一次审批卡，
  旧文件成为孤儿留在盘上（不影响安全，方向是更保守）。
- **丙（兼容读：新旧两个名字都读并合并）**：规则永不断，但撤销授权与手改 JSON 的出口变成两个文件，
  判定逻辑长一条分支 ⇒ 本稿**不推荐**（理由见 §4 末）。

⚠ 这一刀和 Q7c 那条「改错就是权限面失效」的判断现在要**订正一半**：归一后**读写两侧同时变**，
所以不会把 allow 变成 deny、也不会让 deny 失配 —— 真正的代价只有「已记住的授权要重答一次」这一项
（乙案）或「一次可回退的文件改名」（甲案）。原话登记在队列 §4，不擦掉。

- **R2**：交叉自证 —— 归一形 fnv 的**高 32 位**必须是 `9242b25e`，也就是记忆层那个已归一目录
  `tity-9242b25e` 的短哈希。本机实测中 ⇒ 说明"归一形键位"这一串在两条独立编码（文件名与目录名）里

- **R3**：目标文件名（`9242b25e6d61a032.json`）在 `permissions/` 下**必须不存在**；在场就说明
  归一形那边已经有规则，**不许覆盖**，交人看（同名冲突 = 停，不自动合并规则集）。

R1/R2/R3 任一不中 ⇒ 本稿的迁移面作废，回去重取磁盘。

## 4. 方案：归一收在 store 层那一处，不是三处补参数

Q7c 学到的形状在这里直接复用：**合一的是喂进去的键**。

- 落点 = `permission_rules.rs` 的 `file_of()` 之前过一次 `plugin_api::wskey::normalize`
  （或者 `verdicts` / `add_allow` / `clear` 三个入口共用一个内部 `key()`）。选 store 层而不是调用方，
  理由是这里有三处入参（E1/E2/E3）加一条人手写的路（E4）：调用方各补一次 = 下一刀新增调用点又漏一次，
  而 `file_of` 只有一份。
- **不碰审批语义**：`rule_matches`、③deny/⑤allow 的判定顺序、模式放行优先级一行不动 ——
  本刀只改"同一个项目的几种写法落到同一个文件"，不改"命中规则之后做什么"。
- 刻意不做：不把 `list_all()` 改成按归一形过滤（它本来就走目录遍历，与 fnv 输入无关，
  改它 = 造第二条通路）；不在 UI 上显示归一形（显示用人读字段，见 §8）。
- ⚠ **为什么否掉丙案**：兼容读要同时读两个文件并合并 `allow`/`deny`，那"撤销授权"就得决定
  删哪一个（或两个都删）；`clear()` 的语义从"整文件删除"变成"跨文件删除 + 空集判断两次"。
  多出来的复杂度全部落在**权限判定路径**上，而它换来的收益只有"5 条压测遗留规则不用重答"。
  这条取舍按实测写在这里，等他裁定时看得见成本落在哪一侧。

3. 两阶段改名：先把旧文件复制成**临时名**并在临时名里**只精确替换** `"workspace": "<原样串>"` 一处

## 7. 判据设计（开工那一批要落的东西，现在先立清楚）

1. **形状判据**：E1/E2 两处不得再出现「resolver 直取 `.workspace`」⇒ B2 的白名单从
   {视图, approval} 收成 {视图} 一个；`permission_rules.rs` 内必须存在唯一一个归一调用点
   （`file_of` 之前那一处），三个入口（`verdicts`/`add_allow`/`clear`）不得各自再归一次 = 第二真源。

   ⚠ **v2.199 实测订正（原话留档不擦，历批第 111 条）**：这一条照写做不到。E2 那次取用同时喂决策卡的环境行，改吃视图产出就得**再解析一次会话上下文**，直接撞 M-18a（`tests_approval/ctx_parse.rs::assert_one_parse` 五支各钉 `count == 1`）。落地的形状 = **取用点仍是 2 处**（判据 K3/K3b）+ **审批面不出现 `scope_key`/`normalize`**（K4）+ **归一唯一在 `permission_rules.rs::keyed()`**（K1），B2 白名单维持 {视图, approval} 不收窄。结论：判据与既有承重不变式冲突时，**改的应是判据**，不是把代码拧成判据的形状。
2. **行为判据**：同一个项目的四种写法（正斜杠／反斜杠／大小写漂移／尾分隔符）经归一必须命中
   **同一个规则文件**——Windows 两支合并、POSIX 不许合（照 v2.197 那条用例的平台分形写法，
   期望一律现算不钉字面串）。
3. **反面判据**：`fnv1a64(原样串) ≠ fnv1a64(归一形)` 必须成立（本机 = `9467…` vs `9242…`），
   它是"不归一会长出第二个规则文件"的正面描述。
4. **不变式判据**：规则**内容**与判定顺序逐字节不变 —— 迁移前后对同一 `tool`+`subject` 的
   `verdicts()` 结果必须相同（这条是权限面最要命的：改名字可以，改判定不可以）。
5. **变异靶（各证一档独有）**：摘掉 store 层的归一 ⇒ 判据 1 红；在某个入口再归一次 ⇒ 判据 1 的
   "唯一归一点"红；把反面判据那条删掉 ⇒ 行为判据失去分家能力；把 `rule_matches` 顺手"优化"一下 ⇒
   不变式判据红。

## 8. 边界（写清楚，免得下一批当 bug 修）

- 审批卡载荷里的 workspace（E2）是**给人看的那一行**，归一后会从 `F:\Warehouse\TITY` 变成
  `f:\warehouse\tity`（小写）。这是键位统一的直接结果，不是显示 bug；如果他要求卡片上继续显示原始写法，
  那是另一个决策（旁车原样串仍可从 `read_meta` 取，但那就等于在权限面上再养一种串形）。
- 磁盘上"规则文件名 = 哈希"这件事对人不可读，靠的是文件里那个 `workspace` 人读字段 ——
  归一后该字段也变归一形，人手工核对时要按 §3 的复现算，不能靠肉眼比对路径写法。
- 无缓存 = 人改即生效这条性质不变（本刀不引入缓存）。
- 本稿所有读数只覆盖本机（`~/.Locowrk`）：换一台机器规则文件数量与内容都不同，
  实现里**不许**出现 `9467667791757632` 或 `9242b25e6d61a032` 这类具体名字，一切按扫目录现算。
- 两个决策点未定 ⇒ 主体不开工；本稿不动代码、不动磁盘。
