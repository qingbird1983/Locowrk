# 提示词：工具执行过程展示重构

## 一、任务概述

重构对话流中「工具执行过程」的展示，解决三个问题：

1. **过程排版乱**：每一步长短不一、不对齐、状态显示粗糙
2. **卡片占空间**：工具执行、子代理执行都用卡片包裹，信息密度低
3. **详细视图裸 JSON**：展开最底层时，看到的是花括号、字段名、原始数据结构，用户看不懂

目标：改成**紧凑对齐的列表行 + 人类可读的详细视图**。

不改折叠逻辑和状态机，只改展示层。

---

## 二、核心原则

**参考风格**：类似现代 CLI 工具的输出——没有卡片，只有整齐的行。

**三条红线**：

1. **不要卡片**：没有边框、背景色、圆角、阴影
2. **列必须对齐**：所有行的同名列左右边缘严格对齐
3. **不展示原始 JSON**：详细视图必须加工成人类可读的形式

---

## 三、折叠行的结构

每一步（思考 / 工具调用 / 读文件 / 命令 / 搜索）都是一行，从左到右分五段：

```
[图标] [类型] [描述] [状态]           [展开三角]
```

| 段 | 宽度 | 对齐 | 说明 |
|---|---|---|---|
| 图标 | 固定 20px | 居中 | 按类型区分 |
| 类型 | 固定 38px | 左对齐 | "思考"/"读取"/"终端"/"查阅"/"搜索"（v4.15 用户目测定案，原 64px 观感过空收窄） |
| 描述 | 弹性，占剩余空间 | 左对齐 | 一句话，超长省略 |
| 状态 | 固定宽度 | 右对齐 | "持续了几秒"/"成功"/"失败" |
| 展开三角 | 固定 24px | 右对齐 | 悬停才显示 |

**用 CSS Grid 实现，不要用表格、不要用 flex + 手写宽度。**

### 对齐规范

* 所有行的图标列左边缘对齐
* 所有行的类型列左边缘对齐
* 所有行的描述列左边缘对齐
* 所有行的状态列右边缘对齐
* 所有行的三角列右边缘对齐

### 状态展示

| 状态 | 视觉 |
|---|---|
| 进行中 | spinner + 弱化文字（"思考中…"） |
| 完成 | 弱化对勾，或什么都不显示 |
| 失败 | 小红色叉 + 高亮色文字 |

**克制**：成功不需要强调，失败才需要。

### 展开三角

* 默认 `opacity: 0`（隐藏）
* 鼠标悬停整行时 `opacity: 1`（淡入）
* 过渡时长：`var(--lk-duration-fast)`
* **三角始终占据固定宽度，避免悬停时行内容位移**
* 键盘 Tab 聚焦时也显示

### 缩进与层级

**层级通过左侧缩进 + 竖线表示，不用卡片嵌套。**

```
🧠 思考  分析用户需求                      ↗
📄 读取  README.md                         ↗
▶ 终端  cargo test  ✓ 成功                 ↗
🧠 思考  结果分析                          ↗
   │  📄 读取  main.rs
   │  📄 读取  lib.rs
```

子步骤比父步骤多缩进一级，左侧一条竖线连接。

### 描述文案规范

* 一句话，不超过 40 字
* 去掉技术术语
* 路径只显示文件名，不显示全路径
* 命令只显示首词 + 关键参数
* 例如：
  * ❌ "read file F:/xxx/yyy.rs"
  * ✅ "读取了 [main.rs](http://main.rs)"

### 间距

| 位置 | 间距 |
|---|---|
| 行与行之间 | --lk-space-1（4px） |
| 步骤组之间 | --lk-space-2（8px） |
| 缩进一级 | --lk-space-3（12px） |
| 行内元素之间 | --lk-space-2（8px） |

## 四、详细视图（展开后的内容）

### 当前问题

展开一个工具调用，看到的是：

```
{
  "entries": [
    {
      "kind": "dir",
      "name": "capabilities",
      "size": 0
    }
  ]
}
```

花括号、引号、字段名全部裸露。工程上正确，但用户看不懂。

### 改造方向

**不是"美化 JSON"，是"按工具类型定制渲染"。**

**执行前必做**：先盘点项目里已有的组件。

```
1. 搜索 desktop/src/components/ 下所有已存在的卡片、列表、树、代码块组件
2. 列一个清单：组件名 + 用途
3. 详细视图的渲染，优先复用这些组件
```

**如果发现"详细视图想展示的东西"和"已有组件的能力"匹配，直接用已有组件。** **不要为了详细视图另写一套。**

### 数据到组件的映射

| 数据类型 | 复用组件 |
|---|---|
| 文件列表 / 目录树 | 文件树组件 |
| 代码内容 | 代码块组件（按扩展名高亮） |
| 子代理执行结果 | 子 Agent 展示组件（改造后见第五节） |
| 搜索结果 | 搜索结果列表组件 |
| 命令输出 | 终端输出组件 |
| 键值对 | 属性列表组件 |
| 纯文本 | 段落或代码块 |
| 无法识别 | 属性列表组件兜底 |

### 按工具类型的渲染

| 工具 | 输入展示 | 输出展示 |
|---|---|---|
| fs_read | 路径（高亮） | 代码块 |
| fs_list | 路径 | 树形列表 |
| fs_write | 路径 + 内容 | "已写入 X 字节" |
| fs_grep | 搜索词 + 路径 | 匹配结果列表 |
| shell | 命令（等宽） | 标准输出（等宽）+ 退出码 |
| fetch | URL | 状态码 + 内容摘要 |
| git | 子命令 + 参数 | 按子命令定制 |
| 通用兜底 | 参数列表 | 键值对列表 |

### 通用规则

* **去掉所有 JSON 语法**：不显示 `{`、`}`、`\\\[`、`\\\]`、引号、下划线字段名
* **字段名翻译成中文标签**：`path` → 路径，`size` → 大小，`kind` → 类型
* **值格式化**：数字加单位、时间转相对时间、路径简化、枚举翻译
* **长内容折叠**：超过 N 行用长消息折叠组件
* **保留"查看原始数据"入口**：放在右上角或底部，默认收起

### "查看原始数据"入口

在详细视图的右上角或底部，放一个小入口：

```
原始数据 ▸
```

点击后展开真正的 JSON。**给工程师用的，普通用户不用看。**

### 自检

完成后检查每一个工具的详细视图：

* 有没有出现 `{` `}` `\\\[` `\\\]` 裸露的花括号？
* 有没有出现下划线风格的字段名（如 child_session_id）？
* 有没有出现英文枚举值（如 budget_exhausted）？

**任何一项出现，说明这个工具的渲染没做完。**

## 五、子代理展示改造

### 当前问题

子代理用大卡片展示，占位置，信息密度低。

### 改造为紧凑行

```
🤖 子 Agent  subagent_run  ✓ 成功  持续 12 秒        ↗
```

**展开后**，把原来卡片里的内容改为缩进的列表行：

```
🤖 子 Agent  subagent_run  ✓ 成功  持续 12 秒
   │  任务    这是一个界面连通性测试任务...
   │  状态    ✓ 已完成
   │  轮次    2
   │  工具    echo
   │  [查看完整对话]
```

**关键**：

* 状态、轮次、工具用"标签 + 值"两列展示，不用卡片框
* "查看完整对话"是文本按钮，不是卡片
* 整个子代理块，视觉上就是几行缩进的文本

## 七、不要做的事

* **不要卡片**：没有边框、背景色、圆角、阴影
* **不要折叠态和展开态用不同布局**：展开只是追加缩进的子行，行本身不变
* **不要悬停时让行内容位移**：三角位置固定，只改透明度
* **不要用不同颜色区分工具类型**：图标已经区分了，颜色会花
* **不要保留子代理的大卡片**
* **不要直接展示原始 JSON**
* **不要为了详细视图另写一套渲染器**：先复用已有组件

## 八、验收标准

### 折叠行

* [ ] 所有工具执行步骤都是一行，没有卡片
* [ ] 五列（图标/类型/描述/状态/三角）严格对齐
* [ ] 展开三角悬停才显示，位置固定不位移
* [ ] 状态展示克制，成功弱化，失败高亮

### 详细视图

* [ ] 展开任意工具，看不到裸露的 JSON 语法
* [ ] 参数按"标签 + 值"两列展示
* [ ] 输出按工具类型定制渲染
* [ ] 有"查看原始数据"入口，默认收起
* [ ] 长内容用折叠组件

### 子代理

* [ ] 从大卡片改为紧凑行 + 缩进列表
* [ ] 展开后是"标签 + 值"两列

### 整体

* [ ] 缩进用竖线表示层级，不用卡片嵌套
* [ ] 行与行紧凑，不浪费垂直空间
* [ ] 改造前 / 改造后视觉对比明显改善
