# 提示词：三栏响应式布局重构（非对称级联折叠 v2）

## 一、核心原则修正

**之前的设计错误**：把断点当成了"按钮开关"。窗口小于某个宽度，按钮就冻结或隐藏。
这是让用户伺候软件。

**正确的设计**：断点决定的是"展开模式"，不是"能不能用"。
**任何窗口尺寸下，左右栏的展开/收起按钮都必须可用。**

---

## 二、布局结构

```
左栏（导航） | 中间（主内容） | 右栏（辅助面板）
```

## 三、断点定义（修正版）

| 断点 | 窗口宽度 | 布局模式 |
|---|---|---|
| **xl** | ≥ 1400px | push 模式，三栏可同时存在 |
| **lg** | 800-1399px | push 模式，左右栏可同时存在 |
| **md** | 400-799px | **overlay 模式**，左右栏互斥，只能展开单边 |
| **sm** | < 400px | 显示"窗口过窄"提示，禁止使用 |

**关键修正**：
1. **窗口最窄限制从 800px 改到 400px**
2. **800-1399px 时，左右栏按钮都可正常使用**（不是只能到 1400 才激活）
3. **400-799px 时，左右栏按钮同样可用**，只是展开方式变为 overlay

---

## 四、两种展开模式

### push 模式（窗口 ≥ 800px）

侧栏展开时，**挤压**主内容区，正常占位。

```
┌──────┬──────────────┬──────┐
│ 左栏 │   主内容      │ 右栏 │
└──────┴──────────────┴──────┘
```

- 左栏展开 → 主内容区变窄
- 右栏展开 → 主内容区变窄
- 左右栏可同时展开

### overlay 模式（400-799px）

侧栏展开时，**浮在主内容之上**，不挤压主内容。

```
┌─────────────────────────────┐
│ 主内容（占满宽度）            │
│                             │
│ ┌─────┐                     │
│ │左栏 │ ← 浮层覆盖           │
│ │     │                     │
│ └─────┘                     │
└─────────────────────────────┘
```

- 左栏展开 → 从左侧浮出，覆盖主内容
- 右栏展开 → 从右侧浮出，覆盖主内容
- **最大宽度限制为窗口的 2/3**
- **左右栏互斥**：展开一边时，自动收起另一边

---

## 五、单边互斥规则（overlay 模式专属）

**当窗口在 400-799px 时：**

- 用户点击"展开左栏" → 左栏浮出，如果右栏已展开，则右栏自动收起
- 用户点击"展开右栏" → 右栏浮出，如果左栏已展开，则左栏自动收起
- 用户点击"收起当前侧栏" → 侧栏收起，主内容恢复全宽
- **不能同时展开两边**

**push 模式（≥800px）没有这个限制**：左右栏可同时展开。

---

## 六、折叠与展开行为

### 窗口缩小时

| 触发 | 行为 |
|---|---|
| 窗口 < 1400px | 右栏如果展开，**不自动折叠**（用户手动状态优先） |
| 窗口 < 800px | 切换到 overlay 模式。如果左右栏同时展开，**保留左栏，收起右栏** |
| 窗口 < 400px | 显示"窗口过窄"提示 |

### 窗口放大时

| 触发 | 行为 |
|---|---|
| 窗口 > 800px | 从 overlay 模式切回 push 模式 |
| 窗口 > 1100px | 左栏自动展开（如果之前是自动折叠的） |
| 窗口 > 1400px | **右栏不自动展开**（用户手动状态优先） |

### 非对称原则（保留）

- **左栏是导航** → 窗口放大时自动恢复
- **右栏是辅助** → 窗口放大时不自动弹出，需用户手动

**这是有意的设计，不是 bug。** 在实现时不要"顺手"让右栏也自动展开。

---

## 七、用户手动状态优先

- 用户手动折叠了左栏 → 窗口放大时不自动展开
- 用户手动展开了右栏 → 窗口缩小时仍按断点折叠
- 用户手动状态持久化到 localStorage
- 切换布局模式（push ↔ overlay）时，保留用户的手动展开状态

---

## 八、交互元素

| 元素 | 位置 | 行为 |
|---|---|---|
| 左栏切换按钮 | 窗口左上角 | 展开/收起左栏 |
| 右栏切换按钮 | 窗口右上角 | 展开/收起右栏 |
| 左栏右边缘手柄 | 左栏右边缘 | 拖拽调整左栏宽度 |
| 右栏左边缘手柄 | 右栏左边缘 | 拖拽调整右栏宽度 |
| overlay 遮罩 | 浮层侧栏以外区域 | 点击收起侧栏 |

**关键**：**两个切换按钮在任何窗口宽度下（≥400px）都必须可见、可点击。**
不允许出现"按钮冻结""按钮隐藏"的状态。

---

## 九、动画细节

- 折叠/展开统一用 `width` + `opacity` 过渡
- 不使用 `display: none`（会打断动画）
- push 模式：用 width 过渡
- overlay 模式：用 `transform: translateX` 处理滑出
- 时长：`var(--lk-duration-normal)`
- 缓动：`var(--lk-ease-out)`

---

## 十、为什么展开是非对称的

这个规则不是技术限制，是产品判断：

- **左栏是导航** → 用户需要它来切换上下文，自动恢复省事
- **右栏是辅助** → 用户不需要它也能工作，自动弹出反而打扰

**在实现时要明确这一点，否则 AI 会"顺手"让右栏也自动展开。**

---

## 十一、验收标准

- [ ] 窗口 ≥ 400px 时，左右栏切换按钮始终可见、可点击
- [ ] 窗口 800-1399px 时，左右栏按钮正常工作
- [ ] 窗口 400-799px 时，左右栏按钮正常工作，展开方式为 overlay
- [ ] overlay 模式下，左右栏互斥，展开一边自动收起另一边
- [ ] overlay 模式下，侧栏最大宽度为窗口的 2/3
- [ ] overlay 模式下，点击遮罩可收起侧栏
- [ ] 窗口 < 400px 时，显示"窗口过窄"提示
- [ ] 窗口放大时，左栏自动展开，右栏不自动展开
- [ ] 用户手动状态持久化
- [ ] 切换 push/overlay 模式时，动画平滑
- [ ] 全程没有"按钮冻结"或"按钮隐藏"的状态

---

## 十二、不要做的事

- **不要用断点控制按钮的可用性**
- **不要在窗口变窄时隐藏按钮**
- **不要用 `display: none` 做折叠**（打断动画）
- **不要同时展开左右栏（overlay 模式下）**
- **不要让 overlay 模式的侧栏超过窗口 2/3 宽度**
- **不要在窗口放大时自动展开右栏**

**关键修正点**：

**"按钮可用性"和"布局模式"要分开。**

- 之前的设计：窗口 < 800px → 左栏按钮隐藏 ← 错
- 现在的设计：窗口 < 800px → 按钮还在，只是展开方式变成 overlay ← 对

**"user 伺候软件"的反面**是：**软件在任何尺寸下都给用户完整的控制权，只是呈现方式不同。**
