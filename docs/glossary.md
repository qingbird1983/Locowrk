# 术语表（面向非技术读者）

按主题分组，每条给一句话解释。看文档遇到不懂的词先查这里；文档作者第一次使用术语时应链接本表。

## 参照系

- **Locowrk**：本项目名（`Loco` + `wrk`，不是 `work`；不加 `-pi`）。一个给 pi 做的原生桌面工作台。
- **pi**：一个开源的命令行 AI 编码代理（TypeScript 编写，GitHub: earendil-works/pi）。本项目以它的行为作为功能与兼容性的参照系。
- **sky-valley/pi（简称 pi-go）**：pi 的纯 Go 移植版。其运行所需源码已以 MIT fork 进本仓库 `pi/`，由本项目维护；它提供 Agent 循环、模型接入、工具、会话与技能，但没有终端界面，也没有 pi 的扩展运行时。
- **MyGo**：一个纯 Go 的桌面应用框架（GitHub: egoist/mygo）。窗口可以用 Go 画原生界面，也可以显示系统网页；它是本项目的桌面宿主。
- **TUI / GUI**：TUI = 终端里的字符界面；GUI = 图形窗口界面（本项目的桌面端）。

## pi 的概念

- **内核**：pi 中与界面无关的部分——调用大模型、执行 Agent 循环、管理工具与会话。
- **扩展（extension）/ 插件**：第三方写的增强文件，可以给 Agent 加工具、加命令、拦截行为。
- **编排型扩展**：不碰界面、只影响“做事流程”的扩展（注册工具、注册命令、事件钩子）。本项目兼容这一类（A 轨）。
- **TUI 型扩展**：需要在终端里画界面的扩展。本项目不翻译这类界面，改由桌面原生插件提供等价信息。
- **桌面插件（B 轨）**：围绕 Go 内核事件流重建的原生插件，可画 Go 界面或嵌入网页。
- **事件钩子（hook）**：内核在关键节点（如“工具即将执行前”）向外发出的通知，插件可借机观察或修改行为。
- **会话（session）**：一次完整的对话记录，落盘成 JSONL 文件，可恢复、可分叉。
- **compaction（压缩）**：对话太长时把早期内容摘要化以腾出空间。
- **skill（技能）**：一份 `SKILL.md` 加可选脚本，描述一类任务的做事方法；启动时被发现并注入系统提示词。
- **项目上下文**：仓库里的 `AGENTS.md` / `CLAUDE.md` 一类文件，会被拼进系统提示词。
- **prompt template（提示词模板）**：可复用的提示词片段；pi 有，`sky-valley/pi` 目前尚未移植。
- **TypeBox / JSON Schema**：描述“参数长什么样”的规范语言；JSON Schema 是通用标准，TypeBox 是 pi 用的具体写法。

## 大模型接入

- **Provider（模型供应商）**：Anthropic、OpenAI、Google 等。
- **协议适配（wire protocol）**：每家供应商的 HTTP 接口格式不同，需要分别适配。
- **模型目录**：可用模型清单（名称、参数上限、价格等），纯数据。
- **MCP**：Model Context Protocol，一个开放标准，让外部工具以统一方式接入 AI 客户端。
- **凭证 / 钥匙串**：API key 等敏感信息存放在操作系统钥匙串里，配置文件只存引用。

## 本项目技术栈

- **Go**：系统级编程语言，编译成独立可执行文件；本项目内核与桌面宿主的语言。
- **MyGo `ui.View`**：MyGo 的原生界面写法——界面是应用状态的函数，每帧构建一次，由框架在 GPU 上绘制，不经过 HTML。
- **系统 WebView**：操作系统自带的网页容器（Windows 的 WebView2、macOS 的 WKWebView、Linux 的 WebKitGTK），不额外打包浏览器引擎。
- **Typed IPC**：MyGo 的进程内/页面间调用机制——Go 服务绑定后生成 TypeScript 客户端，channel 可以把流推给页面。
- **进程隔离**：插件作为独立进程运行，通过 stdin/stdout 或 gRPC 通信；插件崩溃不会拖垮宿主。
- **JSON-RPC**：一种轻量的远程调用格式，本项目首选用于子进程插件。
- **`plugin` 包**：Go 标准的动态库加载机制；平台受限、不能卸载、版本强耦合，本项目不用它做插件系统。

## 工程方法

- **ADR（Architecture Decision Record，决策记录）**：一页纸文档，记录“做了什么决定、为什么、放弃了什么备选”。只增不改，推翻旧决策就写新的一篇。
- **文档先行**：先写设计与规范文档并定稿，再写代码。
- **接缝（seam）**：系统里预留的扩展点。MVP 阶段把接缝留对，后面加功能就是“挂上去”而不是“拆了重装”。
- **验收场景**：用非技术语言描述的“做到什么程度算完成”，每个阶段若干条，逐条打勾。
- **fixture（夹具）**：预先录制的固定测试数据，用来离线测试协议适配，保证测试不花钱、结果稳定。
- **门禁（gate）**：提交/合并前必须通过的自动检查（格式、静态检查、测试、体量、文档完整性）。
- **信任（trust）**：是否允许加载某个项目目录下的技能/插件。默认不加载，需要用户显式授权。
