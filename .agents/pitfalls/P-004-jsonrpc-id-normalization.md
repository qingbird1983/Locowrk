# P-004：JSON-RPC 的数字/字符串 id 匹配不上

## 现象

适配器握手超时（`initialize ... timeout`），插件其实已经回了响应；mock 的 `request` 也一直等不到宿主回包。

## 根因

宿主发请求时把 id 编成 JSON 字符串（`"1"`），等待表按 `1` 建键；插件原样回 `"1"`，宿主按原始字节 `"1"` 查表，键不同，响应被当作未知 id 丢弃。反过来（发数字、回字符串）同样不匹配。

JSON-RPC 允许 id 是数字或字符串，协议只说“回同一 id”，没说编码形状。

## 修复

等待表统一用去引号的 key：`strings.Trim(string(rawID), "\"")`；请求与响应两侧都走这个函数。数字 `1` 与字符串 `"1"` 视为同一 id。

## 预防

- 测试里让 mock 用字符串 id、宿主用数字 id，覆盖两种形状。
- 不要用 `string(rawID)` 直接做 map key；先规范化。
- 类似的“线上形状”差异（`null` vs 缺失、数字精度）同样在边界归一化，不散落到业务分支。
