## 目标

现在几乎所有工具共用同一张卡，只有文件名和"跑完了"。要在长会话里看懂"它到底做了什么、
哪一步出事、现在是在等还是在重试"。这一阶段把工具卡按类型做全，并把折叠、状态、停止、重试
四件事一次做对。

## 验收标准（必须可测：跑什么命令、看到什么结果）

先说怎么看：`cd desktop && pnpm tauri dev`，起一个会话让它连着跑工具，下面每条都在真实界面核对。

- [ ] AC-1 文件读写类（读文件、写文件、改行、打补丁）：卡片上一行就能看到**路径 + 加了几行减了几行**；
      展开看到具体改动位置。跑一次 `edit_replace` 与一次 `fs_write`，两者显示不一样
- [ ] AC-2 命令执行类：卡片上能看到**实际命令行**与退出码；失败时错误摘要直接可见，不用展开
- [ ] AC-3 搜索与网络类（找文件、搜内容、抓网页、查工具）：各自显示自己的关键信息
      （命中数 / 查询词 / 网址与状态码），不再共用"已完成"三个字
- [ ] AC-4 子任务与定时类（起子代理、安排定时任务、发通知）：卡片能跳向对应详情页，且显示它绑的对象
- [ ] AC-5 其余类型逐类过一遍：设计稿 §4 那张 27 类表里，**每一类要么有专属卡，要么明确写"共用通用卡，
      因为它没有独有信息"**；两边都对得上号（这张核对表我来出，你抽查）
- [ ] AC-6 折叠三层：默认一行摘要 → 点一下看关键参数 → 再点看完整输出；
      50 行以上工具记录的长会话滚起来不卡，且默认状态下整屏高度可控
- [ ] AC-7 思考内容默认收起（想读再点开），且**不会**因为它而让工具卡看起来在忙
- [ ] AC-8 六种状态词（等待 / 进行 / 成功 / 失败 / 取消 / 需你确认）中英都有：
      切到英文界面跑一遍，不出现中文残留，也不出现空白标签
- [ ] AC-9 审批中的那一步：卡片就地显示"等你确认"，与审批浮层指向同一件事，
      不允许出现"卡片说在跑、弹窗说要批准"两套话
- [ ] AC-10 停止：跑到一半点停止，那一轮与在跑的那张卡显示"已停止"而不是"完成"；
      重进这个会话看历史，仍然是"已停止"（这条后端已有凭据，前端要接上）
- [ ] AC-11 重试可见：模型连接重试时你能看到"正在重试（第 N 次）"，而不是一片安静以为卡死
- [ ] AC-12 `make check` 全绿（含中英成对那道检查）；新增界面用例覆盖上面每条能自动化的那几项

## 非目标

- 不做产出物面板与文件页签（下一阶段）
- 不改工具本身的行为与权限判定，只改"它做了什么怎么让你看见"
- 不引入新的动画、配色、自造控件；形态一律走已有的前端标准

## 设计要点

一句话：**同类只许一种形态，一眼能认出是什么工具、现在处于哪个状态**。
有长期影响的取舍（比如卡片信息从哪里取）写进 `docs/adr/`。

## 计划

1. 第一刀：状态词六态 + 折叠三层 + 停止与重试可见（先把"看不看得懂"解决）
2. 第二刀：读写类与命令类两套专属卡（用得最多、信息最值钱的先做）
3. 第三刀：其余类型逐类补齐 + 27 类核对表收口
4. 每刀完都先给你在真实界面看一遍，再进下一刀

## 风险与回滚

- 风险：长会话性能（折叠策略改坏会明显卡顿）→ AC-6 用 50+ 工具行的真实会话核对
- 风险：状态与审批两套口径又分叉 → AC-9 专门盯这一条
- 挂账 / 遗留：后端"等待用户回答的时长"目前没记进日志，那一半的"扣掉等待时间"仍做不到（旧账，不藏）
- 回滚：每刀一个提交，单刀可回退；不动数据
