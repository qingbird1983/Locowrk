## 目标

按方案稿定的形状落地两件事，且**彻底解耦**：记忆 = 扁平事实文件、一处落盘
（`~/.Locowrk/memory/` 全局 + 项目两层，一事实一文件、四类型、索引常驻正文按需）；
上下文 = LLM 深度压缩主位、机械层（落盘 / 微压缩 / 滑窗）做前置减速与失败保护网，
会话日志永不被改写（压缩是组装期的投影）。北极星 = 一个会话窗口里连续工作不重开会话，
占用有界且成本近似平坦。

## 非目标

- 不为旧记忆数据做兼容或迁移承诺：sqlite 只一次性导出，树投影冻结只读；删除、覆盖
  `~/.Locowrk` 任何内容仍单独点头（降设计门槛 ≠ 降确认门槛）
- 第一版不做 embedding 向量检索：grep 全文 + 索引指针够用（实证依据见方案稿 A 节）
- 第一版不做后台定期整理通道（"dream" 式）：先让回合收束增量抽取跑起来，
  积弊实测出现再立批，不预造机制
- `<repo>/.Locowrk/` 交接层的**目录原则**维持 2026-10-05 三条原话（住用户仓库、
  git 排除、宁严勿松）；内容形态按方案稿 F 重定，本文件不重复其形状
- 不顺手把看板（阶段 06）、工具卡（阶段 02）塞进本阶段
- 跨设备同步、记忆可视化编辑器照旧不在范围

## 设计要点

一句话：**记忆不从会话派生、会话不靠记忆瘦身；压缩改投影不改日志。**
被否决过的形状与理由 = `docs/adr/0007` 的「被否决的方案」表（8 行）+ 方案稿同名节，
本文件只给指针、不复制理由（模板第 24 行纪律）。
