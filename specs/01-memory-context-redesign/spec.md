## 目标

现在这套记忆与上下文，你已经明确说"用着不理想"。这一阶段的目标不是修补，是**重新定形状**：
记什么、什么时候记、怎么带进对话、怎么忘。目标形态由你说，我负责把它写成可核对的验收，

### 你的不满意必须先回答的四件事（我已实测出来的硬约束，重构方案绕不开）

- [ ] AC-4 权威源只有一个：机器看的表、人改的文件、给模型看的投影，现在**三处都能各说各话**。
      新方案要指名谁是唯一真源，其余两个是它的投影还是它的编辑面。
      可核对形态：写清"改哪一处会立刻反映到另外两处，改哪一处不会"。
- [ ] AC-5 "忘掉了"要能被验证。现状实测：**删掉文件不等于删掉记忆**——
      判定矩阵写着"目录整个不在 = 复位手势，不删记录"，而首次启动又会按表把文件补写回来，
      所以下次启动全在。新方案必须给出"你怎么确认它真忘了"的操作步骤。
- [ ] AC-6 不要许诺做不到的事。"项目记忆删了不可恢复"这句话在旧形状下**不成立**
      （投影可重建、会话日志不删，重新整理会再长出一棵同样的树）。新方案要么改行为，要么改措辞。
- [ ] AC-7 带进对话的内容要有"发生那一次的凭据"。旧做法是注入时把四路信号现算一遍再排一次序，
      跨会话重放时那个数已经拿不到了，解释就不是当时真发生过的。
      可核对形态：任何"为什么带这条进来"的回答都要能指到一条存下来的记录。
